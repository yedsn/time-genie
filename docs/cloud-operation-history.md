# 云端操作记录

云端操作记录用于回答“谁在什么时候通过哪台设备改了什么”。它和同步用的 `workspace_changes` 分离：同步变更序列负责设备增量拉取，操作记录负责向用户解释一次业务动作。

## 记录范围

- 用户、自动化、导入、迁移、回滚和系统动作会标记不同来源。
- 一次批量业务动作只生成一条顶层记录，详情可列出受影响对象。
- 相同操作 ID 的幂等重试不会重复生成记录；未成功提交的操作不会显示成成功历史。
- 设备名称在写入时保存快照，因此设备改名或撤销后仍能识别历史来源。

详情只保存白名单字段的提交前后值。访问令牌、密码、密钥、`secret_ref`、Supabase 会话、自动化命令和未允许字段不会进入日志或搜索内容。

## 浏览与保留

在“设置 → 操作记录”中会直接按时间倒序显示全部数据变更，每页 50 条，可使用上一页和下一页连续浏览。刷新会回到最新的第一页。页面不要求先选择设备、来源、业务类型或关键词；展开详情和翻页均为只读，不会写入业务数据、同步状态或云端快照。

默认保留 90 天。过期清理只删除操作记录及其明细，不删除业务数据、同步变更或云端快照。界面会显示每条记录的到期时间。

## 能力边界

操作记录不是可执行的撤销脚本，不支持从单条日志恢复一个实体。需要整体回到某个历史状态时，应使用云端快照；记录已经过期时也不能据此恢复数据。
