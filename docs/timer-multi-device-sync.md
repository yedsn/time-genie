# 多设备计时同步

TimeGenie 的普通事项计时采用“本地先记录、云端按到达顺序收敛”的方式。开始、暂停、继续和结束都是离散事实；计时中的秒数只在本机根据最近的事实计算，不会每秒上传。

## 使用规则

- 点击“开始计时”会立即在本机开始，不需要先取得计时写入权，也不会因为另一台设备在线而等待。
- 任一已授权设备都可以直接暂停、继续或结束计时。后台租约只用于未归属时间的跨日边界协调，不参与普通计时写入。
- 两台设备提交竞争事实时，先到云端的结果生效。后到设备自动采用云端记录，清理败方待同步链，不生成需要人工选择的计时冲突。
- 自动跟随时显示“已在另一台设备保存，已跟随该结果”，可点击“查看记录”进入时间记录。若实际用时需要调整，可使用现有的“修正实际用时”入口。
- 结束时间由提交设备记录；服务端只在客户端时间超前时，把结束边界限制到“开始时间至服务端接收时刻”之间。离线结束后再联网提交时，原结束时间会保留。

## 未归属时间显示

未归属时间以云端返回的权威累计秒数为基准，再加上本机自本次拉取后的经过时间。它不再用“本机当前绝对时间减云端起点”计算，因此两台设备即使系统时钟相差数分钟，显示值仍只相差网络拉取延迟。阈值提示、处理分钟和界面秒数使用同一基准。

自动化校验模拟了两台绝对系统时钟相差 300 秒的设备：权威基准为 42 秒、本机均经过 3.999 秒时，两端显示均为 45 秒；系统时钟倒拨时显示不会倒退。

## 兼容与故障处理

旧客户端调用的 `tracking_lease_takeover_for_timer_write` 暂时保留为无副作用兼容入口：调用成功，但不会改变租约持有者、令牌、有效期或版本。升级前遗留的计时 `competing_edit` 会被重新归类并按上述权威结果自动收敛；事项、报告等非计时对象仍使用原有冲突处理流程。
