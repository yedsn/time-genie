# 今日事项独立实例升级说明

从 TimeGenie 0.4.4 的今日事项独立实例版本开始，“加入今日”会创建一份拥有独立 ID 的今日事项。今日事项与进行中来源事项的标题、预计、完成、排序、实际用时和删除状态不再双向联动。

## Supabase 升级顺序

1. 备份 Supabase 工作空间。
2. 先备份 Supabase 工作空间。
3. 在 Supabase SQL Editor 执行完整 `schema.sql`，或在已有结构上依次执行今日实例迁移及 `20261023m_timegenie_remove_client_generation_gate.sql`。
4. 重新打开应用并刷新云端数据。

当前直连云端模式不再发送或校验客户端数字版本号。旧同步客户端仍会被 `sync_v1`/`direct_v2` 存储协议屏障拒绝，避免旧 outbox 覆盖直连数据；新版直连客户端只按身份、设备授权、workspace epoch 和实体 expected version 校验。

## 数据边界

- 升级前已经记录的实际用时继续归属原事项，不复制到今日实例。
- 当前工作日的旧计划在新版首次读取时幂等物化为今日实例。
- 历史日期的预计和实际记录保留，不批量改写为实例。
- 重复今日事项选择“修改今后全部”时，只更新当前实例和来源模板，不回写历史实例。

## 回滚限制

升级后的工作空间不能安全地直接改回旧客户端语义。需要回滚应用时，应同时恢复执行上述 SQL 前创建的工作空间备份；不要让旧版客户端继续写入已升级的工作空间。
