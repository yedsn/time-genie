# 数据备份与恢复

TimeGenie 的本地备份是一个带完整性校验的 `.timegenie-backup` 逻辑归档。它用于误操作恢复、设备迁移和本机数据库损坏后的业务数据重建，不是 SQLite 文件副本，也不是持续同步文件。

## 备份包含什么

- 事项与计划：主体、工作日、工作时间、事项树、状态历史、每日估时和重复规则。
- 时间记录：计时条目、时间段、工时分配、未归属记录和实际工时调整。
- 报告：报告模板、报告正文和报告关联事项。
- 共享设置：工作空间级设置、已脱敏的集成配置和外部绑定。

备份不包含 Supabase 或 SeaTable Token、系统凭据库内容、Supabase 项目连接和登录会话、设备授权身份、同步队列、冲突、同步游标、运行时租约、本机文件路径、自动化命令与执行记录。集成配置中的 `secret_ref` 不会写入归档；配置 JSON 内名称含 Token、API Key、密码、Authorization、Cookie、凭据或会话标识的字段也会在导出时移除，无法解析的配置 JSON 以空值导出。因此恢复备份不会带回任何集成秘密。

## 导出备份

1. 打开“设置 → 本地备份”。
2. 选择“导出本地备份”，指定保存位置。
3. 应用会从同一个数据库只读快照读取数据，规范化 JSON 内容，为每个文件计算 SHA-256，并在写入后再次读取校验。
4. 普通备份只导出本地业务数据，不读取旧同步队列，也不会因为历史队列、冲突或 workspace epoch 状态而阻止导出。

导出时若有正在运行的计时，备份会以创建时刻为冻结边界，把已经过的时间结算到当前时间段。原数据库中的计时状态不会被修改。

## 预览和恢复

1. 选择“选择备份并预览”。预览会检查格式版本、必需文件、成员白名单、大小限制、逐文件校验和、实体数量和业务引用，不会修改当前数据。
2. 核对备份时间、工作空间、时区、数据数量、将被替换的数据数量和不会恢复的内容。
3. 选择“恢复这份备份”并二次确认。
4. 应用先在备份文件所在目录创建一份“导入前安全备份”；安全备份无法创建或校验失败时，不会开始恢复。
5. 业务数据在单个 SQLite 事务中替换。任一约束或写入失败都会完整回滚。

恢复后会创建新的本地工作空间和当前设备身份，业务实体 ID 与历史关系保持不变；来源云端工作空间、旧设备身份、同步队列和凭据不会恢复。运行中的计时会恢复为“已暂停”，备份之后经过的离线时间不计入工时；未归属采集会停止并标记为已丢弃。

计时条目上的“来源未归属会话”只是溯源线索：该会话在云端被删除后不会保留在本地，因此这类已失效的来源引用不会阻止导出或恢复。恢复时只回填仍然存在的来源会话，其余保持为空；任务父子关系、前一条计时条目等业务关系仍按严格引用校验。

## 恢复后重新使用云端

恢复结果固定为本地模式。需要改用云端时，在“设置 → 数据存储”登录 Supabase；如需把这份本地数据带到云端，先预览“复制本地数据到云端”，确认目标工作空间和数据数量后执行一次性完整替换。不要把 `.timegenie-backup` 当成同步队列直接上传到原云端工作空间。

旧数据库升级到最终双模式结构时的 migration 规则、旧队列救援包位置和数据处置方式见 [`SQLite 迁移与旧同步数据退役`](/sqlite-migrations)。

## 本地与云端的一次性完整复制

“复制本地数据到云端”和“复制云端数据到本地”是用户明确触发的一次性完整替换，不是同步、合并或迁移队列。复制成功后，源空间保留不变，本地空间与 Supabase 云端空间继续独立演进；应用不会自动切换存储模式，也不会为两个空间建立后续同步关系。

复制包覆盖统一目录中的 22 类共享业务实体，包括主体与计划、事项与重复规则、时间记录与未归属记录、实际工时调整、报告与模板，以及共享设置和集成的非敏感配置。它明确排除：

- access token、refresh token、密码、service role 或管理密钥等秘密。
- Supabase 登录会话、设备授权、设备身份和凭据库内容。
- operation history、processed operations、outbox、冲突、同步游标和复制暂存元数据。
- 本机文件路径、运行时状态和集成配置中的 `secret_ref`。

### 复制本地数据到云端

应用先从本地数据库的一致性快照生成版本化数据包，再分块上传并由服务端校验包版本、实体目录、实体数量、逐块 SHA-256 和整包内容哈希。目标云端非空时，服务端必须先创建 `pre_replace` 安全快照；随后在恢复锁保护下，用单个数据库事务完整替换云端业务空间。成功后云端进入新的数据世代，旧客户端会收到重置要求。任一步骤失败都会回滚云端替换，`pre_replace` 快照继续保留用于恢复，本地源数据始终不变。

### 复制云端数据到本地

服务端先冻结一个固定数据世代和变更序号的一致性导出包。应用下载全部分块，并在本地核对包 ID、分块顺序、实体名称、大小、实体数量、逐块 SHA-256 和整包内容哈希；全部校验通过后才允许开始写入。写入前会在本机 `backups` 目录创建 `.timegenie-backup` 安全恢复点，然后用单个 SQLite 事务完整替换本地业务空间。现有本机文件路径和集成 `secret_ref` 会保留，云端源数据不会修改。

### 失败恢复

- 上传、下载或完整性校验失败：尚未开始目标替换，目标空间保持原样。
- 本地写入失败：SQLite 事务完整回滚，复制前安全备份继续保留。
- 云端写入失败：服务端事务完整回滚；非空云端在替换前生成的 `pre_replace` 快照可用于恢复。
- 复制完成后发现选错方向或数据：从目标空间的复制前安全恢复点恢复；不要依赖源空间自动回滚目标。

复制不会删除源数据，不会按记录自动合并，不会自动切换当前存储模式，也不会建立持续同步。需要改用复制后的空间时，应在复制完成后由用户另行选择存储模式。

## 往返核对清单

一次标准核对应满足：

1. 导出结果显示“已通过完整性校验”。
2. 选择刚导出的文件，预览中的各类实体总数与导出结果一致。
3. 确认恢复后，界面显示导入前安全备份路径。
4. 主体、事项、时间记录和报告数量与预览一致。
5. 当前模式为本地；Supabase 登录、授权设备、同步队列和集成 Token 均未从备份恢复。
6. 若导出时存在运行计时，恢复后状态为暂停，时长停在备份创建时刻。
7. 执行“本地 → 云端 → 本地”测试时，复制前后 22 类实体计数与规范化内容哈希应完全一致。
