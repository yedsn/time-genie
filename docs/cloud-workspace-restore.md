# 云端工作空间回滚操作手册

云端回滚把历史镜像原地恢复到同一个工作空间。它不是创建副本，也不会恢复账号会话、设备授权、凭据、同步队列、操作日志或运行时租约。

## 回滚前检查

1. 当前设备在线、已登录且已授权。
2. 结束运行中或暂停中的计时，处理正在采集的未归属时间。
3. `direct_v2` 无本地待同步队列；如工作空间仍是 `sync_v1`，先完成 pending / failed 队列并处理所有冲突，再升级或恢复。
4. 确保其他设备升级到支持工作空间世代的版本。
5. 在“历史镜像”中预览目标镜像差异，确认新增、修改和删除数量。

## 执行回滚

1. 选择可用镜像，点击“回滚到此镜像”。
2. 服务端获取 10 分钟恢复锁；锁存在时普通业务写入和第二个回滚请求都会被拒绝，过期锁可安全接管。
3. 系统在改变业务数据前创建并校验“回滚前安全镜像”。失败时释放锁，当前业务数据不变。
4. 核对安全镜像 ID、目标差异和不会恢复的内容，输入完整镜像名称确认。
5. 服务端在一个事务中恢复业务表、递增 workspace epoch、写入回滚日志和 `workspace_reset`，最后释放锁。任一步失败都会整体回滚。

## 回滚后

- `direct_v2` 设备清空当前进程内的领域数据，根据新的 workspace epoch 重新查询 Supabase；不会下载完整快照或重建 SQLite 业务缓存。
- 其他在线设备收到 `workspace_reset` 后执行同样的权威重查。离线设备恢复连接后先比较 epoch，再重新查询；旧页面数据不能继续写入。
- 仍处于 `sync_v1` 的旧设备按兼容流程保持阻塞，不会静默覆盖或上传；先导出设备救援备份，再明确放弃并升级客户端。
- 可使用回滚前安全镜像把工作空间恢复到操作前状态。安全镜像默认保留 30 天，也可标记为受保护。
- 客户端中断时恢复锁最多保留 10 分钟；取消准备会主动释放锁，已创建的安全镜像仍保留并可识别。

## 自动化验收

运行 `npm run test:supabase:restore-e2e` 可执行隔离双设备回滚演练，覆盖 `direct_v2` 恢复后 epoch 更新、进程内数据清空和权威重查，以及旧 `sync_v1` 设备的救援兼容流程。真实 Supabase 账号演练使用 `npm run test:supabase:e2e`，需先配置专用可丢弃测试账号的环境变量。
