# Spec Delta

## Purpose

该能力用于根据报告周期内的完成事实和最终工时形成稳定、可核对的报告事项汇总，并保证用户在创建前看到的预览与最终保存的报告使用相同的数据范围和渲染口径。

## ADDED Requirements

### Requirement: 报告按稳定事项身份汇总实际用时

系统 SHALL 将报告周期内有效时间分配和实际用时调整按稳定事项身份汇总。同一事项关联多条时间记录时 MUST 只形成一条事项结果，其实际用时 MUST 为这些记录和调整的分钟合计；重复事项的每日实例 MUST 归并到对应的原始事项，不得作为重复事项行单独展示。

#### Scenario: 同一事项存在多条当天时间记录
- **WHEN** 用户创建日报，事项 A 在报告日期存在多条有效时间分配
- **THEN** 报告只展示一条事项 A，实际用时等于所有相关分配分钟之和

#### Scenario: 时间记录包含实际用时调整
- **WHEN** 事项 A 在报告日期既有时间分配又有有效的实际用时调整
- **THEN** 报告中事项 A 的实际用时包含时间分配与调整值的合计

#### Scenario: 重复事项通过每日实例计时
- **WHEN** 重复事项 A 的多个当天实例或实例时间分配属于同一报告日期
- **THEN** 报告以稳定事项 A 展示一条结果，并合并所有实例的实际用时

### Requirement: 日报自动范围只包含当天有效事项

系统 SHALL 在未指定人工事项范围时，自动选择报告日期内存在有效实际用时或当天完成事实的稳定事项。仅因事项当前处于未完成状态、属于主体或存在于其他日期的计划中，系统 MUST NOT 将其自动加入当天日报。

#### Scenario: 进行中事项当天没有执行记录
- **WHEN** 事项 A 当前未完成，但报告日期内没有实际用时且没有完成事实
- **THEN** 自动生成的日报不包含事项 A

#### Scenario: 当天有用时但尚未完成
- **WHEN** 事项 A 在报告日期内存在有效实际用时且当前尚未完成
- **THEN** 自动生成的日报包含事项 A 并标识其实际用时

#### Scenario: 当天完成但没有实际用时
- **WHEN** 事项 A 在报告日期内完成但没有实际用时
- **THEN** 自动生成的日报包含事项 A，且不得虚构实际用时

### Requirement: 日报事项展示合并后的实际用时

系统 SHALL 在日报的叶子事项后展示该事项在报告日期内合并后的实际用时。时长 MUST 按报告时长设置使用分钟或小时格式；作为层级上下文展示的父事项不得重复累计或重复展示子事项工时。

#### Scenario: 展示合并用时
- **WHEN** 事项 A 当天合并后的实际用时为 95 分钟且报告使用分钟格式
- **THEN** 日报在事项 A 后展示等价于“实际：1h35min”的时长信息

#### Scenario: 父事项仅用于层级上下文
- **WHEN** 被纳入日报的子事项 A 具有未直接计时的父事项 P
- **THEN** 报告保留 P 以表达层级，但只在 A 上展示 A 的实际用时，不把该用时重复显示为 P 的实际用时

### Requirement: 创建预览与最终报告保持一致

系统 SHALL 让创建报告预览与最终创建使用相同的周期归一化、自动事项范围、稳定事项聚合、模板和渲染规则。在预览后相关数据未变化且用户使用相同输入创建报告时，最终保存的 Markdown MUST 与预览 Markdown 一致。

#### Scenario: 预览后直接创建日报
- **WHEN** 用户查看某日期、主体和模板的日报预览后，在底层数据未变化的情况下直接创建报告
- **THEN** 保存的报告事项、每项实际用时、总工时和 Markdown 内容与预览一致

#### Scenario: 本地与云端使用相同业务口径
- **WHEN** 本地存储模式和 Supabase 直连模式分别基于等价数据创建同一范围的日报
- **THEN** 两种模式均按稳定事项合并用时、排除无关进行中事项，并展示每项合计实际用时
