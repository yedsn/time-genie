# Proposal

## Why

创建日报时的报告预览仍使用一套独立且较旧的数据筛选与渲染逻辑，可能列出与当天无关的进行中事项、重复事项实例，并且不展示同一事项多条时间记录合并后的实际用时。预览与最终生成结果口径不一致，用户无法在保存前准确确认日报内容。

## What Changes

- 统一创建报告预览与正式创建、重新生成所使用的事项范围和报告渲染口径。
- 日报只自动纳入当天已完成或存在有效实际用时的稳定事项，不因事项当前仍为进行中而自动列入。
- 将同一稳定事项在当天的多条时间分配、重复事项每日实例和实际用时调整合并为一条事项结果。
- 在日报每个叶子事项后展示合并后的实际用时，并保持配置的分钟或小时显示格式。
- 保证预览内容与使用相同日期、主体、模板和自动事项范围创建后的报告内容一致。
- 增加本地与 Supabase 直连模式的聚合、预览一致性和重复事项回归验证。

## Capabilities

### New Capabilities

- `report-generation`: 定义日报事项范围、稳定事项工时聚合、实际用时展示，以及创建预览与最终生成结果的一致性。

### Modified Capabilities

无。项目当前没有持久化主规格，本变更以新能力规格承接现有报告生成行为并补齐一致性要求。

## Impact

- 前端报告创建弹窗：`src-ui/src/components/ReportWorkspace.vue` 及报告预览请求类型。
- Rust/Tauri 报告命令与本地生成逻辑：`src-tauri/src/reports.rs`。
- Supabase 直连报告预览、范围选择与渲染函数，以及对应 schema 汇总文件。
- 报告生成相关 Rust 单元测试、Supabase schema 集成测试和必要的前端请求验证。
- 不新增持久化业务表，不改变既有报告、事项或时间记录的数据结构。
