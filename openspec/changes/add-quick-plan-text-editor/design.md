# Design

## Context

见 `proposal.md` 与 `specs/quick-plan-text-editing/spec.md`。当前待办页由 `PlanListEditor.vue` 展示当前主体的有序事项树，事项具有稳定 `id`、`parentId`、`sortOrder` 和 `version`。现有单项能力已经支持定位新增、标题更新、两级原子移动和子树软删除，但这些命令分别提交，不能保证整份文本调整全有或全无。

计划树当前最多两级，父事项不能是重复事项或具有直接工时的事项。事项还可能关联备注、预计、每日预计、重复规则、计时分配和云同步实体，因此不能通过标题重新匹配或用“全部删除后重建”实现批量编辑。工作区支持本地优先和 Supabase 同步，批量写入必须与现有 outbox 保持同一事务边界。

## Goals / Non-Goals

**Goals:**

- 用标题与层级的精确匹配把未变化文本映射到原事项，并把改名或改层级稳定地表达为删除旧事项与新建事项。
- 在前后端共享清晰的最终树快照和基线版本语义，让预览范围与实际提交范围一致。
- 在一个 SQLite 事务内应用整批变化、提升 revision 并创建云同步 outbox。
- 将文本解析、最终树校验、差异计算和摘要生成提取为可独立验证的纯逻辑。

**Non-Goals:**

- 不编辑已完成历史、事项备注、预计用时、日期、重复规则或计时数据。
- 不支持三级及更深层级、跨主体移动、Markdown 块级结构或自动排程。
- 不以标题作为数据库主键；只把标题与层级完全相同的行用于本次编辑中的原事项身份复用。
- 不把快速编辑入口放到今日概览页，也不替换现有逐项编辑和拖动交互。

## Decisions

### 1. 使用单个受控 Markdown 编辑区，并在文本变更后重建行模型

编辑弹框主体只有一个 `MdEditor` Markdown 编辑区，用户可以像编辑普通文本一样自由选择、剪切、粘贴、改名、删除和重排整段计划，不渲染逐行输入控件。工具栏只开放适合事项标题的行内格式，包括下划线、粗体、斜体、删除线、行内代码和链接；不开放标题、表格、列表等可能破坏“一行一个事项”语义的块级格式。下划线使用编辑器支持的 HTML 行内标记，因为 CommonMark 没有原生下划线语法。系统保存打开时的原计划行集合，每次 Markdown 源文本变化后重新解析。只有标题文本（含 Markdown 标记）和缩进层级都完全一致的行才复用原 `taskId`；新行获得会话内 `lineKey`。

多个标题和层级完全相同的行按原计划出现顺序依次消费匹配项，行为固定。解析时剥离结构性的“- ”列表前缀，列表符号不进入事项标题；未精确匹配的文本行一律创建新事项，未被消费的原事项一律删除；不做改名推断、模糊相似度或位置配对。编辑器输出一级“- 事项”、二级“  - 子事项”，Tab/Shift+Tab 只修改列表行前的层级缩进。

逐行输入控件可以天然绑定 ID，但不符合“整个功能只是一个输入框”的交互目标，因此不采用。删除并重建全部事项虽然适合纯文本，却会破坏备注、预计、重复规则、计时和同步身份，也不采用。

### 2. 缩进解析采用严格且可定位的规范

序列化时一级行无前缀，二级行输出两个空格。粘贴或导入文本时仅接受空前缀、一个 Tab、两个空格或四个空格；一或三个空格、Tab 与空格混用、两个 Tab或超过四个空格都产生带行号的错误。纯空白的新行不进入最终树。

编辑器中的 Tab/Shift+Tab直接改变 `depth`，而不是向标题插入制表符。二级列表行必须跟随一个最近的一级列表行，该一级行成为其父级。用户不能把含子项的行整体缩进为二级，也不能制造三级结构。结构性的“- ”前缀会被解析器剥离，标题保留其余文本。

宽松地按任意空白数量推断层级看似方便，但会把复制产生的对齐空格误认为层级，也无法明确区分二级与未来更深层级，因此不采用。

### 3. 草稿差异由精确复用结果和最终树共同计算

打开编辑器时保存完整基线：当前主体 ID、按顺序排列的所有进行中持久事项、每项版本及父子关系。最终行模型解析为扁平有序树后按以下规则计算：

- 精确匹配后带 `taskId` 的行只会产生顺序移动；
- 无 `taskId` 的非空行生成创建项，并用 `lineKey` 表达新事项之间或新旧事项之间的父级引用；
- 基线中不存在于最终树的事项生成待删除项；
- 先被移动出原父项的子事项仍在最终树中，因此不进入父项的级联删除集合；
- 空白的新行忽略，清空已有行等同于从最终树移除。

变化摘要直接使用该差异结果，不再在提交时另行推断。改名和改层级表现为“删除旧事项 + 新增新事项”，标题允许重复并按原顺序精确消费匹配。

### 4. 删除范围完全由最终文本决定

用户在单个 Markdown 编辑区中删除父项或子项时，系统不执行即时级联动作，也不需要额外的逐行删除控制。保存差异时，所有未被精确复用的旧事项都会进入待删除范围；用户如果要保留子项，只需把它作为最终文本中的一条完整行保留，并按需要调整其缩进。

进入摘要时，删除区按原计划路径展示每个待删除事项，并将父项下仍被移除的子项缩进列出。删除按钮文案与普通无删除保存区分为“确认删除并保存”。摘要返回编辑不会修改数据库，且草稿保持不变。

只显示删除数量会隐藏重建后的删除范围；因此摘要仍需按原计划路径展开所有未匹配旧事项，但不在编辑过程中强行级联删除。

### 5. 批量请求同时携带基线快照、最终树和精确删除确认集合

新增 `task_plan_batch_apply` 类型的命令，请求至少包含：

- `subjectId`；
- `baselineTasks`：编辑器打开时所有进行中事项的 `taskId` 与 `expectedVersion`；
- `finalItems`：最终有序行，包含 `lineKey`、可选 `taskId`、标题和可选 `parentLineKey`；
- `confirmedDeleteTaskIds`：用户在摘要中实际确认的精确事项 ID 集合。

后端不信任前端的变化类型或排序值，而是根据基线和最终快照重新计算。它验证当前主体的进行中事项 ID 集合与基线完全相同、每项版本一致、已有 ID 不重复或跨主体、新行 key 唯一、父引用存在、最终深度最多两级、父项资格有效，以及服务端删除集合与 `confirmedDeleteTaskIds` 完全相同。任何集合差异都返回冲突，前端保留草稿并要求重新加载/预览。

只传变化项无法发现编辑期间其他设备新增的事项，可能在用户不知情时覆盖顺序或产生不完整摘要；只使用全局 revision 又会让无关主体或计时变化造成过多冲突，因此采用当前主体进行中事项快照。

### 6. 后端按最终状态在单个事务中重建该主体的活动树位置

事务开始后完成全部验证并为新行预生成任务 ID，再按父项优先顺序创建新事项。随后按最终树为所有保留事项写入规范化 `parent_id` 与同级 `sort_order`（固定间隔如 10），只在标题或位置实际变化时提升该任务版本。

删除使用服务端已经验证的精确集合执行软删除。事务先应用仍保留事项的父级变化，再删除缺失事项，因此已明确移出父项的子事项不会被递归误删；对于整棵被移除的子树，集合中会同时包含父项和子项。所有创建、更新和删除在同一事务内提升一次工作区 revision，并逐实体创建现有 task outbox。提交后才执行在线 flush，返回创建映射与变化计数，前端最终重新加载权威计划。

逐条调用现有 create/update/move/delete 命令会产生部分成功、多个 revision 和中途同步，无法满足一致保存，因此不采用。直接删除当前主体全部事项再重建会破坏所有附属数据和外部身份，同样不采用。

### 7. 父项资格和完成状态使用现有领域规则

最终树中成为父项的已有事项必须非重复且没有直接工时；成为二级的事项不能仍带有保留子项。新建事项尚无重复规则和工时，可以成为父项。批次只接受打开编辑器时属于当前主体的进行中事项；已完成历史不参与快照，也不会因本批次被重新打开或删除。

前端纯逻辑可提前给出同样提示，但后端必须重新校验，以处理旧客户端、并发数据和恶意请求。

## Risks / Trade-offs

- [Markdown 编辑表面的光标、选择和输入法处理更复杂] → 把身份与树结构放在独立行模型中，补充中文输入法、多行粘贴、撤销和键盘焦点的组件级验证。
- [用户可能把清空标题当作暂时编辑而不是删除] → 只有进入摘要时才把空白已有行视为待删除，摘要单独列出且必须显式确认。
- [主体事项较多时完整快照和版本校验成本增加] → 请求只包含当前主体进行中事项，使用 ID 映射和一次事务查询；这是换取防误删与一致性的可接受成本。
- [规范化全部同级排序可能提升多条任务版本并产生较多 outbox] → 仅更新标题、父级或目标排序值实际变化的事项；排序固定间隔，避免后续频繁归一化。
- [编辑期间云端变化会让长时间草稿无法直接保存] → 保留本地草稿和变化摘要，明确提示冲突；不自动合并删除与层级变化，以安全优先。
- [父项删除动作同时移除可见子树可能误操作] → 提供立即撤销、完整删除摘要和独立确认按钮，数据库写入前不改变任何持久数据。

## Migration Plan

1. 先实现并验证前端行模型、序列化/解析、差异和删除摘要纯逻辑，不接入保存。
2. 增加后端批量请求、主体快照校验、最终树验证、事务保存与云同步测试，不改变现有单项命令。
3. 接入待办页入口和编辑弹框，先支持预览，再连接批量保存与冲突提示。
4. 验证空计划、重复标题、新旧事项混排、父子移动、级联删除、版本冲突、本地模式和云端模式。

回滚时移除快速编辑入口和批量命令调用即可；现有逐项编辑、拖动和删除命令保持不变。新命令不新增表，已保存结果仍是普通任务记录，不需要数据回滚。
