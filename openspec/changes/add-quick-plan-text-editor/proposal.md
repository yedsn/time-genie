# Proposal

## Why

待办页虽然已经支持逐项编辑、拖动排序和层级调整，但当用户需要一次性整理大量计划时，逐行操作仍然低效，也不利于直接粘贴或重写一整段计划。需要提供一种接近纯文本的批量编辑方式，让用户通过换行和缩进快速完成当前主体计划树的新增、改名、排序、层级调整与删除，同时避免误删和部分保存。

## What Changes

- 在待办页“分配今日预计”右侧增加“快速编辑计划”入口，打开当前主体进行中事项的文本式编辑器。
- 使用“每行一个事项、无列表符号”的格式；无缩进表示一级事项，Tab、两个空格或四个空格表示二级事项，超过两级时阻止保存并定位错误。
- 使用一个多行文本输入框重建当前计划；标题与缩进完全相同的行按原出现顺序复用原事项，保留其备注、预计、重复规则和计时关联；其余行创建新事项，未匹配的旧事项删除。
- 将从文本中移除的已有事项标记为待删除，不立即修改数据；保存前展示新增、修改、移动和删除摘要。
- 删除父事项时，将其原有子事项明确列为级联删除对象；存在删除时要求用户执行独立的“确认删除并保存”操作。
- 以单次原子批量操作保存整份计划差异，并校验事项版本、主体归属、两级限制、父事项资格和删除范围；任一校验或写入失败时整体回滚。
- 今日页继续保持概览定位，不增加完整计划树编辑入口。

## Capabilities

### New Capabilities

- `quick-plan-text-editing`: 定义当前主体计划树的文本式批量编辑格式、身份保留、差异预览、显式级联删除确认和原子保存行为。

### Modified Capabilities

无。项目当前没有已归档的主规格；本能力与进行中的 `plan-task-interactions` 和 `quick-plan-estimate-allocation` 变更协作，但不改变它们已经定义的单项交互与今日预计规则。

## Impact

- 前端待办编辑：`src-ui/src/components/PlanListEditor.vue` 增加入口、文本式编辑弹框、行身份维护、解析错误和变化摘要。
- 前端纯逻辑：新增计划文本序列化、缩进解析、身份对齐和差异计算服务及专项验证。
- 前端状态与 Tauri 类型：`src-ui/src/store.ts`、`src-ui/src/services/tauri.ts` 增加整份计划批量保存协调入口。
- Rust 事项领域：`src-tauri/src/tasks.rs` 增加批量计划变更请求，在一个 SQLite 事务中完成创建、更新、移动和软删除，并生成现有云同步 outbox。
- 数据模型：复用 `tasks.parent_id`、`sort_order`、`version` 和 `deleted_at`，不新增表或迁移。
- 验证：覆盖缩进兼容、重复标题、身份保留、父子级联删除摘要、父事项约束、版本冲突、事务回滚和跨设备同步。
