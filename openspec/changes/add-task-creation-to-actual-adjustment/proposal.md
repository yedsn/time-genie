# Proposal

## Why

用户在核对当天实际时间时，可能发现当天临时增加了尚未进入计划的工作。若必须退出“调整今日实际”面板、先到计划列表创建事项再重新打开面板，会打断快速核对流程，因此需要允许在该面板内直接补建当天事项并填写其最终实际分钟。

## What Changes

- 在“调整今日实际”面板内增加“新增事项”，允许一次暂存多个新事项。
- 新事项归属当前主体，名称必填，可作为顶层叶子事项或放入一个符合现有层级规则的父事项下，并默认计划到当前工作日期。
- 新事项创建后立即进入同一面板，可直接输入“今天最终应该是多少分钟”；其打开时实际基线固定为 0。
- 保存前的变化摘要单独列出新增事项、层级位置、目标实际和将创建的正向调整。
- 将新增事项与本批实际调整放入同一原子保存流程；任一事项或调整校验/写入失败时全部回滚。
- 目标为 0 的新事项仍会创建，但不创建零分钟调整记录；取消或关闭面板不会创建尚未保存的草稿事项。
- 新事项和对应调整沿用本地优先、幂等请求、outbox 与云同步机制。

## Capabilities

### New Capabilities

- `actual-adjustment-task-creation`: 定义在“调整今日实际”面板内暂存、预览并原子创建当天叶子事项及其初始实际调整的行为。

### Modified Capabilities

无。项目当前没有已归档主规格；本能力扩展尚在规划中的 `add-quick-actual-time-adjustment` 变更，并以其调整面板、调整记录和批量保存能力为前置依赖。

## Impact

- 前置变更：实施前需要 `add-quick-actual-time-adjustment` 提供调整面板、快照、调整记录和批量保存基础。
- 前端计划页：`src-ui/src/components/PlanListEditor.vue` 的调整面板增加事项草稿、父级选择、目标分钟和新增摘要。
- 前端状态与封装：`src-ui/src/store.ts`、`src-ui/src/services/tauri.ts` 扩展批量请求，以客户端草稿标识关联新事项和初始调整。
- Rust 事项与调整领域：`src-tauri/src/tasks.rs` 与实际调整模块共享事项校验，并在一个事务内创建事项、调整记录和同步 outbox。
- 云同步：新事项与初始调整保持依赖顺序、批次幂等和双设备收敛。
- 验证：覆盖顶层/子事项、层级限制、多个新事项、目标为零、混合现有调整、取消、失败回滚、重复请求和离线同步。
