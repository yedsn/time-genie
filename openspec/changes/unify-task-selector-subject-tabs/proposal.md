# Proposal

## Why

当前事项选择器把多个主体的事项合并到同一列表，并在输入框左侧额外放置主体选择框，用户很难快速辨认事项所属主体，且不同计时、补录和分配入口的创建行为不够一致。需要把主体切换、层级浏览、搜索和新建方式统一到同一个下拉交互中。

## What Changes

- 移除事项输入框左侧的主体选择器，把主体切换改为候选下拉层顶部的 Tab。
- 取消“全部主体”混合列表，一次只展示一个主体的事项，并提供清晰的默认主体选择规则。
- 事项顺序和父子缩进与待办页面保持一致，一级事项作为层级上下文展示，具体可选择事项保持现有资格限制。
- 切换主体时保留搜索文字和当前已选择事项；新选择具体事项时才替换原关联。
- 所有复用通用事项选择器的计时、手动补录、时间记录分配和未归属时间入口采用相同交互。
- 所有入口的新事项创建统一为显式的“新建为一级事项”和“新建为二级事项”；二级创建后再选择当前主体下可用的一级父事项，取消失焦自动创建临时一级事项。

## Capabilities

### New Capabilities

- `unified-task-selection`: 定义跨计时、补录和工时分配入口统一的主体 Tab、树形事项列表、搜索选择及显式分级创建行为。

### Modified Capabilities

无。项目当前没有已归档主规格，本变更以新的统一事项选择能力承接既有选择器行为。

## Impact

- 前端组件：重点调整 `src-ui/src/components/TaskSelectControl.vue` 及 `src-ui/src/styles.css`，调用方继续复用公共组件。
- 前端状态：复用 `store.selectedSubjectId`、主体列表和与待办一致的树形事项顺序，必要时抽取共享选择器纯逻辑。
- 兼容入口：`GlobalTimerBar.vue`、`TimeTrackingWorkspace.vue`、`UnassignedTimeDialog.vue` 的事项选择与创建语义统一。
- 不修改 SQLite、Supabase、Rust 领域命令和同步协议；计时原子转换及事项父级资格校验继续沿用现有实现。
- 验证：补充主体默认值、Tab 切换、层级顺序、搜索保留、显式创建和公共入口覆盖检查，并运行前端类型检查及构建。
