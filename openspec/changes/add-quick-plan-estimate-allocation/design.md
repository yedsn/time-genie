# Design

## Context

见 `proposal.md` 与 `specs/quick-plan-estimate-allocation/spec.md`。计划页当前由 `PlanListEditor.vue` 在每条事项元信息中直接编辑 `task.todayEstimate`，失焦后通过 `store.saveTask` 或 `saveTaskTodayEstimate` 保存。普通事项使用 `task_daily_estimates`，重复事项的有效今日预计为日期覆盖值优先、否则回退到 `tasks.estimate_minutes`；进行中的 `enhance-plan-task-interactions` 变更还会把重复事项今日预计与每次预计组合保存。

主体已经具有按星期配置的工作时段及读取接口，默认工作日为 10:00-12:00、13:30-17:30，共 360 分钟。现有今日预计命令逐条提交，普通事项写入不携带预期版本，无法满足快速分配批次的全有或全无保存和冲突检测。

## Goals / Non-Goals

**Goals:**

- 把时长解析、可分配事项判定、容量计算和草稿差异计算提取为无 UI 依赖的纯逻辑。
- 用一次后端事务保存同一主体、同一日期的一批预计变更，并让本地数据与同步 outbox 同时成功或同时回滚。
- 让快速分配的焦点流稳定可测，不依赖浏览器表单默认行为。
- 复用现有事项、每日预计、重复事项预计和主体工作时段数据，不新增持久化表。

**Non-Goals:**

- 不做自动排程、自动拆分事项、开始时间安排或跨日期容量平衡。
- 不把临时调整的当日容量保存为工作时段配置，也不新增个人每日容量设置。
- 不修改标题来存储时长快捷码，也不继续扩展 Obsidian 的末尾裸数字语法。
- 不让有进行中子事项的父事项参与快速分配；父项既有预计的清理留在单项编辑入口。
- 不重新实现 `enhance-plan-task-interactions` 已规划的单项默认值、重复事项有效预计和组合保存语义。

## Decisions

### 1. 快速分配使用独立草稿面板，列表本身保持只读

`PlanListEditor.vue` 增加“分配今日预计”入口和单实例面板。面板使用现有对话框体系，内容以紧凑的树形行展示：父事项为分组行，叶子事项为输入行。弹框在窗口中间显示，高度取窗口 90% 与固定最大高度中的较小值，头部、汇总和底部固定，事项列表在剩余空间内滚动。进入时从权威任务列表构造 `originalMinutes` 与 `draftText/draftMinutes`，编辑期间不直接修改响应式 `Task` 对象。

关闭时根据草稿与原值的差异决定是否提示放弃。成功提交后重新加载任务和今日概览，再关闭面板；提交失败时保留全部草稿和焦点上下文。

备选方案是在原计划行内依次展开输入框。它仍会受到行元信息、拖动和其他操作按钮干扰，难以形成稳定的纯键盘流程，因此不采用。

### 2. 预计输入统一使用分钟，并提供十五分钟步进

输入框接受 0 到 1440 的整数分钟，其中 `0` 和空字符串都映射为内部的未分配状态；初始化、清空和空输入失焦后统一显示 `0`，保存时仍提交空预计而不是 0 分钟记录。小数、单位、负数和超限值返回带用户文案的错误。输入框保留无效的用户原始文本，只有确认或步进操作才更新规范化分钟草稿，以免无效输入覆盖原值。

输入框左右分别提供减少和增加 15 分钟按钮。增加从未分配状态起步为 15 分钟；减少到 0 分钟时转为未分配状态，但界面继续显示 `0`。右侧以只读文字显示分钟值换算后的小时数，未分配时显示 `0 小时`，其他值最多保留两位小数。错误提示仅在存在错误时渲染于输入控件下方并撑高当前事项行；正常事项不预留辅助区域，以保持列表紧凑。

此前的 15、30、45、60 快捷按钮和小时简写会占用事项名称空间，也形成两套输入心智，因此移除。容量输入继续保留显式时长格式，因为它不是逐项高频录入控件。

### 3. 可分配集合按进行中叶子事项计算

从当前主体、当前计划标签的有序事项构建活动子节点映射。只要某事项存在至少一个进行中直接子项，它就在快速分配中成为只读分组；否则该进行中事项是可分配叶子。完成且非重复的子项不阻止父项成为叶子，重复事项按当天有效状态沿用计划页现有活动判定。

容量合计只遍历可分配叶子的草稿。分组父项已有日期预计时显示“不计入快速分配合计”的提示，但不把它放入批次差异，避免新功能在无明确操作时删除旧数据。

备选方案是父项和子项都可编辑，再提供“是否计入”开关。它把去重责任交给用户，容易造成今日概览双计，因此不采用。

### 4. 默认容量从主体工作时段派生，调整仅保存在组件内存

进入模式时读取当前主体的七天工作时段，以目标日期在工作空间时区中的星期选择当天配置，并把每个区间的 `结束分钟 - 开始分钟` 相加。休息日或禁用日为 0。组件保存 `capacityMinutes` 草稿，允许用户用与事项时长相同的显式格式调整，但不调用工作时段保存接口。

汇总纯函数返回 `allocatedMinutes`、`capacityMinutes`、`remainingMinutes` 和 `overMinutes`。超载只改变提示状态，不影响提交按钮。

备选方案是固定 360 分钟。项目已经支持不同主体与不同星期的工作时段，固定值会让已有配置失效，因此不采用。

### 5. 后端增加原子的预计批量保存命令

新增批量请求，包含 `subjectId`、`workDate` 以及仅有变化的条目。每条条目至少包含：

- `taskId`；
- `expectedTaskVersion`，用于验证事项主体、删除状态和重复事项模板更新；
- `expectedDailyEstimateVersion`，不存在时为 null，用于检测每日预计在编辑期间被其他设备新增、修改或删除；
- `estimateMinutes`，null 表示清空。

后端先验证日期、条目唯一性、所有事项属于请求主体且仍为有效事项、版本基线一致以及分钟范围，再开启或在同一事务中完成全部写入：

- 普通事项新增、更新或删除对应 `task_daily_estimates`。
- 重复事项的正数值复用组合保存语义，同时更新 `tasks.estimate_minutes` 和日期预计。
- 重复事项清空时，若存在每次预计，前端不把它作为普通“清空当日”操作提交，而是提示用户返回单项重复预计入口处理，避免清空日期覆盖后立刻又回退到每次预计；若不存在每次预计则可以删除日期覆盖。

所有条目处理完成后只提升一次全局 revision，并在同一事务中为各变更创建现有 task/task_daily_estimate outbox；重复事项的日期操作依赖对应 task 操作。事务提交后再执行在线 flush。返回变更后的任务/每日预计摘要，前端仍以重新加载权威列表为准。

备选方案是前端 `Promise.all` 调用现有单项命令。任一请求失败时其他请求已经提交，无法实现批次回滚，也无法可靠建立重复事项同步依赖，因此不采用。

### 6. 每日预计增加可见基线版本但不改变表结构

任务列表在请求 `dailyEstimateDate` 时，同时返回该日期预计记录的版本；无记录为 null。重复事项从每次预计回退得到的显示值仍需区分“日期记录不存在”，因此 DTO 分别暴露有效显示值和日期预计版本，而不是伪造一条日期记录。

批量提交验证：基线为 null 时当前也必须不存在；基线为数字时当前记录必须存在且版本相同。这样普通事项的每日预计也能检测跨设备竞争，而不需要给表新增字段。

### 7. 键盘导航由显式可分配 ID 顺序驱动

面板维护 `allocatableTaskIds` 和当前焦点索引。Enter 在当前输入有效时提交该行草稿并移动；方向键在输入没有需要浏览器处理的候选菜单时切换；到达边界时不循环。最后一项确认后把视觉重点移向完成按钮，但不自动提交。聚焦后选中完整文本，方便直接覆盖。

父级分组、隐藏或完成的事项不进入索引。若后台刷新导致事项集合变化，编辑中的面板不热替换草稿；最终由版本验证阻止静默覆盖。

### 8. 既有预计仅作为显式建议

每行可显示 `task.estimate` 作为建议。普通事项的整体预计、重复事项的每次预计以及 Obsidian 导入的结构化预计都通过同一“采用建议”动作写入草稿。已有日期预计始终优先初始化草稿，不自动采用建议，也不从标题解析末尾数字。

## Risks / Trade-offs

- [纯分钟输入可能让用户暂时失去小时尺度感] → 输入框右侧持续显示小时换算，左右提供 15 分钟步进按钮，兼顾精确录入和快捷调整。
- [批量命令与进行中的重复预计实现发生代码重叠] → 先把单条普通/重复预计写入提取为接收事务的领域函数，再让单项和批量命令共同调用。
- [父项历史预计仍会被其他页面统计，快速面板合计可能与今日概览不同] → 面板明确列出未计入的父项历史预计；本变更不隐式迁移或删除用户数据。
- [大量事项产生较多 outbox 行] → 仍按现有实体粒度同步，但只提交有变化的条目，并在整个批次完成后统一触发一次在线 flush。
- [工作时段在打开面板后被另一设备修改] → 容量是本次规划提示而非持久业务数据，不参与版本冲突；重新打开面板时读取最新配置。
- [重复事项清空语义容易误伤未来日期] → 有每次预计时禁止在快速面板中用普通清空完成该操作，转到明确说明影响范围的单项入口。

## Migration Plan

1. 先增加每日预计版本读取、事务内预计写入辅助函数和批量保存命令及后端测试，不改变当前计划页入口。
2. 增加前端时长解析、叶子筛选、容量汇总和差异计算纯函数及专项验证脚本。
3. 接入快速分配面板、键盘导航、建议值和放弃确认，再连接批量保存命令。
4. 验证普通事项、重复事项、父子事项、休息日、版本冲突和云同步场景。

回滚时移除快速分配入口即可；批量命令和新增 DTO 字段保持向后兼容。由于不新增表且所有数据仍写入现有预计字段，回滚不会丢失已保存结果。
