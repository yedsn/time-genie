# Proposal

## Why

云端模式目前把 collecting、awaiting_resolution 未归属会话及其分段限定为设备本地状态，只同步处理后生成的最终时间记录。因此一台设备已经分配、记为休息或丢弃某段未归属时间后，另一台设备仍可能继续累计并再次要求处理同一时间，造成多端状态不一致和重复计时。

## What Changes

- **BREAKING**：云端模式下未归属会话不再是设备本地临时状态，而改为工作空间共享状态；本地模式继续保持纯本地行为。
- 未归属会话的创建、暂停、继续、进入待处理、分配到事项、记为休息和丢弃均进入事件驱动同步，并以统一版本防止多设备重复处理。
- 一台设备处理共享未归属会话后，其他设备自动结束并移除该旧会话，不再继续显示旧累计时间或再次弹出旧处理窗口。
- 若收到处理结果时某设备没有活动事项计时且仍处于空闲采集条件，该设备从远端 `resolved_at` 开始建立新的未归属会话；处理前的时间只属于旧会话，处理后的时间只属于新会话。
- 若其他设备当时正在事项计时，则只清除旧未归属会话，不创建新的未归属会话；事项计时的既有全局租约和单活动计时规则不变。
- 增加断线、重连、重复/乱序通知和并发处理保护，确保离线设备恢复后不会复活已处理会话，也不会重复生成工时记录。
- 为从设备本地未归属模型升级到共享模型提供 SQLite 与 Supabase 兼容迁移，清理或封存不能安全合并的旧活动会话并避免重复分钟。

## Capabilities

### New Capabilities

- `shared-unassigned-time`: 定义云端模式下工作空间共享的未归属会话、跨设备处理传播、处理后重新计时边界、并发和离线恢复语义。

### Modified Capabilities

无。主规格目录尚未归档 `timer-sync-coordination`；本变更以新的共享未归属能力明确覆盖旧变更中“未归属临时会话保持设备本地”的行为。

## Impact

- Rust：`src-tauri/src/unassigned.rs` 需要为会话生命周期写入 outbox、应用远端处理结果并按统一边界重建下一会话；`src-tauri/src/cloud_sync.rs` 需要取消对本地活动未归属会话的覆盖保护并完整处理会话/分段增量。
- SQLite：需要新增迁移以区分共享会话来源、处理边界和兼容旧设备本地会话，替换 `0007_local_only_unassigned_sessions.sql` 建立的运行假设。
- Supabase：`unassigned_sessions`、`unassigned_segments`、`workspace_changes` 与 `cloud_apply_patch`/增量读取契约需要支持共享会话聚合、版本校验和处理幂等。
- Vue：未归属状态变更后继续通过 `work-data-changed` 的 `unassigned` 领域刷新；打开的处理弹窗在远端已处理时应关闭或刷新为新的会话。
- 兼容性：旧客户端仍可能只上传最终时间记录；服务端补丁需要保持旧 RPC 调用可用，但共享未归属一致性只由升级后的客户端保证。
- 验证：需要双设备覆盖同时空闲、某端事项计时、远端处理、离线恢复、并发处理和处理后重新计时，确认没有旧时间继续累计、重复工时或重复处理。
