# Design

## Context

见 `proposal.md` 的问题说明和 `specs/shared-unassigned-time/spec.md` 的行为要求。当前实现通过 SQLite 迁移 `0007_local_only_unassigned_sessions.sql` 删除 `unassigned_session` outbox，并在 `unassigned.rs` 中只为处理后生成的 `time_entry` 入队；`cloud_sync.rs` 的完整快照与增量逻辑还会主动保留本机活动未归属会话、忽略远端 `unassigned_sessions` 对它的覆盖。该模型解决了旧版伪冲突，但无法让多个客户端共享处理状态。

计时记录已有本地优先 outbox、实体版本、幂等 operation ID、跨实体依赖和事件驱动协调器。Supabase 已有 `unassigned_sessions`、`unassigned_segments` 表、工作空间变更触发器和快照字段，但现有客户端不再上传活动会话。设计应复用这些能力，而不是建立第二条同步通道。

## Goals / Non-Goals

**Goals:**

- 云端工作空间同一时刻只有一个可处理的共享未归属会话。
- 一台设备处理后，所有设备使用同一 `resolved_at` 切断旧累计并按需开始下一会话。
- 保持本地写入即时、事件驱动后台同步、离线可恢复和处理幂等。
- 不重复计算多设备重叠的空闲分钟，也不重复生成最终工时。
- 本地模式行为保持不变。

**Non-Goals:**

- 不把事项计时改成每秒上传；秒级显示仍由共享开始边界与本地时钟派生。
- 不允许多台设备各自拥有并累加独立未归属时长。
- 不改变未归属分配、休息、丢弃或“同时完成事项”的业务含义和界面布局。
- 不移除现有计时设备租约或全局单活动事项计时约束。

## Decisions

### 1. 以工作空间共享会话作为唯一累计根

云端模式下 `unassigned_session` 恢复为可同步聚合实体，包含会话状态、工作日期、阈值、首段开始时间、累计秒数、处理类型、最终记录、`resolved_at` 和版本；segments 作为会话聚合的子数据随同应用。客户端读取未归属状态时优先使用本地缓存中的共享会话，不再无条件创建设备私有活动会话。

服务端应保证一个工作空间最多存在一个 collecting/awaiting_resolution 共享会话。创建下一会话使用幂等的 compare-and-create RPC 或 `cloud_apply_patch` 受约束动作，避免两台空闲设备同时创建两个根。

备选方案是继续让每台设备独立累计、只广播“已处理”的 tombstone。该方案仍无法统一处理前的累计数字，也无法可靠判断处理后应从哪个设备会话继续，因此不采用。

### 2. 离散生命周期动作写入 outbox，不上传每秒累计

需要同步的动作包括：创建会话、事项计时开始时暂停、事项计时结束时继续、达到待处理状态、处理为 work/break/discard。运行中的秒数由 `duration_seconds + (now - open_segment.started_at)` 派生，不按秒写云端。

会话 payload 保存完整聚合镜像，沿用 time_entry 的同实体版本链协调规则。未发送的连续 pause/resume 可以安全合并为最新完整镜像；sending、conflict 和未知结果仍形成硬边界。

备选方案是只同步处理动作。它无法让另一设备在处理前显示同一会话和同一版本，也无法防止并发处理，因此不采用。

### 3. 处理动作以会话版本和 operation ID 保证唯一

分配、休息和丢弃在一个本地事务中：封口共享会话、写入处理类型和 `resolved_at`、生成最终 time_entry、记录 processed operation，并将共享会话与 time_entry 一起入队。会话操作先提交；time_entry 和可选的 task/task_occurrence 操作依赖会话处理操作成功。

服务端以 session ID、expected version 和 operation ID 原子确认处理。第一个处理成功后提升版本并固定 `resolved_at`；后续同版本处理返回当前终态，不执行第二次业务副作用。客户端把它作为“已由另一设备处理”收敛信号，而不是允许用户覆盖已处理结果。

### 4. 使用 `resolved_at` 作为唯一重新计时边界

应用远端终态时先关闭或删除本地旧会话的开放分段，边界不得晚于云端 `resolved_at`。如果本机没有活动事项计时，协调器尝试获取/创建下一共享会话，开始时间固定为 `resolved_at`，而不是消息到达时间。

若此期间已经存在由其他设备创建的下一共享会话，则直接采用该会话；若本机存在活动事项计时则不创建，待事项计时结束后通过现有 resume 入口获取或创建当时的共享会话。对同一终态的重复通知通过 session version、next-session predecessor ID 或等价唯一约束保持幂等。

### 5. 增量应用不再保留设备本地活动未归属覆盖层

删除 `unassigned_change_is_accepted_without_overwriting_device_local_session`、快照保留本机活动会话等旧假设。增量适配器把 `unassigned_sessions` 与 segments 作为聚合实体短事务应用，并在变化后发布 `unassigned` 领域。前端收到刷新后，如果打开的弹窗 session ID 已失效，则关闭旧弹窗或加载新会话。

本地 dirty 共享会话仍遵守通用延迟协调：远端变化涉及同一 session 时先保留本地结果并记录 deferred entity；相关 outbox 成功或冲突收敛后重取云端最新状态。不同实体继续正常应用。

### 6. 将采集资格与事项计时租约结合

共享未归属会话表示工作空间没有活动事项计时的空闲区间，因此开始或恢复会话前必须确认本地缓存和云端租约没有活动事项计时。事项计时开始会暂停共享会话，结束会恢复/创建共享会话；这些动作走同一协调器排序，避免某设备处理旧会话时另一设备同时继续旧分段。

不新增高频租约轮询。连接恢复、事项计时离散动作和 Realtime 通知负责唤醒协调；现有租约续期计时器只维护计时所有权。

### 7. 分阶段迁移旧设备本地会话

新增 SQLite 迁移保存共享会话来源和前序处理边界，并允许重新为 `unassigned_session` 建立 outbox。首次进入云端共享模式时：

1. 若云端已有活动共享会话，封存本机旧 collecting/awaiting_resolution 会话并采用云端会话。
2. 若云端没有活动会话且本机只有一个旧活动会话，用其 `first_started_at` 和已封口累计创建共享会话。
3. 若多个设备各自带来旧会话，服务端 compare-and-create 只接受一个；其他客户端封存本地旧会话并采用已创建的共享会话，不合并或相加重叠时长。
4. 已 resolved/discarded 会话和已生成 time_entry 保持不变，避免重复历史记录。

旧客户端仍可继续只上传最终 time_entry，但不会具备共享一致性。服务端保留旧函数签名，升级客户端使用新的动作字段或版本化 RPC。

## Risks / Trade-offs

- [两台设备时钟有偏差导致 `resolved_at` 边界不一致] → 处理成功以服务端时间为权威，客户端本地临时结果在确认后校正边界且不得产生负时长。
- [处理会话成功但 time_entry 尚未上传] → 使用 outbox 依赖与相同 operation ID 重试；会话终态不得因子操作暂时失败而重新打开。
- [旧本地会话迁移丢失部分重叠时长] → 不相加无法证明独立的重叠区间，优先避免双计；迁移日志记录被封存会话和选定权威边界。
- [断线设备本地继续显示旧累计] → 本地缓存允许离线显示，但重连后必须先补齐终态再允许处理；离线处理与云端已处理发生竞争时按版本冲突采用先成功结果。
- [多个客户端同时创建下一会话] → 服务端活动会话唯一约束和 compare-and-create 幂等返回同一 session。
- [事项计时和未归属恢复竞态] → 会话生命周期与计时动作进入同一工作空间协调顺序，并在创建前检查活动计时租约。

## Migration Plan

1. 先部署 Supabase 兼容补丁：活动共享会话唯一约束、会话聚合读取、原子创建/处理动作、权限和集成测试；保持旧 RPC 可用。
2. 发布 SQLite 迁移和 Rust 聚合适配器，默认仍能读取旧本地会话，并在云端会话可用后执行一次收敛迁移。
3. 打开共享会话 outbox 与事件驱动增量，移除快照/增量对本机活动未归属会话的特殊保护。
4. 更新前端弹窗失效处理和未归属领域刷新，完成双设备、离线和并发验收后发布。
5. 回滚客户端时保留新增表列和服务端函数；旧客户端只能看到本机临时会话，因此回滚期间不保证跨设备一致性，但不得删除已生成 time_entry 或待同步 outbox。
