# Proposal

## Why

现有 Obsidian 计划导入固定读取前一日日报的“明日计划”，且所有主体共用一份本机路径配置，无法把各主体实际日报顶部已经记录的事项、完成状态和工时准确带入 TimeGenie。需要提供面向主体、按日报日期导入的统一能力，让用户能从待办页或今日页恢复当天真实工作数据，并避免手工重复录入。

## What Changes

- 在主体设置中增加当前设备专用的日报目录配置，每个主体可以指向不同目录；按 `YYYYMMDD.md` 定位所选日期的日报文件。
- 在待办页和今日页增加“从日报导入”入口，允许选择日期、预览解析结果、逐项勾选并确认导入。
- 只解析日报首个标题之后、后续“明日计划”“下周计划”等计划标题之前的顶部事项，保留编号、缩进层级和原始顺序，不提供明日计划切换。
- 识别 `🟢`、`🔴`、`<预计：...>` 和 `<实际：...>`：绿色事项导入为已完成并导入预计与实际分钟，红色事项导入为未完成且只导入预计分钟，无状态事项按未完成处理。
- 从待办页导入时创建长期事项；从今日页导入时创建所选日报日期的独立今日实例。实际分钟写入可审计的实际用时调整，不伪造计时区间。
- 记录稳定的日报来源信息，对同一主体、日期、文件和源事项的重复导入进行识别并跳过，允许用户在预览中看到已导入状态。
- 用新的“从日报导入”流程替代现有仅面向昨日明日计划的导入入口，同时保留其他 Obsidian 报告写入能力。

## Capabilities

### New Capabilities

- `daily-report-task-import`: 主体级本机日报目录配置、日报顶部事项解析、待办/今日导入、状态与时长映射及幂等保护。

### Modified Capabilities

无。当前项目没有已发布的主规格；相关历史 OpenSpec 仅作为现有实现背景。

## Impact

- 前端：主体设置弹框、待办与今日列表工具区、日报导入预览弹框及 Tauri 服务类型。
- 后端：Obsidian 文件定位与 Markdown 解析、事项/今日实例创建、完成状态写入、实际用时调整和导入批次幂等逻辑。
- 数据：需要保存按设备与主体区分的日报目录，以及能表达来源日期、源文件和源行身份的导入记录；相关本地数据需要纳入备份，业务导入结果继续沿用现有云端同步。
- 验证：覆盖真实 `YYYYMMDD.md` 样例、父子层级、状态图标、小时/分钟时长、重复导入、历史日期和待办/今日两种目标。
