# Design

## Context

见 `proposal.md` 与 `specs/tray-status-panel/spec.md`。当前悬浮窗口为实现事项搜索，预置约 `720x520` 的完整 WebView 表面，再通过 Windows 原生区域裁剪显示右下角 `420x360` 主体；打开候选时切换到完整区域。Rust 为此维护紧凑边界、表面边界、窗口模式和动态交互边界，前端还需协调 autocomplete、窗口模式命令和关闭时机。

主窗口已经具备完整事项选择与开始计时能力，托盘原生右键菜单也已有打开工作台、开始无事项计时、暂停、继续、结束、查看今日、检查更新和退出等入口。因此悬浮面板不需要继续复制事项工作台。

## Goals / Non-Goals

**Goals:**

- 将悬浮面板恢复为固定紧凑窗口，删除事项选择所需的扩展表面和模式切换。
- 复用现有计时、未归属时间和今日汇总状态，不引入新的业务数据源。
- 让所有需要选事项、编辑或确认的流程进入主窗口，并支持明确定位。
- 保留已验证的悬停显示、三秒移出关闭和外部点击关闭。

**Non-Goals:**

- 不从托盘悬浮面板创建、搜索、筛选或修改事项。
- 不在悬浮面板内实现时间拆分、多事项分配或同步冲突处理。
- 不移除系统托盘图标或原生右键菜单。
- 不改变计时和未归属时间的业务语义或持久化结构。

## Decisions

### 1. 悬浮窗口恢复单一固定尺寸

Rust 只计算并设置紧凑窗口边界，窗口显示期间不再维护完整候选表面、原生区域裁剪或 `Compact/TaskSelection` 模式。`HoverState` 只保留托盘边界、实际窗口边界、显示 generation 和关闭监控所需状态。

这会删除 `window_expand_hover_for_task_selection`、`window_restore_hover_compact`、`set_hover_window_mode`、扩展定位函数和相关 Windows GDI 区域调用。固定窗口边界直接作为三秒移出与外部点击的唯一面板区域。

备选方案是保留大表面但永远只使用紧凑裁剪。它可以减少初期改动，却留下不再需要的 Windows 专用复杂度和回归风险，因此不采用。

### 2. 面板按活动计时状态切换有限动作

存在活动计时时，面板展示状态、时长和当前事项；运行状态提供暂停，暂停状态提供继续，两种状态都提供“结束并处理”。结束动作沿用现有停止业务，但随后显示主窗口并进入已有结束确认或处理流程。

没有活动计时时，面板展示未归属摘要、今日已记录和待归属时间，并提供“选择事项并开始”“处理未归属时间”和“打开主窗口”。不在悬浮面板保留“无事项开始计时”按钮；该能力若仍需要，可继续通过原生右键菜单使用。

备选方案是完全删除悬浮窗口，仅使用 tooltip 和右键菜单。它最简单，但会失去实时计时、未归属时间和今日摘要的可见性，因此本次保留简化面板。

### 3. 使用显式主窗口导航事件定位复杂流程

“选择事项并开始”调用新的或复用的主窗口导航命令：先隐藏悬浮面板，再显示主窗口并发出定位计时区域的事件。主窗口收到事件后切换到时间记录页面，并将焦点交给现有事项选择控件，但不自动选择或开始。

“处理未归属时间”继续复用 `window_open_main_unassigned` 和现有权威状态刷新。“结束并处理”复用停止计时后的主窗口确认流程，避免在托盘重复分配 UI。

备选方案是所有按钮只打开主窗口首页。它实现更少，但用户仍需二次寻找目标区域，因此采用显式定位事件。

### 4. 前端移除托盘事项选择依赖

`HoverPanel` 不再导入 `TaskSelectControl`，也不保存 `selectedTaskId`、`selectionExpanded` 或选择过渡 Promise。托盘专用 autocomplete 样式可以删除；通用 `TaskSelectControl` 仍供主窗口、未归属弹框和其他业务使用，不因本变更改变其通用行为。

`trayHoverCore` 保留单次刷新合并和空闲展示判定，删除仅为托盘选择有效性服务的 `reconcileTrayTaskSelection` 及对应测试。

### 5. 刷新与关闭监控沿用现有机制

面板首次挂载及每次 `tray-hover-shown` 后仍并行刷新工作台、计时和未归属状态；手动刷新保留加载和错误反馈。Rust 的指针监控继续以 25ms 读取指针和按钮状态，固定窗口边界使判断更直接。

## Risks / Trade-offs

- [用户不能从悬浮面板直接选择事项] → 提供明确的“选择事项并开始”按钮，并在主窗口自动定位到事项选择区域。
- [删除扩展模式时遗漏调用导致编译或运行残留] → 全仓搜索窗口模式命令、选择状态、扩展尺寸常量和 GDI 区域 API，并以构建和 Windows 实际交互验证清理完整性。
- [结束计时后的主窗口流程与现有确认逻辑竞态] → 复用现有 timer stopped 事件和确认入口，不创建第二套停止后导航状态。
- [固定窗口内容过多再次变拥挤] → 信息层级限定为一项主状态、一行事项或未归属摘要、一行今日统计和最多三个动作。
- [原生右键菜单与悬浮面板动作部分重复] → 允许重复的仅是高频单步控制；右键菜单继续承担无事项开始、检查更新和退出等系统级动作。

## Migration Plan

1. 先实现主窗口“选择事项并开始”定位事件，确保移除托盘选择前存在替代路径。
2. 简化 `HoverPanel` 的状态与动作，删除事项选择组件和扩展模式调用。
3. 将 Rust 悬浮窗口恢复为固定尺寸，清理扩展边界、裁剪和窗口模式代码。
4. 删除不再使用的服务接口、样式和测试分支，更新托盘面板测试。
5. 在实际 Windows 程序验证悬停显示、固定位置、暂停/继续、结束处理、主窗口定位、未归属入口、三秒关闭和外部点击关闭。

回滚时可恢复原有 `TaskSelectControl` 和窗口模式命令；本变更没有数据迁移，回滚不影响已有记录。
