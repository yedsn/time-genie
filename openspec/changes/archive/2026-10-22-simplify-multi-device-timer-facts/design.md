# Design

## Context

动机见 `proposal.md`，行为要求见 `specs/timer-fact-convergence/spec.md` 与 `specs/shared-unassigned-time-display/spec.md`。以下是实现方式必须面对的当前状态：

- 云端 `timegenie.apply_calendar_time_entry` 在写入普通事项计时前校验租约，未持有则返回 `LEASE_NOT_HELD`；客户端 `reconcile_timer_sync_context` 把它转成 `lease_wait` 恢复原因，队列因此停在等待状态。
- 客户端在推送计时操作前，若本机没有租约令牌，会调用当天新增的 `tracking_lease_takeover_for_timer_write` 抢占租约；抢占会打断另一台设备的在途写入，是当前 15 秒／281 秒这类真实冲突的来源之一。
- 云端已有唯一约束 `uq_time_entries_active`（每个工作空间最多一个活动计时）和 `uq_unassigned_active`，计时写入也在 advisory lock 与 `base_version` 校验下执行，并发安全不依赖租约。
- 客户端把计时状态收敛分为已确认、可压缩、真正冲突三类；`cloud_version` 超过本机最终版本且内容不同、或云端由另一台设备更新时，当前会直接落成用户冲突。
- 未归属时间的显示值在前端由“本机当前时间减去云端返回的绝对起点时间戳”得出（`store.ts` 的 `unassignedSeconds`），因此直接暴露各设备系统时钟偏差；同一份状态里后端已经返回权威 `elapsedSeconds`，但前端未使用。
- 事项计时的显示是时钟安全的一类：后端时长加“本机自拉取以来的经过时间”（`entryDurationSecondsAt`），不受绝对时钟偏差影响。
- 未归属时间的处理动作（分配、记为休息、丢弃）在云端已经是“先到生效”：会话已处理或版本不匹配时返回 `accepted:false` 与权威结果，客户端已具备回退败方本地结果的能力，缺的只是用户可见提示。

## Goals / Non-Goals

**Goals:**

- 让计时写入在任意已授权设备上即时被接受，不再存在用户可见的写入资格等待。
- 用“先到云端事实生效”的确定性规则替代计时类操作的次生冲突，同时保证被取代的一方本地数据与云端一致。
- 让计时与未归属时间的显示值在不同设备系统时钟存在偏差时仍然一致。

**Non-Goals:**

- 不移除内部计时租约本身，也不改动未归属时间的跨日边界协调机制。
- 不改变事项计时按日切片、连续性中断分段、结算分钟与工时分配的业务语义。
- 不为非计时对象（事项、报告、重复规则等）改变冲突模型。
- 不引入 CRDT、事件溯源表或服务器权威时钟驱动的实时计时服务器。

## Decisions

### 1. 计时写入取消写入权门槛

服务端 `apply_calendar_time_entry` 不再校验租约，任何已授权且已注册的设备提交的计时事实都直接进入既有的并发校验路径（`uq_time_entries_active` 唯一约束、`pg_advisory_xact_lock`、`base_version` 校验、幂等 `processed_operations`）。客户端移除推送前的抢占调用与 `lease_wait` 恢复原因。

备选方案是保留租约并只允许显式操作抢占（即当前已部署的临时补丁）。它治好了无限等待，却让两台设备都写出自己的事实，把“等待冲突”换成“数据冲突”，没有解决根因；另一种是把云端做成唯一计时状态机，那会牺牲离线计时与本地优先交互。

### 2. 计时类操作采用“先到云端的事实生效”

服务端语义基本不变：已有事实时后到的写入得到权威快照而不是覆盖它。改动集中在客户端分类：对计时类操作（`timer_start`、`timer_pause`、`timer_resume`、`timer_stop`、连续性关闭、跨日切片），当云端事实无法由本机队列解释时，判定为“跟随”而不是“冲突”——删除本机该实体及其依赖操作、采用权威计时镜像、刷新相关域，并发出一次跟随提示。只有非计时对象，或云端连权威镜像都无法提供时，才继续进入既有的用户冲突流程。

判定按意图而不是按版本：结束类意图遇到云端已结束即跟随；开始类意图遇到云端已存在活动计时即跟随并放弃本地新建；暂停／继续遇到云端已处于目标状态即视为已确认，遇到云端已发生竞争转换则跟随云端。

备选方案是“较早时间戳生效”。它需要云端改写已生成的时长、分段与分配，且结果依赖各设备时钟准确度，因此不采用。

### 3. 结束边界在服务端做上界收敛

“各端本地计算”意味着结束时刻由提出结束的设备给出。为避免某台设备时钟偏快直接变成虚高时长，服务端在接受结束事实时把边界收敛到 `[started_at, 服务端接收时刻]`，并用收敛后的边界计算时长、切片与新的未归属起点。离线停止在联网后提交时，服务端接收时刻晚于点按时刻，收敛不会生效；只有客户端时钟超前时上界才会生效。

备选方案是完全信任客户端时间戳，代价是任意一台设备时钟不准都会写进最终工时；另一种是完全使用服务端时间，会把离线停止记录成同步时刻，损失真实结束时间。

残留风险是设备时钟偏慢导致时长短于实际，服务端无法识别，仍由既有的“修正实际用时”流程兜底。

### 4. 跟随结果通过一次性事件提示用户

同步工作线程在判定跟随时发出一个专用事件（携带实体类型、实体 ID、被跟随的版本与时间），主窗口监听后显示一条可自动消失的提示，并提供跳转到该时间记录的入口。提示文案只说明“已在另一台设备保存，已跟随该结果”，不额外查询设备名，避免多一次网络往返。窗口未打开时提示被丢弃，同步结果本身不受影响。

备选方案是把提示做成需要用户确认的对话框，或写进冲突列表；前者打断操作，后者把自动收敛重新变成待办事项，都与本变更的目标相反。

### 5. 未归属显示改为“权威时长 + 本地增量”

前端不再用绝对起点时间戳推算显示值，改为复用事项计时已经验证过的模式：以最近一次拉取的权威未归属时长为基准，按本机自拉取以来的经过时间逐秒推进，阈值判断与处理分钟展示都基于同一数值。后端已经返回 `elapsedSeconds`，因此不需要新增 RPC 或时钟偏移子系统。

备选方案是引入服务端时钟偏移估算并用它校正绝对时间戳。它对未归属显示是更重的方案，也解决不了“设备离线期间无法重新采样偏移”的场景；本决策只要求各设备显示一致，不需要绝对时间语义。

### 6. 租约职责收窄并保留兼容层

租约继续服务于未归属时间的跨日边界协调，但不再参与任何用户可见的计时写入。`timer_write_lease_context` 与租约获取返回中的 `authoritativeTimer` 不再参与计时路径；`tracking_lease_takeover_for_timer_write` 先降级为无副作用的兼容实现以兼容仍未升级的客户端，客户端版本发布后再删除。

备选方案是立即删除租约与相关 RPC。那会让未升级客户端直接报错，并迫使跨日协调改为完全依赖 advisory lock，扩大本次变更范围。

### 7. 历史计时冲突一次性重分类

升级前遗留的计时类冲突（如本机 `timer_stop` 的 `competing_edit`）按新规则重新判定：重扫计时类冲突项，取得云端权威镜像后按第 2 条收敛，连带处理其依赖操作。重扫只作用于计时实体，不触碰其他类型的冲突，且可重复执行。

## Risks / Trade-offs

- [用户操作被静默取代] → 跟随必然产生一条轻提示，并保留跳转到记录与修正实际用时的入口；被取代的只是计时事实，且规则是先到者生效。
- [提示被忽略或窗口未打开] → 提示可安全丢弃；权威结果会出现在时间记录里，用户仍可事后修正。
- [设备时钟偏慢导致时长偏短] → 服务端无法检测，依赖用户修正实际用时兜底；这是本地计算模型的固有代价，记录在案。
- [取消门槛后并发写入增多] → 并发安全由唯一约束、advisory lock 与版本校验保证，不依赖租约；需要补充并发开始与重复结束的回归测试。
- [旧客户端仍会抢占租约] → 服务端先部署兼容层，让抢占调用成为无副作用成功，客户端发布后再删除入口，避免升级窗口期报错。
- [显示基准切换造成阈值提示跳变] → 仅允许一次性小于一秒的校正，并让阈值判断与显示共用同一基准。
- [跟随提示可能掩盖真实竞争] → 仅计时事实走跟随；事项、报告等对象仍进入用户冲突流程。

## Migration Plan

1. 部署服务端兼容补丁：计时写入不再校验租约；`tracking_lease_takeover_for_timer_write` 保留但变为无副作用兼容实现；结束边界上界收敛生效；`supabase/schema_integration_test.sql` 与 `scripts/verify-supabase-schema.mjs` 同步验证权限与幂等性。
2. 发布客户端：移除抢占与 `lease_wait`，接入跟随判定、跟随事件与历史冲突重分类，并切换未归属显示基准。
3. 客户端覆盖率确认后，删除兼容性质的抢占 RPC 与 `timer_write_lease_context`。
4. 回滚策略：服务端保留兼容层期间，旧客户端可继续工作；客户端回滚只需恢复抢占调用与等待状态。若已执行第 3 步，回滚需重新部署旧版服务端补丁。
