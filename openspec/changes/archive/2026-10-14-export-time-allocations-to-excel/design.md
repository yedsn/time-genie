# Design

## Context

见 `proposal.md` 和 `specs/time-allocation-export/spec.md`。计时页面已经通过本地 SQLite 历史查询展示全部正式时间记录；`time_entries` 保存工作日期、原始时间段、来源、类型和备注，`time_allocations` 保存事项、分钟及归属备注，事项可关联主体。云端模式的权威快照与增量也会落入同一 SQLite 缓存，因此导出不需要网络接口。

应用已经初始化 `tauri-plugin-dialog`，但当前 capability 未授予保存对话框权限，前端也未安装该插件的 JavaScript 包。为了避免把大量业务行传到前端并在 WebView 里生成二进制文件，设计选择由 Rust 完成查询、行展开、Excel 构建和写入。

## Goals / Non-Goals

**Goals:**

- 用统一的后端行生成器支撑预览统计与实际 Excel，避免两套计算规则。
- 正确展开事项归属、剩余未归属分钟和休息特殊行，并保持分钟合计无重复。
- 使用工作空间日期和时区格式化日期、时间段及运行中快照。
- 对大日期范围保持前台可响应，并保证读取和文件生成不会进入同步状态。

**Non-Goals:**

- 不增加 CSV、PDF、多个工作表、主体筛选、事项筛选或自定义列模板。
- 不导出完整原始数据库、计时分段、同步元数据、版本信息或敏感配置。
- 不把 Excel 上传到 Supabase，也不保存导出历史记录。
- 不修改时间记录、归属、事项或云端 schema。

## Decisions

### 1. 使用预览命令和执行命令，共享同一个行生成器

新增日期范围请求：

```text
start_date
end_date
include_special_time
```

后端提供只读预览，返回 `row_count`、`total_minutes` 和默认文件名；执行命令额外接收目标路径，重新从同一事务快照构建行、生成 Excel 并返回实际统计。预览不缓存完整行，执行时重新读取，以实际文件生成时的数据为准。

备选方案是在前端根据历史分页逐页收集数据。该方案受每页 7 天限制、会产生多次调用，并且事项主体信息不完整，因此不采用。预览后缓存完整导出 payload 也可能在记录变化后写出陈旧内容，因此不采用。

### 2. 先批量查询扁平来源，再确定性展开导出行

后端按 `time_entries.work_date BETWEEN start_date AND end_date` 一次查询未删除记录，联结正分钟 allocations、tasks 和 subjects，并批量加载生成时间段和层级事项路径所需信息。行按工作日期升序、开始时间升序、记录 ID、归属创建顺序稳定排序。

每条工作记录的行生成规则：

1. 为每条正分钟 allocation 生成具体事项行；主体取事项所属主体，事项显示完整层级路径。
2. 若开启特殊时间，计算 `max(0, settlement_minutes - sum(positive allocation minutes))`，正数时生成一条“未归属”行。
3. 若记录类型是休息，仅在开启特殊时间时生成一条“休息”行，分钟取该记录结算分钟。
4. 删除/无效记录在 SQL 层排除；零分钟行不生成。

若异常旧数据的正归属合计超过结算分钟，具体事项归属仍按实际保存分钟导出，但未归属剩余截断为零，避免产生负数特殊行。

### 3. Excel 固定为一个结构化“工时归属”工作表

采用 Rust Excel 写入库（优先 `rust_xlsxwriter`）生成文件，列固定为：

```text
工作日期 | 主体 | 事项 | 用时（分钟） | 时间段 | 备注
```

首行使用标题样式、自动筛选和冻结；日期、分钟使用合适的 Excel 类型，文本列设置可读列宽与自动换行。数据末尾增加“合计”行，分钟公式或静态值必须等于实际数据行分钟之和。工作簿只有一个工作表，不创建隐藏元数据页。

备选方案是在前端使用 SheetJS。该方案需要把导出数据和二进制生成都放进 WebView、增加较大的前端包，并扩大敏感数据进入前端状态的范围，因此不采用。

### 4. 时间段按工作空间时区格式化，运行中记录使用单次快照时刻

后端在每次预览或执行开始时只捕获一次 `snapshot_at`，使用工作空间时区格式化 `HH:mm-HH:mm`。已结束记录使用保存的开始与结束；运行中记录以 `snapshot_at` 作为显示结束点并按现有 `load_entry` 规则计算有效时长；暂停记录使用最后有效结束边界或累计时长，不把暂停等待时间计入。运行中或暂停记录没有具体事项正归属时，只有开启特殊时间才生成未归属行，并在备注中标明状态。

对于跨日计时，数据库已经按 `work_date` 生成日期切片，导出直接使用每个切片，不重新合并整条计时链。

### 5. 备注合并采用稳定、可辨识的文本规则

事项归属行按存在性合并：

```text
计时：<时间记录备注>；归属：<allocation 备注>
```

缺失的一部分省略，不产生空标签。未归属和休息行保留计时备注，并追加“未归属”“休息”“进行中”或“已暂停”等必要标识。导出不包含内部 UUID、版本、设备 ID 或同步状态。

### 6. 保存对话框由前端打开，文件内容由后端写入

前端安装 `@tauri-apps/plugin-dialog`，capability 增加 `dialog:allow-save`，使用过滤器限制为 `.xlsx` 并传入后端给出的默认文件名。选择路径后调用执行命令。用户取消时前端直接结束，不调用写入命令。

备选方案是让 Rust 命令内部打开对话框。前端需要区分取消、预览、写入和错误状态，直接由前端编排更清晰，也便于保留弹框输入。

### 7. 导出弹框采用请求序号防止旧预览覆盖新条件

弹框打开时根据 `workspaceToday` 计算当前月首末日，默认关闭特殊时间。日期或开关变化后执行轻量防抖预览；每次请求带前端请求序号，仅最新结果可以更新行数与合计。导出期间禁用重复提交，但不阻塞计时器刷新和后台同步。

当预览行数为零时禁用导出按钮并展示明确说明。写入失败时保留日期范围与选项，成功后可关闭弹框并展示实际保存路径、行数和分钟。

## Risks / Trade-offs

- [超大日期范围生成文件耗时] → 查询只读取需要字段并批量联结；Excel 在 Tauri 异步命令中生成，前端显示导出中且计时显示继续刷新。
- [预览与执行之间数据变化] → 执行命令重新生成并返回实际统计，成功提示使用实际值。
- [事项或主体已删除] → LEFT JOIN 并使用“已删除事项”“已删除主体”等快照式回退文本，不丢失仍有效的历史 allocation。
- [目标文件被 Excel 占用] → 捕获写入错误并提示重新选择路径，不覆盖或删除原文件。
- [运行中时长每次预览变化] → 单次请求固定 `snapshot_at`，预览和执行分别视为各自一致的快照。
- [旧数据归属分钟超过记录分钟] → 具体归属保持事实值，特殊未归属分钟最小为零，统计仍严格等于导出行。
- [云端缓存尚未收到最新远端记录] → 文件明确反映当前本地权威缓存；导出不等待网络，以保持离线可用和前台响应。

## Migration Plan

1. 增加 Excel 依赖、导出行模型、范围查询、预览与工作簿生成测试。
2. 注册 Tauri 命令，增加保存对话框前端包和 capability 权限。
3. 在计时页面接入导出弹框、默认月份、预览和另存为流程。
4. 验证本地与云端离线缓存、运行中记录、大日期范围、文件占用和取消路径。
5. 发布不需要数据库或 Supabase 迁移；回滚客户端不会影响任何业务数据，已导出的 Excel 保持普通本地文件。
