# Proposal

## Why

当前云端模式同时由前端定时器、Rust 后台轮询和 Supabase Realtime 触发同步；任一云端变化还可能导致完整快照替换和前端全量重载，造成定时同步期间界面卡顿。需要改为事件驱动的近实时同步，让本地操作立即在后台上传、远端操作由 Socket 通知后增量落地，并把手动同步收敛为异常恢复入口。

## What Changes

- 移除前端和 Rust 后台对业务数据的固定周期上传、拉取；本地写入成功后立即唤醒后台上传队列。
- 使用 Supabase Realtime Socket 接收远端变更通知，并按云端变更序号拉取、应用缺失的增量数据。
- 应用启动、云端登录成功和 Socket 重连成功后执行一次增量补齐，弥补断线、休眠或进程未运行期间错过的通知。
- 保留 Socket 心跳、断线重连退避、计时设备租约续期和临时错误自动重试；这些机制不得触发无变化的完整业务数据同步。
- 将本地唤醒、Realtime 通知、重连补齐和手动重试统一交给单一后台同步协调器，合并重复信号并保证同一时间只运行一个同步任务。
- 以实体增量更新本地缓存，避免单条变化触发完整快照清空重建；首次初始化、显式重置或不兼容迁移仍可使用完整快照。
- 增量范围覆盖普通事项、按日预估、重复规则、每日重复事项轮次、主体、工时、报告和工作空间设置，并保持本地未同步修改及现有冲突保护。
- 同步完成后仅通知前端刷新实际受影响的领域，并合并短时间内重复通知，避免工作区、工时和报告的无条件全量重载。
- 正常状态只显示实时同步状态；手动操作仅在持续错误、待同步积压、认证异常或冲突时用于重试或处理，不再作为日常刷新手段。
- 所有网络、JSON 处理和可能阻塞的 SQLite 同步工作在专用后台执行环境中完成，不占用窗口事件和异步运行时工作线程。

## Capabilities

### New Capabilities

- `event-driven-cloud-sync`: 定义云端模式下本地事件即时上传、Realtime 远端通知、断线增量补齐、实体级落地、后台隔离、精准前端刷新和异常手动恢复的行为。

### Modified Capabilities

无。当前主规格目录尚无已归档能力；按日预估和重复事项的业务对齐由 `align-cloud-task-planning-features` 变更定义，本变更只补充其事件驱动同步与无阻塞交付约束。

## Impact

- Rust：`src-tauri/src/cloud_sync.rs` 需要重构后台调度、Realtime 消费、增量拉取和实体应用；同步命令需避免在 async worker 中直接执行阻塞 HTTP 或长 SQLite 事务。
- Supabase：`workspace_changes` 及相关 RPC 需要为每种同步实体提供足以获取实体最新状态或删除语义的增量契约；Realtime publication 和 RLS 权限继续作为远端通知边界。
- Vue：`src-ui/src/views/MainWorkbench.vue` 移除 15 秒自动完整同步；`src-ui/src/App.vue` 按变化领域刷新；同步按钮和提示改为异常恢复语义。
- 数据库：日常远端变化采用短事务按实体写入，完整快照仅保留给初始化、显式重置和迁移恢复。
- 兼容性：本地模式不建立云端连接；云端现有 outbox、幂等操作、版本冲突、认证和设备撤销规则继续有效。
- 验证：需要覆盖慢网、断网恢复、Socket 重连漏消息补齐、多信号合并、前台延迟、按日预估与重复事项跨设备传播，以及完整快照不再进入日常同步路径。
