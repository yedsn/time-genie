## Context

事项完成目前由 Vue 组件发出 `toggle` 事件，store 调用 Tauri 完成接口后重新加载工作区数据。全部待办和今日事项分别由 `PlanListEditor.vue` 与 `TaskTable.vue` 提供完成入口，完成后事项可能从当前未完成列表消失并进入已完成区域。现有样式包含少量 hover 和状态闪烁，但没有完成专属反馈，也没有统一区分“完成成功”“恢复未完成”和“请求失败”的前端结果。

本变更需要跨组件协调异步成功结果、列表重排和全清判定，并引入一个轻量粒子依赖。事项状态语义、Tauri 命令和持久化结构保持不变。行为要求见 `specs/task-completion-feedback/spec.md`。

## Goals / Non-Goals

**Goals:**

- 在后端确认成功后，为所有主动完成入口提供一致的完成反馈。
- 将庆祝反馈统一固定在屏幕顶部通知区域，避免效果随鼠标位置漂移，同时不让 DOM 元素引用穿过 store 层。
- 统一普通完成、批量完成和当前视图全部完成的强度判定。
- 让列表重排与庆祝编排互不阻塞，并支持应用内开关和效果降级。
- 将粒子和音效实现封装在单一前端模块中，避免组件直接依赖第三方或浏览器媒体 API。

**Non-Goals:**

- 不新增积分、等级、连续完成天数、震动或成就系统。
- 不自动完成父事项，也不改变完成、恢复、同步和报告业务规则。
- 不为应用内所有状态变化建立通用动画框架。
- 不引入远程 Lottie 素材、WebGL 粒子引擎或长期运行的环境动画。

## Decisions

### 1. 完成操作返回结构化结果，由界面触发反馈

将 store 的完成方法从仅返回 `Promise<void>` 调整为返回结构化结果，例如完成方向、成功状态、完成数量和刷新后的视图统计。组件或页面在成功结果返回后将结果传给统一反馈服务，不采集或传递鼠标坐标。

这样可以确保庆祝发生在服务端确认之后，同时避免把 DOM 元素、鼠标事件或坐标存入 Pinia。失败继续由现有错误处理链路处理，反馈服务不会被调用。

备选方案：在 store 内直接触发粒子。该方案会使状态层依赖 DOM、视口坐标和动画库，难以测试与复用，因此不采用。

### 2. 使用独立的完成反馈编排器

新增前端完成反馈模块，接收以下最小上下文：

- 本次完成事项数量；
- 操作前后的当前视图未完成数量；
- 应用内激励动画是否启用。

编排器负责选择 `normal` 或 `all-clear` 模式、读取应用内激励动画和音效开关、限制并发、合并短时间内的反馈，并调用粒子与音效适配器。组件只负责在开关启用时给当前事项行短暂添加状态类，避免各入口分别复制庆祝参数。

备选方案：每个组件自行实现动画。该方案容易导致今日事项和全部待办的反馈不一致，也难以统一限流与无障碍行为，因此不采用。

### 3. 使用 `canvas-confetti` 实现顶部通知区域粒子

普通完成从屏幕左右底部向上方中间的庆祝卡片方向同时发射两段粒子，发射起点固定在底部区域，角度、速度、扩散范围、大小和数量在受控区间内随机变化。全部完成使用更宽的里程碑卡片，并从左右底部发射三段更密集、上升距离更长的随机粒子。颜色沿用当前界面的绿色、薄荷色、暖黄色、白色和低饱和蓝色；粒子混合内置方片、圆片、星片，以及风筝碎片、飘带、闪电和爱心等自定义路径形状。发射点不随鼠标位置变化，所有效果保持短时、非阻塞和不捕获指针事件。

自定义路径通过 `confetti.shapeFromPath` 创建，并显式提供预计算变换矩阵；形状对象在首次使用时创建一次并缓存，后续完成操作直接复用，避免运行时重复扫描路径边界。若浏览器不支持路径碎片，则自动降级为内置方片、圆片和星片。

依赖通过适配器延迟加载或在调用边界捕获异常；粒子失败不得传播到完成业务。所有粒子使用单一固定层，避免每次完成创建长期存活的 canvas。

备选方案：

- 纯 CSS 粒子：无需依赖，但随机轨迹、清理和跨入口复用成本较高。
- `@tsparticles/confetti`：效果丰富，但当前场景所需能力有限，体积与模块数量过重。
- Lottie：适合固定插画或奖杯动画，但当前仍需额外维护素材，且粒子喷发的灵活度较低。

### 4. 列表反馈使用 Vue 过渡与 CSS 状态类

待办列表使用 Vue 的列表过渡能力或等价的 FLIP 过渡处理事项移除与剩余行补位。完成行在数据刷新前保留一个短暂的确认状态，播放对勾缩放、绿色背景闪过和内容淡出；刷新后由列表过渡完成位置变化。已完成计数在增加时播放一次轻微缩放。

动画优先使用 `transform` 和 `opacity`，避免逐帧修改高度、位置或其他会引起频繁布局的属性。反馈层设置 `pointer-events: none`，不改变键盘焦点规则。

备选方案：先乐观地移动事项，再回滚失败。虽然响应更快，但会在失败时产生“先庆祝后撤销”的错误反馈，因此不采用。

### 5. 全部完成基于用户操作前后的当前视图快照判定

调用完成操作前记录当前视图未完成事项数量；成功刷新后读取相同视图范围的新数量。只有从大于零变为零，且本次操作确实产生未完成到完成转换时，才触发全部完成模式。切换页面、主体、过滤条件或同步刷新导致的空列表不触发庆祝。

对于工时分配等一次完成多个事项的入口，由调用方提供本次成功完成数量和相关视图上下文；若没有明确可见视图，则播放一次合并普通庆祝，不虚构“当前页面全部完成”。

### 6. 使用设备级应用设置控制激励动画

设置读取设备级 `completion_feedback_enabled`，缺省为 `true`。用户切换开关后立即更新运行时反馈状态，保存设置时持久化。关闭时停止当前粒子与提示，并使后续完成操作不添加任何激励动画状态。

此设置不读取 `prefers-reduced-motion`，也不向 `canvas-confetti` 传入系统减少动态效果禁用选项，因此 Windows 动画配置不会覆盖应用选择。

### 7. 使用 Howler.js 播放本地成功音效

将用户选定的 `mixkit-correct-answer-tone-2870.wav` 复制为前端本地资源 `src-ui/src/assets/audio/completion-success.wav`，由 Howler.js 在首次需要时创建单一 `Howl` 实例并预加载。普通完成和全部完成均保持音效原始速度，普通完成使用略低音量，全部完成使用较高音量。每次播放前停止上一次声音，音效与粒子共用完成模式和限流判断，连续快速完成不会产生密集重叠的声音。资源随应用离线打包，不依赖网络请求或用户下载目录。

设备级 `completion_feedback_sound_enabled` 缺省为 `true`，可在设置页独立关闭。关闭音效不会关闭卡片、粒子或列表动画；关闭激励动画时视觉反馈停止，音效入口也不会因完成反馈模式为 `none` 而播放。Howler 加载、解码或播放失败时由反馈调用边界捕获并静默降级，不影响事项完成与视觉反馈；应用卸载反馈服务时停止声音并释放音频资源。

## Risks / Trade-offs

- [不同入口的完成控件位置不同导致反馈漂移] → 统一使用屏幕顶部通知区域作为视觉锚点，不采集鼠标或控件坐标。
- [刷新耗时使反馈显得延迟] → 完成控件进入非庆祝的提交中状态，后端成功后立即播放确认；不使用错误的乐观庆祝。
- [连续完成造成粒子堆积] → 编排器对普通反馈限流并复用 canvas；短窗口内的批量结果合并，全部完成模式覆盖普通模式。
- [列表移除过快看不到行反馈] → 成功后先设置短暂本地反馈状态，再执行或呈现列表重排；总延迟保持短促，且不阻塞其他操作。
- [第三方粒子依赖异常] → 通过适配器隔离并捕获错误，业务完成和 CSS 状态确认继续正常工作。
- [浏览器阻止自动播放或音频 API 不可用] → 在用户交互后恢复音频上下文并捕获异常，保留完整视觉反馈和业务结果。
- [全清判定受过滤条件影响] → 将文案和判定限定为“当前视图全部完成”，不宣称主体或所有事项全部完成。
- [动画影响低性能设备] → 控制粒子数量和持续时间，只使用 transform/opacity，并允许用户在应用设置中完全关闭激励动画。

## Migration Plan

1. 安装并封装 `canvas-confetti`，先提供不会影响现有完成流程的反馈服务。
2. 调整 store 完成方法的返回结果，保持现有调用方可以等待完成并获得刷新后的状态。
3. 依次接入全部待办、今日事项和多事项完成入口，并加入列表状态过渡。
4. 补充应用内开关和依赖异常降级验证，再运行类型检查与生产构建。
5. 若需要回滚，可移除反馈调用与依赖，恢复原完成方法返回类型；事项接口和数据无需迁移或回滚。
