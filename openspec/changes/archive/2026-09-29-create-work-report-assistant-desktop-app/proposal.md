## Why

当前工作日报流程依赖多个 Python 脚本、Obsidian 文件和 SeaTable 操作。计划需要从前一天复制并重新整理，工时需要手动记录和换算，日报、周报和同步又分散在不同入口，导致每天需要重复执行多个步骤，也无法自然记录“先粗略计时、最后再手动拆分归属”的真实工作方式。

现在需要一个 Windows 桌面工作台，将计划整理、独立计时、工时结算、日报/周报生成和外部同步集中到一个可持续使用的入口，同时保留 Obsidian Markdown 归档和 SeaTable 事项管理能力。

## What Changes

- 新增一个 Windows 桌面工作台，支持主窗口和系统托盘快速操作。
- 从前一天的 Obsidian 日报中提取明日计划，生成当天的候选计划列表。
- 支持在桌面工具中编辑、删除、排序、拆分和新增今日计划事项。
- 新增独立的工作计时器；开始计时时可以选择一个默认事项，但不强制绑定最终工时归属。
- 支持计时暂停、继续、结束、手动补录、修改时间和添加备注。
- 新增原始计时记录与工时分配记录，允许一段原始工时拆分到多个事项。
- 在日报生成前显示原始工时、已分配工时和待结算工时，并校验分配总量。
- 根据最终结算结果生成 Obsidian 日报和给上司使用的分钟级日报文本。
- 根据已结算日报生成周报，并继续支持工资和 SeaTable 待报销数据汇总。
- 支持将今日计划、事项状态和最终工时同步到 SeaTable，并将日报/周报写回 Obsidian。
- 将本地工作数据保存为结构化数据，避免把 Markdown 解析作为唯一业务数据源。

## Capabilities

### New Capabilities

- `daily-workbench`: 管理每日计划、事项编辑、事项状态和今日工作台展示。
- `time-tracking-and-allocation`: 记录独立原始时间片，并支持默认事项、暂停继续、手动修正和跨事项工时分配。
- `report-generation`: 根据已结算事项生成 Obsidian 日报、上报版日报和周报。
- `external-sync`: 与 Obsidian Markdown 文件和 SeaTable 事项/报销数据进行可控同步。

## Impact

- 新增 Windows 桌面应用及其本地数据层，预计使用 Tauri、Vue 和 SQLite。
- 新增系统托盘窗口、主窗口、可能的全局快捷键和 Windows 开机启动配置。
- 需要读取和写入用户配置的 Obsidian 日报目录，并兼容现有 Markdown 结构。
- 需要复用或重构现有 Python 脚本中的日报、周报和 SeaTable 业务规则。
- 需要保存 SeaTable 服务地址、Base API Token 等配置；敏感配置不得写入导出的普通数据文件。
- 第一阶段以单用户、本地优先为目标，不引入多人协作和云端主数据库。
