# Proposal

## Why

当前统一计时事项弹框已经能浏览、轻量编辑并开始事项，但用户在实际执行过程中还需要频繁调整今日实际、整理事项顺序、处理未归属时间和重新分配今天的时间记录；这些能力分散在多个弹框和输入式选择器中，仍然需要来回切换上下文。需要把现有计时弹框扩展为可复用的“执行事项”面板，让事项维护、执行计时和今天的时间归属使用同一套高密度事项树与交互。

## What Changes

- 将空闲入口命名为“开始执行事项”、活动计时入口命名为“切换执行事项”，共享面板标题统一为“执行事项”。
- 执行模式同时展示全部进行中事项和今天完成的事项，不按状态重新分组，严格保持待办页原有父子结构与排序；更早完成的历史事项不混入。
- 面板中的今日预计只用于只读参考，不提供输入或自动保存；预计时间统一回到待办页分配和调整，新建事项也不在执行面板中填写预计。
- 在面板中将今日实际升级为可操作字段：点击已确认实际打开紧凑浮层，按目标分钟保存单事项正负调整；当前活动计时本段单独实时展示且不提前计入已确认实际。
- 今天完成的叶子事项提供“继续”动作，原子完成重新打开事项并开始或切换计时，失败时不得留下只重新打开或只切换一半的状态。
- 面板支持与待办页一致的拖动排序、整组移动和一级/二级层级调整；搜索状态下禁用拖动，避免对隐藏事项产生歧义。
- 移除待办页独立的“调整今日实际”入口，将相应能力并入执行事项面板；完整批量管理和历史完成事项浏览仍保留在待办页。
- 将未归属时间处理改为共享面板的时间分配模式，直接在完整事项树中向一个或多个叶子事项分配分钟，并保留记为休息、丢弃、新增及轻量事项编辑，不再嵌套输入式事项选择器。
- 将今天时间记录的归属或重新分配接入同一时间分配模式；分配模式不提供开始/切换计时，也不允许在归属保存前同时调整实际，避免重复计入分钟。
- **BREAKING**：昨天及更早的时间记录全部只读，不再允许调整归属、修改起止时间或备注、删除记录、撤销历史实际调整；若编辑期间工作日期变化，保存请求必须被拒绝并刷新权威状态。

## Capabilities

### New Capabilities

- `execution-task-panel`: 定义可复用的执行事项面板及其执行、未归属分配和今天时间记录归属三种模式，包括原顺序展示、今日实际单项调整、已完成事项继续、拖动排序和历史记录只读边界。

### Modified Capabilities

无。项目当前没有已归档主规格，本变更以新能力统一描述现有计时弹框、实际调整、未归属处理和时间记录编辑的扩展行为。

## Impact

- 前端共享面板：扩展 `TimerTaskDialog.vue` 或重命名为更通用的执行事项面板，抽取模式化列、动作和底部提交区。
- 前端入口：调整 `GlobalTimerBar.vue`、`TimeTrackingWorkspace.vue`、`TodayOverviewWorkspace.vue`、`PlanListEditor.vue`、`UnassignedTimeDialog.vue` 与 `MainWorkbench.vue` 的名称和打开方式。
- 事项树与拖动：复用 `PlanListEditor.vue`、`planTaskInteractionCore.ts` 和 store 现有排序/层级移动能力，避免维护第二套规则。
- 今日实际：复用 `actual_time_adjustments`、快照和批量调整领域语义，补充面向单事项的提交协调与并发保护，不修改原始计时记录。
- 计时领域：为已完成事项“继续”增加重新打开与计时转换的原子或等价幂等边界，并保持唯一活动计时及未归属直接丢弃语义。
- 时间归属：共享未归属和今天时间记录的高密度分配编辑器，继续复用现有分配、休息、丢弃和记录归属命令。
- 历史只读：前端隐藏非今日编辑入口，后端命令同步校验工作日期，不能只依赖界面限制。
- 云同步与验证：排序、实际调整、继续计时和时间归属继续接入现有本地优先/outbox 语义，并补充本地、云端、跨窗口、窄窗口、键盘和主题验收。
