# Design

## Context

见 `proposal.md` 与 `specs/execution-task-panel/spec.md`。当前 `TimerTaskDialog.vue` 已提供按主体浏览、名称和备注自动保存、今日预计只读参考、更多、新增及开始/切换；`PlanListEditor.vue` 独立提供完整树形拖动、预计分配和批量“调整今日实际”；`UnassignedTimeDialog.vue` 与 `TimeTrackingWorkspace.vue` 的归属编辑则分别嵌套多个 `TaskSelectControl`。这些界面读取相同事项数据，却各自维护列表、选择和保存草稿。

今日实际已经由独立 `actual_time_adjustments` 实体表达正负差额并统一进入计划、今日概览、报表、趋势和导出口径；时间归属已经支持多事项分配、完成事项、休息与丢弃；事项排序和最多两级规则也已有 store 与后端命令。设计应复用这些领域能力，而不是把现有大组件直接互相嵌套。

## Goals / Non-Goals

**Goals:**

- 用一个共享事项树外壳承载执行、未归属分配和今天记录分配三种模式。
- 让模式只配置列、主要动作和业务提交边界，事项浏览、编辑、新增、排序与焦点行为保持一致。
- 复用实际调整、时间分配和事项移动的现有领域模型，并补足单项调整、完成后继续和历史只读的服务端保障。
- 保持本地优先、幂等、版本冲突和云端唯一活动计时语义。

**Non-Goals:**

- 不把执行事项面板变成全部历史事项或全部时间记录的管理器。
- 不允许在时间分配未提交时同时修改已确认实际。
- 不改变未归属开始事项即丢弃、停止确认或原始计时记录不可篡改的语义。
- 不支持三级事项、任意树深度或搜索结果内的相对拖动。
- 不恢复非今天时间记录的任何写能力。

## Decisions

### 1. 抽取共享事项树外壳，用模式适配器提供业务动作

将现有计时事项弹框演进为通用执行事项面板，内部拆分为：主体/搜索工具栏、可排序事项树、共享行编辑、新建行、备注/更多浮层，以及模式专属的时间列、主要动作和底部区域。面板接收显式模式：

- `execute`：展示已确认实际、活动本段与开始/切换/继续。
- `unassigned-allocation`：展示未归属区间、剩余分钟和每行分配输入。
- `entry-allocation`：展示目标记录与现有/调整后归属。

模式适配器只负责初始化业务草稿、校验合计、提交或取消；事项名称、备注、更多、新增和拖动始终走共享能力。今日预计在三种模式中只显示权威值，不建立编辑草稿；新增事项也不填写预计，预计分配继续由待办页负责。这样避免把 `UnassignedTimeDialog` 或时间记录内联编辑器原样塞入弹框，也避免三个组件复制完整事项树。

备选方案是保留三个独立界面，只让它们都打开同一个事项选择弹框。该方案仍然产生两层交互和多个选择器实例，无法满足直接浏览整树、拖动和边看边分配，因此不采用。

### 2. 执行列表使用“进行中主树 + 今日完成补入”的稳定顺序模型

常规 workspace 事项列表只含进行中事项，而实际调整快照包含今天完成或今天有实际的事项。面板需要构建一个稳定模型：以待办排序键和父子关系为权威，合并进行中事项与今天完成事项；父事项在任一后代入选时作为上下文补入。完成状态只影响行样式和动作，不参与排序。

今天完成事项的版本、父级和排序信息必须来自权威查询，不能只凭历史时间记录反推。建议扩展现有执行面板快照或实际调整快照，返回当前主体所需的完整树、完成日期、今日预计、最终实际和活动状态。当前已分配但不在常规范围的事项由分配模式额外 pin 到原父级上下文或明确的“当前归属”区域，同时仍保持可搜索和可理解。

备选方案是在前端拼接已完成分页数据。它可能缺少父级、排序或只加载部分页面，无法保证原顺序，因此不采用。

### 3. 单项实际调整复用批量领域契约，不直接修改分钟

今日实际浮层以打开时的最终实际和调整指纹建立单行草稿，提交时仍使用现有调整批量命令的单项请求，携带事项版本、基线、目标、差额、指纹、备注和稳定请求 ID。成功后刷新执行快照；失败保留草稿。原始计时、分配和既有调整记录保持不可变。

活动本段仅来自当前计时状态并单独格式化，不进入调整基线。父项的已确认汇总沿用共享最终实际查询，活动提示只作为状态标记，不与汇总相加。

待办页原批量调整入口移除后，底层批量能力仍可保留供兼容、测试和未来批量入口使用；本变更只将主用户入口转为单项浮层。

### 4. 为完成事项“继续”增加组合计时转换目标

扩展统一计时转换请求，使目标可表达“重新打开已完成事项并开始/切换”。本地事务与云端原子 RPC 在同一个幂等操作中：

1. 校验目标是今天完成、可计时的叶子事项及其期望版本；
2. 校验当前活动计时 ID/版本；
3. 把事项状态恢复为进行中；
4. 在同一权威时间边界结束原活动项并开始目标项；
5. 原子处理未归属锚点、outbox、幂等结果与修订。

任何校验或写入失败整笔回滚。结果显式返回重新打开后的事项、原计时停止结果和新活动计时，供前端一次刷新。不能由前端先调用“重新打开”再调用 `transitionTimer`，否则第二步失败会留下半完成状态。

### 5. 拖动复用待办移动意图，组件共享而非复制 Sortable 编排

把 `PlanListEditor.vue` 中子树选择、目标深度判断、非法三级检测和 `planTaskMoveIntent` 编排提取为可复用 composable/组件。待办页和执行面板使用相同的拖动手柄、插件配置与 store `movePlanTask` 命令。

面板搜索词非空时销毁或禁用 Sortable，并显示解释文案。时间分配模式的分钟草稿使用事项 ID 作为稳定键；排序刷新只更新行顺序，不重建或清空草稿。移动成功后刷新权威树，冲突时恢复原顺序并保留业务草稿。

备选方案是在执行面板单独实现上下按钮或仅同级拖动。它与用户确认的完整待办拖动语义不一致，也会形成第二套规则，因此不采用。

### 6. 未归属与记录归属共享稀疏分钟草稿

时间分配模式为当前面板维护 `task_id -> minutes/complete_task` 的稀疏草稿，而不是渲染多个独立选择器。点击未选叶子的“分配”动作时，将当前剩余分钟填入；用户也可直接编辑为 0 到总分钟。已选事项跨主体标签或搜索时仍保留，并在摘要中可见。

未归属模式提交现有未归属处理请求；记录模式提交现有替换分配请求。两者共享合计、剩余/超出、完成事项开关和新增草稿持久化顺序，但保留不同的版本与处置参数。记为休息或丢弃只在未归属模式可用；记录模式针对现有记录保留其合法处置能力。

在任一分配草稿存在时，实际列只读。保存成功并刷新后，用户可从执行模式重新打开实际浮层，避免“分配增加实际”和“按旧基线产生调整”重复计入。

### 7. 历史只读必须由共享日期守卫覆盖所有写命令

抽取后端“目标工作日期必须等于 workspace 当前工作日期”的守卫，并应用于时间记录修正、分配替换、处置/删除以及实际调整删除等所有受影响写命令。请求需携带或从目标实体解析工作日期；事务开始后读取当前 workspace 日期，避免只在前端打开时判断。

前端按时间历史分组日期隐藏所有非今天动作，但后端仍是最终权威。如果面板打开后跨日，提交会收到稳定错误码；前端丢弃或保留只读快照、刷新历史并说明日期已变化。读取和导出历史不受影响。

### 8. 草稿关闭策略按字段类型区分

名称和备注继续逐项自动保存；今日预计只读展示且不产生草稿；拖动立即保存。实际目标与时间分配属于业务草稿，不在关闭时静默提交。关闭面板时若存在业务草稿，提示保存/继续编辑或放弃；切换主体时同样不得丢失当前模式草稿。

执行计时动作前只冲刷目标行的事项字段；实际草稿必须先明确确认或取消。分配模式没有计时动作，因此不会触发未归属直接丢弃。

### 9. 入口迁移保持一个面板实例与显式上下文

主工作台继续维护唯一共享面板实例和返回焦点元素，打开请求携带模式及上下文：主体、计时备注、未归属 session/version 或时间记录 ID/version。待办页原“调整今日实际”按钮移除，并新增/保留“执行事项”入口；顶部、今日和计时页面按状态显示“开始执行事项”或“切换执行事项”。

托盘和系统事件仍只请求打开执行模式，不切换页面。未归属弹框可退化为共享面板模式包装或被主工作台状态替代，但不能再包含 `TaskSelectControl`。时间记录内联编辑器改为只读摘要加“调整归属”入口，今天才可打开。

## Risks / Trade-offs

- [共享面板功能过多，信息密度失控] → 用显式模式只呈现当前业务需要的主要列和动作，低频字段继续留在备注/更多浮层。
- [进行中与完成事项来自不同查询，排序或版本不完整] → 由后端提供单一执行快照，按持久化排序键返回完整上下文，不依赖完成分页拼接。
- [单项实际调整与活动计时产生理解偏差] → 分开展示已确认实际和活动本段，浮层明确只调整前者。
- [继续操作跨事项与计时领域，云端实现复杂] → 使用单个幂等组合操作和事务/RPC，失败整笔回滚。
- [拖动刷新导致分钟或编辑草稿丢失] → 草稿以事项 ID 保存，视图顺序与业务草稿分离；冲突刷新后重挂到仍有效事项。
- [分配模式允许编辑事项造成版本冲突] → 事项字段逐项独立保存，分配提交重新校验目标事项；失败只阻断对应提交并保留分钟草稿。
- [历史只读属于 BREAKING 行为，用户失去纠错入口] → 在时间记录中明确标记“历史记录只读”，发布前迁移文案与文档；今天仍保留完整修正能力。
- [跨日边界导致已打开面板突然不可保存] → 后端日期守卫拒绝旧日提交，前端刷新并清楚提示，不尝试自动迁移草稿到今天。

## Migration Plan

1. 先抽取共享事项树、拖动协调和模式无关的行编辑能力，保持现有执行模式行为不变。
2. 增加执行快照、单项实际调整协调、完成事项原子继续和历史日期写入守卫，并补齐本地/云端测试。
3. 接入未归属和今天记录的分配模式，替换嵌套 `TaskSelectControl` 与时间记录内联编辑。
4. 开放完整拖动、迁移入口文案、移除独立实际调整入口，并完成键盘、窄窗口和主题验证。
5. 部署云端 RPC/约束后再发布依赖它的客户端，执行双设备和跨窗口收敛验收。

回滚前端时可恢复旧计时弹框、未归属弹框和记录内联编辑；新增组合命令与日期守卫若已部署，需要保留历史只读规则或同步回滚对应客户端，避免新旧版本对历史写权限理解不一致。实际调整、事项排序和时间分配均使用现有数据实体，不需要回填业务数据。
