# Proposal

## Why

当前“今日事项”只是长期事项在某个工作日的一份成员关系，两边共用同一个事项 ID，因此今日页改名、完成、调整实际用时或删除时会连带改变进行中事项；用户无法把今日安排当成一份独立、可放心执行的计划。需要让加入今日这一动作生成真正独立的事项实例，同时保留两者之间的来源追溯。

## What Changes

- **BREAKING** 将“加入今日”改为创建独立今日事项实例：新实例使用独立事项 ID，并从来源事项复制当时的标题、备注、整体预计、层级、排序和基础业务字段；来源事项 ID 只用于追溯，不再参与双向同步。
- 今日实例的标题、备注、整体预计、今日预计、层级、排序、完成状态、实际用时和删除操作全部独立。修改进行中事项不影响已经存在的今日实例，修改今日实例也不影响进行中事项。
- 在今日页直接新增的事项只创建今日实例；通过“配置今日事项”、执行弹框或进行中快捷入口加入来源事项时，都创建新的今日实例并保留父子结构所需的上下文副本。重复来源事项已配置“每次预计”且当天没有单独预计时，新实例自动把“每次预计”作为初始今日预计；之后两边仍保持独立。
- “进行中 / 已完成”标签排除所有今日实例；待办今日标签和执行事项弹框只读取当前工作日的今日实例；历史分配、未归属时间、报告和备份继续使用完整合法事项范围，并保留今日实例的实际时间。
- 今日标签继续复用进行中标签的列表形态与交互，包括底部“+”新增、行内编辑、子事项、树形拖动排序、右键行菜单、17px 二级缩进、常显拖动柄、禁用态父项勾选框、空状态和柔和骨架加载。今日页“快速编辑计划”只编辑当天实例，进行中页只编辑长期事项；进行中列表只编辑整体预计或重复事项的每次预计，不再展示今日预计。
- “配置今日事项”保持单一今日实例列表，只用于编辑、排序、调整预计和实际用时；工具区提供“从进行中导入”，点击后在同一弹框内切换到简洁的来源选择步骤，只列出来源并支持全选与逐项勾选，不在导入步骤填写时间。导入后回到配置列表：重复来源自动使用每次预计，其余事项再统一设置今日预计。配置弹框中的拖动、改名和实际调整只作用于今日实例，MUST NOT 修改来源事项。
- 重复事项按当前工作日生成独立实例。修改重复模板只影响之后创建的实例；完成、删除或改名今天实例不会改变模板或其他日期。当天显式移出后不得自动重建，手动再次加入会创建一份新实例而不是恢复旧内容。
- 移出今日或删除今日实例采用软删除归档，来源事项不变，历史计时与实际调整继续可报告；再次加入同一来源时创建新实例。删除来源事项也不会删除已经存在的今日实例。
- 本地与 Supabase 增加今日实例标识、实例来源链接和来源事项/日期映射；现有当日计划在首次使用时物化为独立实例，历史按日预计和实际时间数据保留。
- 事项的预计开始日期已到、已逾期或当天产生过时间记录，仍不会因此自动成为今日实例。
- 本变更更新 `merge-tasks-and-timer-into-execution-list` 中“执行弹框展示全部进行中事项”和“不新增按天执行清单”的既有边界；其他计时转换、父事项不可执行和完整待办管理职责保持不变。

## Capabilities

### New Capabilities

- `today-task-planning`: 定义独立今日事项实例、来源追溯、今日页与进行中页隔离、配置今日事项、重复事项、移出与再次加入、执行弹框范围，以及本地和云端同步规则。

### Modified Capabilities

无。当前项目尚未归档形成主规格；与在途 `timer-task-dialog` 变更的差异在本变更设计中明确，并由新能力规格覆盖。

## Impact

- 前端状态与界面：`src-ui/src/store.ts`、`MainWorkbench.vue`、`PlanListEditor.vue`、`TimerTaskDialog.vue` 及其派生逻辑和样式。
- 本地后端：事项创建与查询、今日计划、执行快照、重复事项、实际用时调整、今日概览和报告；新增 SQLite 迁移。
- 云端与同步：`supabase/schema.sql`、事项与来源日期映射的序列化/合并、快照备份恢复、冲突展示及双设备测试。
- 兼容性：这是跨版本破坏性语义变化。旧版本无法正确区分今日实例与长期事项，同一云工作空间必须在升级客户端后再继续写入计划数据；回滚需要恢复升级前备份。
- 不新增第三方依赖，不改变唯一活动计时、停止确认、未归属时间或报告时间口径。
