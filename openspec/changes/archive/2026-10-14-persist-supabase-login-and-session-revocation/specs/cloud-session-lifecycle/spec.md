# Spec Delta

## Purpose

为 TimeGenie 的 Supabase 云端模式定义可长期恢复、可安全续期且可由用户或后台明确撤销的会话生命周期，使临时网络故障不会反复要求输入密码，同时让单设备和全部设备退出具有可验证的一致行为。

## ADDED Requirements

### Requirement: 首次登录后长期保持会话
系统 SHALL 在邮箱密码登录成功后把恢复会话所需的 token 保存到操作系统凭据库，密码 MUST NOT 落盘；只要会话未被明确撤销，应用重启、操作系统重启或 access token 到期都 SHALL 自动恢复或刷新会话，而不再次要求输入账号密码。

#### Scenario: 重启后自动恢复
- **WHEN** 用户已成功登录、关闭应用后重新启动，且保存的 refresh token 仍有效
- **THEN** 系统自动恢复账号状态并允许云端同步，不显示账号密码输入要求

#### Scenario: Access token 到期后自动续期
- **WHEN** 当前 access token 已到期或即将到期，且 refresh token 仍有效
- **THEN** 系统在发起云端业务请求前自动刷新 token、保存轮换后的会话并继续原请求

#### Scenario: 密码不被持久化
- **WHEN** 用户完成邮箱密码登录
- **THEN** 系统只持久化恢复会话所需的 token，且本地数据库、普通配置、日志和导出中均不包含登录密码或完整 token

### Requirement: 临时故障不得清除登录状态
系统 SHALL 区分“会话已明确失效”和“当前无法验证会话”。断网、超时、限流、Supabase 5xx、系统凭据库暂时读取失败、云端 Schema 缺失、RLS 权限错误以及业务错误 MUST NOT 删除已保存的 refresh token；界面 SHALL 将可恢复的网络问题显示为离线或暂不可用，而不是未登录。

#### Scenario: 离线启动保留账号
- **WHEN** 应用启动时无法连接 Supabase，但系统凭据库中存在结构有效的已保存会话
- **THEN** 系统显示该账号处于离线但保留登录状态，允许查看本地缓存，并在网络恢复后自动重新校验和同步

#### Scenario: Supabase 临时故障
- **WHEN** 会话刷新或业务请求收到超时、限流或服务端临时错误
- **THEN** 系统保留本机会话，记录可重试错误，且不显示密码登录表单

#### Scenario: 非身份类错误
- **WHEN** 云端请求因 Schema、RLS、版本冲突或业务校验失败
- **THEN** 系统展示对应错误并保留登录状态，不把该错误解释为会话撤销

#### Scenario: 凭据库暂时不可用
- **WHEN** 操作系统凭据库返回可恢复的读取错误，而不是确认凭据不存在
- **THEN** 系统显示本机凭据暂不可用并保留账号上下文，不覆盖或删除凭据，也不把状态静默降为未登录

### Requirement: 只有明确失效事件触发重新登录
系统 MUST 只在用户手动退出、refresh token 被 Supabase 明确判定为无效、账号被禁用、当前 Auth 会话被撤销或当前设备授权被撤销时清除本机会话并进入需要重新登录状态。单次业务请求的 401/403 MUST 先触发一次受控刷新和重试，不能直接删除会话。

#### Scenario: Refresh token 明确失效
- **WHEN** Supabase Auth 明确返回 refresh token 无效、已撤销或用户不可用
- **THEN** 系统清除本机保存的会话，保留本地业务数据，并提示用户重新登录

#### Scenario: 业务请求 token 过期
- **WHEN** 可安全重放的业务请求因 access token 过期返回身份错误
- **THEN** 系统先刷新会话并重试一次，只有刷新明确失败时才进入需要重新登录状态

#### Scenario: 不可安全重放的请求
- **WHEN** 不可安全重放的业务请求返回身份错误
- **THEN** 系统刷新会话但不自动重复该业务动作，并向用户返回可重试提示，不得仅因该请求失败就删除仍可恢复的会话

### Requirement: 用户可以查看账号设备
系统 SHALL 提供当前账号的设备列表，至少显示设备名称、平台、应用版本、最近在线时间、是否为当前设备以及是否已撤销；用户 MUST 只能查看自己工作空间内的设备。

#### Scenario: 查看设备列表
- **WHEN** 已登录用户打开设备管理
- **THEN** 系统返回该用户工作空间的设备，并明确标记当前设备和已撤销设备

#### Scenario: 跨账号隔离
- **WHEN** 用户请求不属于自己工作空间的设备信息
- **THEN** 云端拒绝访问且不泄露该设备是否存在

### Requirement: 支持撤销单台设备
系统 SHALL 允许用户撤销自己账号下的指定设备。撤销当前设备等同于退出当前设备；撤销其他设备 SHALL 使目标设备在下一次启动、会话检查或同步前置检查时停止云端访问并清除本机会话，且不影响其余设备。

#### Scenario: 撤销其他设备
- **WHEN** 用户确认撤销账号下的一台非当前设备
- **THEN** 云端把目标设备标记为已撤销，其他设备保持登录，目标设备下一次联网检查时进入需要重新登录状态

#### Scenario: 撤销当前设备
- **WHEN** 用户确认撤销当前设备或执行普通退出
- **THEN** 系统撤销当前设备授权、请求 Supabase 注销当前 Auth 会话、清除本机 token，并切换到不会继续上传的本地状态

#### Scenario: 已撤销设备重新授权
- **WHEN** 已撤销设备上的用户重新输入有效账号密码登录
- **THEN** 系统把本次登录作为新的设备授权，恢复该安装实例的云端访问，且不得自动上传撤销后尚未审阅的本地待同步修改

#### Scenario: 离线期间发生远程撤销
- **WHEN** 设备离线期间在其他设备或后台被撤销，但本机尚未获知该状态
- **THEN** 本机可以继续按既有本地优先规则保存修改；恢复网络后系统 MUST 在上传任何待同步修改前校验设备授权，发现撤销后停止上传、保留本地修改供用户处理并要求重新登录

### Requirement: 支持撤销全部设备
系统 SHALL 提供“退出所有设备”操作，并在执行前进行明确的二次确认。操作成功后 SHALL 撤销该账号的全部 Supabase Auth refresh token 和全部 TimeGenie 设备授权，包括发起操作的当前设备。

#### Scenario: 退出所有设备
- **WHEN** 用户完成二次确认并执行退出所有设备
- **THEN** 云端撤销该账号全部会话与设备授权，当前设备立即清除本机会话，其他设备在下一次联网检查或 token 刷新时进入需要重新登录状态

#### Scenario: 取消全设备退出
- **WHEN** 用户在二次确认中取消操作
- **THEN** 系统不撤销任何 Auth 会话或设备授权

### Requirement: 后台撤销可以被客户端识别
系统 SHALL 支持管理员通过 Supabase Auth 管理能力撤销账号会话，并通过受控的设备授权数据撤销指定 TimeGenie 设备。客户端 SHALL 在启动、主动会话检查、token 刷新和同步上传前识别后台撤销；桌面端 MUST NOT 持有 service_role 或其他管理密钥。

#### Scenario: 后台撤销指定设备
- **WHEN** 管理员在 Supabase 后台把指定 TimeGenie 设备标记为已撤销
- **THEN** 该设备下一次联网授权检查时停止同步并清除本机会话，其他设备不受影响

#### Scenario: 后台撤销账号 Auth 会话
- **WHEN** 管理员通过 Supabase Auth 管理能力撤销该账号的会话
- **THEN** 受影响设备在下一次 token 刷新或会话校验时清除本机会话并提示重新登录

#### Scenario: 客户端不使用管理密钥
- **WHEN** 桌面端执行设备列表、设备撤销或退出操作
- **THEN** 所有请求均使用 anon key、当前用户 JWT 和受 RLS 或受控服务端逻辑保护的接口，不读取或保存 service_role key
