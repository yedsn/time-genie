# Proposal

## Why

当前计时开始、计时结束和事项完成只能在应用内部产生状态变化，无法通知其他项目、运行本地脚本或触发 `raycast://confetti`、`motioncue://...` 等自定义协议。增加设备级自动化 Hook 后，用户可以把日常工作事件连接到已有工具，同时保持计时和待办操作简单可靠。

## What Changes

- 在设置页增加“自动化 Hook”管理，支持创建、编辑、启停、排序、删除和测试多条规则。
- 第一版提供 `timer.started`、`timer.stopped`、`task.completed` 三类业务事件，明确区分结束一段计时与完成一个事项。
- 支持两类动作：通过操作系统打开 HTTP/HTTPS 或自定义 URI；以结构化的程序、参数和工作目录运行本地程序或脚本。
- Hook 在业务事务成功后后台执行，执行失败、超时或目标不存在不得回滚或阻塞原业务操作。
- 向本地程序的标准输入传递结构化 JSON 事件，并为 URI 提供经过编码的模板变量。
- 记录最近执行状态、耗时、退出码和有限长度的输出/错误，设置页可查看测试与实际执行结果。
- Hook 配置和执行记录只保存在当前设备，不通过工作空间或 Supabase 同步；云端数据模式下仍由发起操作的设备执行本机 Hook。
- 第一版不提供前置拦截、业务结果修改、复杂条件表达式、自动重试或远程命令执行。

## Capabilities

### New Capabilities

- `automation-hooks`: 定义设备级 Hook 规则、业务事件、URI 与本地程序动作、事件上下文、异步执行、失败隔离、测试和运行记录。

### Modified Capabilities

无。当前主规格目录尚无已归档能力，本变更以独立能力补充自动化行为。

## Impact

- 本地 SQLite 需要新增设备 Hook 规则和运行记录，并限制历史记录数量或保留时间。
- Tauri Rust 后端需要增加 Hook CRUD、测试、模板渲染、URI 打开、本地子进程执行与后台调度能力。
- 计时开始、计时结束、待办完成以及计时分配中的“同时完成”路径需要在成功提交后发布一致的业务事件；托盘入口也必须经过同一事件出口。
- Vue 设置页需要增加 Hook 列表与编辑弹框，展示动作摘要、启用状态和最近执行结果。
- Windows 本地命令必须隐藏终端窗口；URI 调用需要使用操作系统协议处理器并反馈未注册协议等错误。
- 需要补充数据库迁移、事件载荷、去重、模板变量、超时、失败隔离、托盘入口和多事项完成场景测试。
