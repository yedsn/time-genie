# Spec Delta

## Purpose

允许用户把计时和待办的关键业务事件连接到当前设备上的自定义协议、本地程序或脚本，并以可测试、可追踪且不影响核心业务可靠性的方式执行自动化动作。

## ADDED Requirements

### Requirement: 管理设备级 Hook 规则
系统 SHALL 在设置中提供设备级 Hook 规则管理，允许用户创建、编辑、启用、停用、排序和删除多条规则。每条规则 SHALL 包含稳定 ID、名称、触发事件、动作类型、动作配置、超时时间和启用状态，并且不得通过工作空间或 Supabase 同步到其他设备。

#### Scenario: 创建多条同事件规则
- **WHEN** 用户为 `task.completed` 创建两条已启用规则
- **THEN** 系统保存两条独立规则，并在事项完成时按配置顺序分别调度

#### Scenario: 停用规则
- **WHEN** 用户停用一条已存在的规则并保存设置
- **THEN** 后续匹配事件不再执行该规则，其他已启用规则保持正常

#### Scenario: 切换设备
- **WHEN** 同一工作空间在另一台设备登录或同步
- **THEN** 另一台设备不会自动获得本机的 Hook 规则或执行记录

### Requirement: 支持明确的业务事件
系统 SHALL 支持 `timer.started`、`timer.stopped` 和 `task.completed` 三类 Hook 事件。计时事件 SHALL 表示一段计时成功开始或结束；事项完成事件 SHALL 表示普通事项或重复事项某日轮次从未完成变为完成，不得把暂停、继续、恢复事项或单纯分配工时解释为上述事件。

#### Scenario: 开始计时后触发
- **WHEN** 用户从主窗口、今日页、待办页或托盘成功开始一段计时
- **THEN** 系统在计时记录提交成功后发布一次 `timer.started` 事件

#### Scenario: 结束待归属计时后触发
- **WHEN** 用户结束一段没有有效关联事项或原事项已经删除的计时
- **THEN** 系统仍发布一次 `timer.stopped` 事件，并在事件中保留计时名称快照和待归属状态

#### Scenario: 直接完成事项
- **WHEN** 用户勾选一个未完成事项或重复事项当天轮次并成功提交
- **THEN** 系统针对该事项发布一次 `task.completed` 事件

#### Scenario: 一次分配完成多个事项
- **WHEN** 用户将一段时间分配给多个事项并勾选其中两个“同时完成”
- **THEN** 系统发布一次工时分配业务结果，并针对两个实际从未完成变为完成的事项各发布一次 `task.completed` 事件

#### Scenario: 恢复已完成事项
- **WHEN** 用户取消勾选一个已完成事项
- **THEN** 系统不得发布 `task.completed` 事件

### Requirement: 仅在成功提交后执行并隔离失败
系统 MUST 在对应业务操作成功提交后调度 Hook。Hook SHALL 在后台执行；启动失败、协议未注册、非零退出码、超时或输出解析失败均不得回滚、阻塞或改变计时和事项业务结果。

#### Scenario: 业务操作失败
- **WHEN** 计时开始或事项完成因版本冲突而未提交
- **THEN** 系统不创建对应 Hook 执行记录，也不启动任何匹配动作

#### Scenario: Hook 执行失败
- **WHEN** 计时已经成功结束，但匹配的本地程序不存在或返回非零退出码
- **THEN** 计时保持已结束状态，系统记录 Hook 失败并允许用户之后查看错误

#### Scenario: Hook 执行超时
- **WHEN** 本地程序超过规则配置的超时时间仍未退出
- **THEN** 系统终止该执行并记录为超时，不影响其他规则继续执行

### Requirement: 支持 URI 动作
系统 SHALL 支持通过当前操作系统的默认协议处理器打开 `http`、`https` 和已注册的自定义 URI。URI 动作 SHALL 支持受控模板变量，并对插入 URI 的动态值进行百分号编码；未注册协议或非法 URI SHALL 作为 Hook 执行失败记录。

#### Scenario: 触发自定义协议
- **WHEN** 已启用规则在事项完成时打开 `motioncue://play/task-complete`
- **THEN** 系统调用操作系统协议处理器，并将调用结果记录为成功或失败

#### Scenario: Raycast 协议未注册
- **WHEN** 当前设备没有可处理 `raycast://confetti` 的应用
- **THEN** Hook 记录显示协议未注册或无法打开，事项完成仍然成功

#### Scenario: URI 模板包含中文事项名称
- **WHEN** URI 模板包含 `{{task.title}}` 且事项名称含中文、空格或保留字符
- **THEN** 系统使用编码后的值生成合法 URI，不把事项名称解释为额外参数或 URI 结构

### Requirement: 支持结构化本地程序动作
系统 SHALL 允许用户分别配置可执行程序、参数列表、可选工作目录和 1 至 60 秒超时时间。系统 MUST 直接启动指定程序而不是默认交给 Shell 解释，并 SHALL 在 Windows 上隐藏子进程终端窗口。

#### Scenario: 运行 PowerShell 脚本
- **WHEN** 用户配置程序 `powershell.exe`，并将 `-NoProfile`、`-File` 和脚本路径保存为独立参数
- **THEN** 系统按参数边界启动 PowerShell，且桌面应用不会弹出额外终端窗口

#### Scenario: 参数包含空格
- **WHEN** 程序路径、脚本路径或模板变量值包含空格
- **THEN** 系统保持各参数边界，不要求用户手工拼接转义引号

#### Scenario: 尝试使用 Shell 语法
- **WHEN** 用户把管道或重定向符号作为普通参数保存
- **THEN** 系统将其作为字面参数传递，不隐式执行 Shell 管道或重定向

### Requirement: 提供结构化事件上下文
本地程序动作 SHALL 从标准输入接收 UTF-8 JSON 事件，至少包含事件类型、事件 ID、发生时间、设备 ID，以及适用的主体、事项、事项路径、计时记录、时长、分配状态和名称快照。不存在或已删除的实体 SHALL 以空对象或快照表达，不得导致事件无法执行。

#### Scenario: 计时关联事项仍存在
- **WHEN** `timer.stopped` 对应一个有效事项
- **THEN** 标准输入 JSON 包含计时信息及事项 ID、名称、完整路径和主体信息

#### Scenario: 原事项已经删除
- **WHEN** 计时结束时原事项已经不存在
- **THEN** 标准输入 JSON 的当前事项为空，但包含开始计时时保存的名称快照、计时 ID和时长

#### Scenario: 重复事项当天完成
- **WHEN** 用户完成重复事项的当天轮次
- **THEN** `task.completed` 事件包含稳定事项 ID和轮次日期，使脚本能够区分不同日期的完成事件

### Requirement: 防止同一业务事件重复执行
系统 SHALL 为每个业务事件生成稳定事件 ID，并保证同一设备上的同一 `event_id + hook_id` 最多产生一次实际执行。界面刷新、网络重试、云端响应重放和历史数据同步不得补执行旧 Hook。

#### Scenario: 云端请求重试返回同一结果
- **WHEN** 同一计时结束操作因网络响应不确定而使用相同操作 ID 重试
- **THEN** 系统只执行一次匹配的 `timer.stopped` Hook

#### Scenario: 拉取其他设备的历史变化
- **WHEN** 当前设备从 Supabase 拉取另一台设备已经完成的事项或已经结束的计时
- **THEN** 当前设备不为这些历史变化执行本地 Hook

### Requirement: 支持测试规则
设置页 SHALL 为每条规则提供测试操作。测试 SHALL 使用明确标记为测试的示例事件载荷执行当前草稿配置，不创建、完成或修改真实事项和计时记录，并显示成功、失败、超时、耗时及可用错误信息。

#### Scenario: 测试未保存的 URI 草稿
- **WHEN** 用户编辑 URI 后点击测试但尚未保存规则
- **THEN** 系统使用当前草稿执行一次测试，并且不改变已保存规则

#### Scenario: 测试本地程序
- **WHEN** 用户测试本地程序动作
- **THEN** 程序收到 `test: true` 的示例 JSON，设置页展示执行耗时、退出码和有限长度输出

### Requirement: 保留有限的执行记录
系统 SHALL 为测试与实际执行记录 Hook 名称、事件类型、事件 ID、状态、开始和结束时间、耗时、退出码以及截断后的标准输出、标准错误或错误信息。系统 MUST 对记录数量和单次输出大小设置上限，并允许设置页查看最近结果而不暴露应用凭据。

#### Scenario: 程序输出大量文本
- **WHEN** 本地程序产生超过单次记录上限的标准输出或错误输出
- **THEN** 系统只保留末尾的有限内容并标记已截断，数据库不会无限增长

#### Scenario: 查看最近失败
- **WHEN** 用户在设置页查看一条最近失败的 Hook
- **THEN** 系统展示可用于定位问题的状态、时间、耗时和错误摘要，但不展示系统凭据或未配置为事件字段的敏感数据
