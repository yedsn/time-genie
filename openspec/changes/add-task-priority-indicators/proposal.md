# Proposal

## Why

当前事项只能通过标题、日期和手动顺序表达安排意图，用户无法快速辨认哪些事项更需要关注。为事项增加稳定、跨设备同步的优先级颜色标识，可以提升浏览和选择效率，同时保留现有手动排序习惯。

## What Changes

- 为事项增加“紧急、高、普通、低”四档优先级，其中已有事项和新建事项默认使用“普通”。
- 在进行中待办、今日计划、计时/执行事项弹框及已完成历史中，以颜色标识并辅以文字或可访问名称展示优先级。
- 允许用户在事项管理和紧凑事项设置入口中修改优先级，并纳入现有的版本冲突保护。
- 优先级仅影响视觉标识，不参与事项排序；现有手动拖拽顺序和父子树顺序保持不变。
- 复制事项及创建今日实例时继承来源事项的优先级；父子事项分别维护自身优先级，后续修改互不联动。
- 将优先级纳入本地数据库、Supabase 云端结构、直接云存储、备份恢复和跨设备同步链路。

## Capabilities

### New Capabilities

- `task-priority-indicators`: 定义事项优先级的档位、默认值、编辑、继承、同步和颜色标识行为。

### Modified Capabilities

无。当前项目没有已发布的主规格，本变更以新能力描述事项优先级行为。

## Impact

- 本地数据：`tasks` 表迁移、事项 DTO、创建/更新/复制/今日实例及相关查询。
- 云端数据：`supabase/schema.sql`、部署补丁及直接云存储的任务行映射与校验。
- 前端：事项类型与状态映射、待办编辑器、今日计划、计时/执行弹框、已完成历史及共享样式。
- 数据流：工作空间快照、备份恢复、跨设备变更和版本冲突处理。
- 测试：优先级默认值与校验、继承行为、顺序不变、同步往返及主要界面展示。
