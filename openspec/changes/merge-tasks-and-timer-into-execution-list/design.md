# Design

## Context

见 `proposal.md` 与 `specs/execution-list/spec.md`。当前主窗口把“待办”和“计时”作为两个一级页面：`PlanListEditor.vue` 已具备当前主体事项的行内改名、新增、删除、层级、排序、预计、备注、完成和单个悬停计时按钮；`TimeTrackingWorkspace.vue` 顶部则再次提供大型计时状态、事项选择器和暂停/继续/结束按钮，下方才是时间记录处理。顶部 `GlobalTimerBar.vue` 还提供第三个开始、切换与控制入口。

计时状态已经集中在 store 的 `runningEntry`，开始与切换已统一通过 `transitionTimer`，暂停、继续、停止、停止确认和未归属处理也已有稳定流程。事项的 `directMinutes` / `totalMinutes` 表示最终实际口径，不包含尚未确认归属的活动计时。因此本变更应以重新组合现有界面和状态为主，避免复制计时状态机或改变持久化语义。

## Goals / Non-Goals

**Goals:**

- 让 `PlanListEditor` 成为当前主体日常执行的唯一主列表，同时继续复用现有事项编辑能力。
- 让执行状态区、事项行与全局快捷入口读取同一份 store 状态和调用同一组计时动作。
- 明确区分最终实际用时与当前活动段时长，避免视觉合计提前改变业务口径。
- 收敛时间记录页面职责，并保持停止确认、历史定位和未归属处理路径可达。
- 尽量把改动限制在前端组合、展示逻辑和验证脚本，不引入新数据表或同步协议。

**Non-Goals:**

- 不新增按天维护的执行清单，也不把所有主体的事项混合到同一列表。
- 不改变最多两级、父事项只汇总、叶子事项可计时等领域规则。
- 不改变计时转换、最终归属、停止确认、未归属时间清除或多设备计时权威语义。
- 不把完整工时拆分编辑器嵌入执行列表；复杂归属继续留在停止确认和时间记录页面。
- 不移除公共事项选择器，它仍服务全局快捷计时、补录、分配和未归属处理。

## Decisions

### 1. 在现有计划列表上扩展执行能力，不新建第二套事项表

继续以 `PlanListEditor.vue` 作为当前主体进行中事项的权威编辑表，通过新增执行状态和常驻计时单元升级为执行列表。列表仍使用 `store.selectedSubjectTasks`、现有父子扁平顺序和编辑事件，不新增执行列表专用事项副本。

备选方案是创建新的 `ExecutionList.vue`，再复用部分行组件。它会立即产生两套列表状态、拖动、临时事项和批量编辑入口，且用户已经确认不需要独立今日清单，因此没有足够收益。实现时可以在 `PlanListEditor` 内抽取较小的 `ExecutionTimerCell` 或纯展示逻辑，但不复制整张表。

### 2. 保留内部页面 ID，先调整用户可见名称和职责

为降低路由、刷新策略、托盘事件和停止确认跳转的改动风险，store 内部可继续使用 `plan` 与 `timer` 页面 ID；用户可见导航分别改为“执行”和“时间记录”。`MainWorkbench.vue` 仍以现有分支加载页面，但 `timer` 分支不再承担主要开始计时流程。

备选方案是同时把内部 ID 改为 `execution` 与 `records`。它更语义化，但会扩大到页面计数、刷新判断、停止定位、快捷键和测试夹具，属于可独立完成的重命名重构，不应与本次交互合并。

### 3. 执行页使用一个共享状态区，避免与顶部工具重复

执行页面在列表上方渲染一个紧凑执行状态区：有活动计时时显示事项、实时本段时长和暂停/继续/结束；空闲时显示未归属累计和处理入口。该状态区复用 `store.runningEntry`、`entryDurationSeconds`、`unassignedSeconds` 与现有动作。

为避免同一页同时出现两套等价控制，`MainWorkbench` 在执行页不再并列渲染功能相同的 `GlobalTimerBar` 与 `UnassignedTimeIndicator`；在今日概览、时间记录、报告和设置等页面继续显示全局入口。可以抽取一个共享的计时摘要/格式化逻辑，但执行页状态区和顶部紧凑条允许拥有不同布局。

备选方案是在执行页保留顶部全局条且只加强事项行。它改动更小，但未归属入口和当前计时会与列表割裂，也会让合并后的页面仍像两个拼接工具。

### 4. 用动作矩阵驱动每行计时控制

为叶子事项根据全局活动状态派生单一动作模型：

- 无活动计时：`start`；
- 活动计时属于其他事项：`switch`；
- 当前事项运行中：`pause` 与 `stop`；
- 当前事项暂停中：`resume` 与 `stop`；
- 有子事项的父项：`summary`，不提供可触发计时动作。

派生逻辑应提取为无 UI 依赖的纯函数或集中 computed，供按钮文案、图标、title、ARIA 标签、禁用态和测试共同使用。执行列表的开始与切换都调用 `store.transitionTimer({ taskId })`，暂停、继续和结束继续调用现有 store 方法，避免列表组件自行拼接停止与开始。

备选方案是根据 `runningTaskId` 在模板中分散多个条件。当前模板已经存在类似分支，继续扩展容易让视觉状态、文案和实际事件不一致。

### 5. 最终实际与活动时长分层展示

事项行继续以 `directMinutes` 展示叶子的最终实际，以 `totalMinutes` 展示父项后代汇总。当前活动叶子额外展示由活动 entry 计算的实时本段时长，例如“实际 35 分钟 · 本段 00:18:32”，不得把本段直接加进 `directMinutes`。父项只汇总最终实际；若后代正在计时，可显示“组内计时中”及活动子项名称，但不把未确认本段加进父项总计。

停止并确认归属后，现有刷新链会更新最终实际。切换产生的旧段在未确认前仍不进入最终实际；界面可以显示轻量待归属提示，但本变更不新增另一套临时实际合计。

备选方案是把实时段加到实际列形成视觉合计。虽然更接近即时总数，但会与报告、导出、父项汇总和未确认归属口径不一致，并可能在用户改分配后跳变。

### 6. 活动事项的危险操作先防护，不自动编排复合动作

当前活动事项仍允许改名、编辑备注和预计、拖动排序；完成和删除则在前端入口处阻止，并提示先结束或切换计时。这样不会把“完成/删除”隐式扩展成“停止、打开归属确认、再修改事项”的多阶段操作，也避免用户误以为计时记录已自动确认。

备选方案是在点击完成或删除时自动停止并继续原动作。它会与停止确认弹框争夺焦点，删除默认事项还可能使待归属记录失去有效候选，因此本次选择显式防护。后端现有版本和引用校验仍作为最终保障。

### 7. 未归属时间只改变承载位置，不改变生命周期

执行状态区在没有活动事项时展示 `unassignedSeconds` 和打开 `UnassignedTimeDialog` 的入口。用户从任一事项行开始计时时，仍只调用现有 `transitionTimer`；后端按既有原子规则清除活动未归属起点并开始事项。前端不增加确认、冻结、待处理队列或自动分配。

现有未归属弹框继续支持拆分给多个事项、同时完成、记为休息和忽略。执行页只提供状态与入口，不复制复杂编辑器。其他页面仍由顶部 `UnassignedTimeIndicator` 提供入口。

备选方案是把分配编辑器直接展开在执行列表顶部。它会显著挤压列表并复制 `UnassignedTimeDialog` 的动态分钟、拆分和并发处理逻辑，超出本次合并目标。

### 8. 时间记录页移除大型计时焦点面板但保留全局控制

`TimeTrackingWorkspace.vue` 删除或停用顶部 `time-focus-panel` 及其专用 `TaskSelectControl`、备注和计时忙碌状态，只保留时间记录头部、手动补录、历史分页、修正、归属、特殊时间和导出。页面标题与空状态文案改为时间记录语义。

停止确认的“调整归属”继续把内部页面切到 `timer`，加载目标历史页并展开记录；因为内部 ID 不变，现有定位逻辑只需更新可见文案和必要的页面结构选择器。用户在时间记录页需要开始或切换时使用顶部 `GlobalTimerBar`。

备选方案是保留大型面板但折叠。它仍会留下两个主计时入口，并使时间记录列表在常规窗口中向下偏移，未真正完成职责收敛。

### 9. 新增轻量逻辑验证并保留现有端到端边界

为动作矩阵、活动事项危险操作防护、最终实际与本段展示模型、执行页/其他页顶部工具选择增加纯逻辑测试或项目现有风格的验证脚本。组件层验证当前行状态、父项禁用、窄宽度常驻动作和时间记录页不再拥有主选择器。

计时事务、未归属清除、多设备权威和停止确认已经由既有 Rust/前端验证覆盖，本次只增加必要回归，不复制底层领域测试。手工走查需要覆盖本地与云端模式、浅色/深色主题、长标题、父子事项和窗口缩放。

## Risks / Trade-offs

- [执行列表信息密度增大，可能挤压事项标题和元信息] → 将计时动作设为常驻主列，次要管理动作继续按悬停或更多菜单展示，并为窄窗口定义优先级与收纳规则。
- [同一计时在状态区、活动行和全局条有多个展示点] → 全部读取同一 store 状态；执行页隐藏功能重复的全局条，其他页面只保留全局条。
- [运行中时长与最终实际容易被误解为重复或漏算] → 使用明确标签和视觉层级分开展示，只有确认归属后刷新最终实际。
- [切换后旧记录待归属可能被忽略] → 沿用现有非阻断提示和时间记录入口，不在执行列表虚构已归属结果。
- [阻止活动事项完成或删除会比普通事项多一步] → 提示中直接说明需要结束或切换，并让暂停、结束、切换操作始终可见。
- [移除时间记录页大型计时区可能影响旧使用习惯] → 顶部全局计时条保留同等开始与切换能力，执行列表成为更完整的主入口。

## Migration Plan

1. 先抽取并验证执行行动作矩阵、活动时长展示和页面工具可见性逻辑，不改变现有页面。
2. 在 `PlanListEditor` 接入常驻计时列、活动行状态和危险操作防护，继续调用现有 store 计时方法。
3. 增加执行页状态区，并在 `MainWorkbench` 按页面选择执行状态区或顶部全局计时/未归属入口。
4. 将导航文案改为“执行”和“时间记录”，收敛 `TimeTrackingWorkspace`，修正停止确认定位和相关空状态文案。
5. 运行前端类型检查、构建、相关验证脚本和 Rust 计时回归，并按本地/云端、主题、父子层级和窄窗口进行手工走查。

本变更没有数据迁移。回滚时可以恢复原导航文案、时间记录页顶部焦点面板和待办行的悬停计时按钮；底层事项、计时、分配及未归属数据均无需回滚。
