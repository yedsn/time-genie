# Design

## Context

见 `proposal.md` 与 `specs/timer-task-dialog/spec.md`。当前开始或切换事项主要依赖 `TaskSelectControl.vue`：顶部 `GlobalTimerBar.vue` 和 `TimeTrackingWorkspace.vue` 都呈现输入框式选择，今日页、托盘事件等入口则把用户带到计时页面或聚焦选择器。该选择器支持主体标签、搜索、已有事项选择和内联新建，但弹出层仍以“搜索一个候选项”为中心，不能同时承担高密度浏览和轻量事项维护。

`PlanListEditor.vue` 已具备事项改名、今日预计、备注、整体预计、日期、重复、完成、删除、新增父子事项和排序能力；其中“调整今日实际”弹框已经验证了高密度父子列表在当前视觉体系中的可用性。计时状态集中在 store 的 `runningEntry`，开始与切换统一通过 `transitionTimer`，因此新弹框应复用现有数据和动作，而不是复制计时状态机。

## Goals / Non-Goals

**Goals:**

- 让任意页面的开始或切换计时都进入同一个高密度事项弹框。
- 让用户在当前主体的今日未完成事项中快速浏览、搜索、轻量编辑、新增并立即计时。
- 通过逐项自动保存减少“先保存整个弹框再计时”的额外步骤，并保证点击计时前不会丢失当前行修改。
- 保留待办页、计时页、停止确认、未归属时间和多设备计时的既有领域语义。
- 保持非计时场景的公共事项选择器可继续复用。

**Non-Goals:**

- 不把待办页改成执行列表，不重命名“待办”或“计时”导航。
- 不在弹框中复制完整待办表，不提供拖动排序、任意层级调整或批量编辑。
- 不在弹框中调整已确认实际用时；相关能力继续由“调整今日实际”和时间记录承担。
- 不把不同主体事项混合为一张列表。按天维护今日计划及其同步协议由后续 `add-today-plan-tab-and-filter-execution-dialog` 变更定义，并覆盖本设计原有的“不新增按天执行清单”边界。
- 不改变最多两级、父事项不可计时、唯一活动计时、停止确认、未归属清除或同步协议。

## Decisions

### 1. 保持现有页面职责，新增跨页面共享弹框

待办页继续由 `PlanListEditor.vue` 承担完整事项管理，计时页继续展示当前计时和时间记录。新增独立的共享弹框组件，由顶部快捷条、计时页、今日页、托盘事件和后续同类入口统一打开。

弹框的打开状态和初始主体应由主工作台或共享 store 协调，避免每个入口各自维护一套弹框。入口只表达“开始”或“切换”意图；暂停、继续和结束仍留在当前计时控制区。

这取代了把 `PlanListEditor` 升级为执行列表的旧方案。旧方案虽然减少页面切换，却使日常待办管理持续承载计时状态和动作，信息密度与用户现有习惯不匹配。

### 2. 所有计时事项选择统一为按钮加弹框

空闲时，各计时入口显示“开始计时”或“选择事项并开始”；已有活动计时时显示当前事项和计时控制，并提供“切换事项”按钮。按钮打开统一弹框，不再在页面上展开 `TaskSelectControl` 输入框。

`TaskSelectControl` 不删除，继续用于手动补录、工时分配、未归属拆分等需要在表单中选择事项的场景。本变更只替换“开始/切换计时”这一类入口，避免为了统一视觉而破坏其他成熟流程。

### 3. 弹框按主体分区，但一次只展示一个主体

弹框顶部展示所有可用主体标签，默认主体按以下顺序确定：入口显式传入的上下文主体、当前选中主体、已有活动计时所属主体、首个可用主体。切换标签时弹框保持打开，并刷新为该主体的今日未完成事项和必要父级上下文；跨日仍活动的计时仅显示在状态区，不混入候选列表。

不同主体不得混排。这样既保留“全部事项可达”，又避免相同名称、父子路径和编辑归属在一张长列表中混淆。弹框不展示已完成事项；如需恢复或维护已完成事项，继续进入待办页的已完成标签。

### 4. 使用高密度父子列表，计时动作常驻

列表视觉密度参考“调整今日实际”弹框。每个叶子行稳定展示：事项名称、今日预计、已确认实际、备注状态、开始或切换按钮以及更多菜单。父事项作为分组行展示汇总预计与汇总实际，可改名和新增子项，但不提供计时按钮。

叶子动作模型为：

- 没有活动计时：`开始`；
- 其他事项活动中：`切换`；
- 当前事项运行中：展示`正在计时`，不重复触发开始；
- 当前事项暂停中：展示`已暂停`，切换到其他事项仍使用`切换`；
- 父事项：只汇总，不可计时。

搜索只过滤当前主体，并保留父项上下文：匹配子项时应显示其父项，匹配父项时可显示该组。主要计时动作始终可见，不依赖悬停。

### 5. 常驻编辑限于名称和今日预计

事项名称与今日预计是计时前最常调整的字段，因此允许在行内直接编辑。名称通过点击进入编辑，回车或失焦保存；今日预计以紧凑分钟输入呈现，回车或失焦保存。保存状态按字段或行展示“保存中、已保存、失败”，不使用弹框级“保存全部”。

备注通过小图标打开紧凑浮层，失焦、明确完成或快捷键提交后保存。整体预计、预计开始日期、重复设置、完成和删除放入“更多”菜单，并可复用现有的小弹框或确认流程。删除和完成仍遵循现有安全校验，尤其不得直接处理当前活动事项。

完整排序和复杂层级调整不进入弹框。用户需要这些操作时通过明确入口前往待办页，避免弹框退化为第二套完整待办表。

### 6. 逐项自动保存并保证计时前提交顺序

弹框为每一行维护本地草稿、已保存基线、保存中状态和字段错误。普通失焦或回车触发该字段保存；一行保存失败只标记该行，不阻断其他事项编辑，也不关闭弹框。

用户点击某行“开始”或“切换”时，按以下顺序执行：

1. 提交该行仍处于编辑态或尚未保存的名称、今日预计和备注；
2. 等待该行保存完成；
3. 保存失败则停在弹框并聚焦错误字段；
4. 保存成功后调用一次 `store.transitionTimer`；
5. 计时成功立即关闭弹框；计时失败保持弹框、刷新权威计时状态并在目标行提示。

弹框不得自行串联“先停止再开始”，也不得在保存失败时继续计时。不同事项可以独立保存，但同一字段的连续修改需要串行化或以版本检查避免旧响应覆盖新值。

### 7. 新增事项后留在弹框并可立即开始

工具栏提供“新增事项”，父行提供“新增子项”。新建编辑行只要求名称，今日预计可选；确认后立即创建并保持弹框打开。新事项应插入到对应主体和父项位置、短暂高亮，并提供开始动作。

如果用户在新建行上直接点击开始，系统先创建事项，拿到有效 ID 后再开始计时；创建失败则保留草稿和错误信息。弹框不提供拖动来重新选择父项；需要复杂调整时进入待办页。

### 8. 已确认实际只读，未归属和切换语义保持不变

叶子行展示 `directMinutes`，父行展示 `totalMinutes`，两者均为已确认实际，只读且不叠加当前活动本段。弹框可显示当前事项的运行或暂停状态，但不承担暂停、继续、结束和实际调整。

开始或切换仍只调用现有 `transitionTimer`。存在活动未归属起点时，后端继续原子丢弃当前未归属时间并开始目标事项；不新增确认弹框、不自动分配，也不生成休息或待处理记录。切换结束的旧记录继续走现有停止确认和待归属流程。

### 9. 弹框必须支持高密度、窄窗口和键盘操作

常规宽度下优先让用户同时看到多行事项。窄窗口中可以隐藏汇总说明、压缩已确认实际或把更多菜单换行，但必须保留事项名称、层级、今日预计和主要计时动作。长标题应截断并提供完整提示，编辑态允许合理扩展。

主体标签、搜索、行内字段、备注、更多菜单和计时按钮都必须可通过键盘操作；开始与切换按钮具有包含事项名称的可访问名称。弹框打开时焦点进入搜索或列表首个可操作项，关闭后返回触发按钮。

## Risks / Trade-offs

- [弹框编辑能力过多，重新变成一张完整待办表] → 常驻只保留名称和今日预计，备注使用浮层，低频字段收进更多，排序和复杂层级明确留在待办页。
- [自动保存和立即计时产生竞态] → 开始/切换前显式冲刷目标行草稿并等待保存完成；失败时禁止进入计时转换。
- [同一弹框由多个页面入口打开，初始主体可能不一致] → 定义统一的主体解析优先级，并允许入口显式传入上下文主体。
- [高密度列表在窄窗口拥挤] → 定义字段优先级和响应式收纳，主要计时动作始终常驻。
- [切换主体时未完成编辑可能丢失] → 切换前提交当前编辑字段；保存失败则留在原主体并提示。
- [非计时选择器与计时弹框并存造成概念重复] → 按用途划界：计时开始/切换使用弹框，补录、分配和未归属拆分继续使用表单型选择器。

## Migration Plan

1. 新增弹框状态、主体解析、列表派生和计时动作模型，先用纯逻辑测试固定行为。
2. 实现高密度列表、搜索、主体标签、新增及名称/今日预计自动保存，再接入备注浮层和更多菜单。
3. 接入 `transitionTimer`，实现计时前冲刷保存、成功关闭和失败留在行内的顺序。
4. 逐一替换顶部快捷条、计时页、今日页和托盘事件中的输入式计时选择入口。
5. 回归待办页未改变、非计时 `TaskSelectControl` 场景正常，以及本地/云端、主题、窄窗口和键盘操作。

本变更没有数据迁移。回滚时恢复各计时入口原有的 `TaskSelectControl` 或页面跳转即可；事项、计时和同步数据无需回滚。
