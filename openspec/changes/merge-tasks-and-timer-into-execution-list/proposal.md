# Proposal

## Why

当前各页面主要通过事项输入框选择或新建事项，再触发开始或切换计时。这个交互一次只能关注一个候选项，浏览全部待办、确认父子层级、顺手修改名称或今日预计都不够直观；用户往往需要先回到待办页整理，再返回计时入口重新选择。需要把所有“开始/切换计时”的事项选择统一为一个高密度弹框，让用户在一个上下文中浏览、轻量编辑并立即开始事项，同时保持待办页现有结构与职责不变。

## What Changes

- 保持“待办”和“计时”页面现状，不再将待办改造为执行列表，也不调整现有导航名称和页面职责。
- 将顶部快捷计时、计时页面、今日页及托盘等开始/切换入口统一为“开始计时”或“切换事项”按钮，点击后打开同一个计时事项弹框。
- 弹框顶部保留主体标签，默认当前上下文主体；一次只展示一个主体的全部进行中事项，不混合不同主体，也不混入已完成事项。
- 采用接近“调整今日实际”的高密度列表，展示父子层级、事项名称、今日预计、已确认实际和常驻开始/切换动作；父事项仅汇总，不可直接计时。
- 弹框内常驻编辑仅包含事项名称和今日预计，采用逐项自动保存；备注通过紧凑浮层编辑，整体预计、预计开始日期、重复设置、完成和删除收进“更多”。
- 支持在弹框中新增一级事项或在父事项下新增子项；完整排序和复杂层级调整继续留在待办页。
- 点击开始或切换时先提交当前行未保存的修改，保存成功后调用现有统一计时转换；计时成功立即关闭弹框，失败则保持弹框并在对应行反馈。
- 开始或切换事项继续直接丢弃当前未归属时间，不改变停止确认、最终实际用时、同步协议或计时权威语义。

## Capabilities

### New Capabilities

- `timer-task-dialog`: 定义跨页面统一的弹框式计时事项浏览、轻量编辑、新增以及开始/切换交互。

### Modified Capabilities

无。项目当前没有已归档主规格，本变更以新能力承接现有计时事项选择入口的统一改造。

## Impact

- 前端组件：新增统一计时事项弹框；`GlobalTimerBar.vue`、`TimeTrackingWorkspace.vue`、`TodayOverviewWorkspace.vue` 和主窗口事件入口改为打开弹框，不再以输入框承担开始/切换。
- 待办编辑：`PlanListEditor.vue` 保持现有页面布局与主要交互，只考虑复用其事项保存能力，不升级为执行列表。
- 事项选择：`TaskSelectControl.vue` 继续服务手动补录、工时分配和未归属处理等非计时场景；计时开始/切换不再依赖它的输入式交互。
- 状态与领域：复用现有事项保存、`store.transitionTimer`、暂停、继续、停止和未归属时间处理，不新增 SQLite/Supabase 表或同步协议。
- 样式与验证：新增高密度弹框、行内保存状态、备注浮层、更多菜单、窄窗口与键盘操作验证，并回归全部计时入口使用同一弹框。
