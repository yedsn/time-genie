# Proposal

## Why

当前待办编辑与事项计时分散在不同页面，用户在工作过程中新增、修改或删除事项后，仍需要进入计时入口再次选择事项，打断了“边整理事项、边执行计时”的连续流程。需要让当前主体的进行中事项列表直接承担日常执行与计时切换，同时把原计时页收敛为时间记录处理页面。

## What Changes

- 将导航中的“待办”升级为“执行”，在当前主体的全部进行中事项列表中统一提供行内编辑、层级与排序管理、完成状态、预计/实际用时和计时操作。
- 让每个可计时叶子事项始终展示开始、切换或当前计时状态；正在计时的事项行高亮并实时展示本段时长，切换事项继续复用现有原子计时转换与待归属语义。
- 在执行列表中提供紧凑的当前计时或未归属时间状态；未归属时间继续使用现有处理弹框，开始任意事项时仍直接丢弃当前未归属时间，不自动分配、不保留待处理记录。
- 保留事项行内新增、改名、删除、新增子项、拖动排序和预计设置，并让新建的可计时事项无需离开列表即可开始计时。
- 将原“计时”导航和页面改为“时间记录”，移除其重复的主计时选择区，保留历史记录、停止后的归属确认、手动补录、时间修正、工时分配、特殊时间处理和导出。
- 保留顶部全局计时条和公共事项选择器，供用户在今日概览、报告、设置和时间记录等页面快速开始或切换事项。
- 不新增“今日执行表”，不改变当前主体范围、两级事项规则、最终实际用时口径、计时停止确认或云端同步协议。

## Capabilities

### New Capabilities

- `execution-list`: 定义将当前主体的进行中事项管理与计时控制合并为执行列表，以及时间记录页面、全局快捷计时和未归属时间之间的职责边界。

### Modified Capabilities

无。项目当前没有已归档主规格，本变更以新的执行列表能力承接现有待办与计时页面的组合行为。

## Impact

- 前端导航与页面：`src-ui/src/views/MainWorkbench.vue` 调整页面名称和职责；`PlanListEditor.vue` 增加常驻计时状态与操作；`TimeTrackingWorkspace.vue` 移除重复的主计时区并保留时间记录工具。
- 前端状态与组件：复用 `store.transitionTimer`、暂停、继续、停止和现有事项保存能力；按需抽取执行行的计时展示纯逻辑，并复用 `UnassignedTimeIndicator.vue`、`GlobalTimerBar.vue` 和停止确认组件。
- 样式与响应式：`src-ui/src/styles.css` 调整执行列表列布局、活动行、常驻操作、窄窗口和父子事项展示。
- 领域与数据：原则上不新增 SQLite/Supabase 表或 Rust 业务协议；最终实际用时继续来自已确认分配，运行中时长只作为实时执行状态展示。
- 验证：覆盖空闲开始、活动切换、暂停/继续/停止、父项不可计时、运行中实时展示、未归属时间直接清除、时间记录职责收敛、窄窗口及现有事项编辑回归。
