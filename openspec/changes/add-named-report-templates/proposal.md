# Proposal

## Why

当前报告模板虽然已经支持日报、周报、月报以及主体级覆盖，但每种类型和主体只能保存一份模板，且必须从已有报告进入设置。用户无法维护“标准日报”“精简日报”“客户周报”等多种格式，也无法在生成报告时明确选择模板。

## What Changes

- 新增统一的报告模板库，允许日报、周报和月报分别创建多份带名称、说明和排序的全局模板。
- 每种报告类型允许设置且必须保持一份默认模板；创建报告时自动预选默认模板，并允许用户为本次报告改选其他同类型模板。
- 报告保存所选模板 ID；重新生成时继续使用原模板的最新内容，而不是自动切换到新的默认模板。调整报告范围时允许更换模板。
- 模板管理支持新建、编辑、复制、删除、设置默认、Markdown 实时预览，以及按报告类型展示可用占位符并插入光标位置。
- 模板面向工作空间内所有主体通用，不再创建新的主体专属模板。
- **BREAKING**：移除“每个报告类型与主体最多一份模板”的数据约束和按主体自动选择模板的行为，模板读写接口改为列表、详情及显式模板 ID 操作。
- 迁移既有内置模板为“标准日报”“标准周报”“标准月报”并设为各类型默认；迁移既有主体专属模板为全局命名模板，处理重名且保留已有报告的模板引用。
- 本地与云端模式同步模板名称、说明、默认状态、排序、软删除和报告模板绑定，并保持离线与多设备操作最终一致。

## Capabilities

### New Capabilities

- `report-template-library`: 定义多份命名报告模板、每类型默认模板、创建与重新生成时的显式模板选择、占位符编辑以及旧模板迁移和多设备同步行为。

### Modified Capabilities

无。当前 `openspec/specs/` 尚无已同步的报告模板能力。

## Impact

- SQLite：`report_templates` 字段与唯一约束、模板迁移、默认模板约束，以及 `reports.template_id` 的引用与软删除兼容。
- Supabase：`timegenie.report_templates` 表、约束/RLS、实体同步 payload、增量 upsert/delete 和部署 SQL。
- Rust：报告模板 CRUD、默认切换、报告创建/调整/重新生成接口、模板校验与迁移测试。
- Vue：报告页模板管理入口、模板库界面、创建报告模板选择、调整范围模板选择和占位符编辑体验。
- 兼容性：已有报告 Markdown 不被改写；已有报告继续保留原模板 ID，只有用户重新生成时才读取该模板的最新内容。
