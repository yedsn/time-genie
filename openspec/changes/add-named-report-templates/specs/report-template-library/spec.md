# Spec Delta

## Purpose

该能力用于让用户集中管理日报、周报和月报的多份命名模板，在生成报告时自由选择合适格式，并通过每种报告类型的默认模板保持日常操作高效且可预测。

## ADDED Requirements

### Requirement: 按报告类型管理多份命名模板
系统 SHALL 允许工作空间为日报、周报和月报分别保存多份全局命名模板。每份模板 MUST 包含唯一标识、报告类型、名称、可选说明、Markdown 内容、默认状态、内置状态、排序、版本和软删除状态。模板 MUST 对工作空间内所有主体可用，不得因主体不同而隐藏或复制模板。

#### Scenario: 为日报创建第二份模板
- **WHEN** 用户在已经存在“标准日报”的情况下创建名为“精简日报”的日报模板
- **THEN** 系统保存两份独立日报模板，且任意主体创建日报时均可选择“精简日报”

#### Scenario: 同类型模板名称重复
- **WHEN** 用户尝试在同一报告类型中创建或重命名为已有的有效模板名称
- **THEN** 系统拒绝保存并提示模板名称重复，不得覆盖已有模板

#### Scenario: 不同类型使用相同名称
- **WHEN** 日报和周报分别存在名为“标准模板”的模板
- **THEN** 系统允许两份模板同时存在，因为名称唯一性只在同一报告类型内生效

### Requirement: 每种报告类型保持唯一默认模板
系统 SHALL 为日报、周报和月报分别保持且仅保持一份有效默认模板。设置新的默认模板 MUST 原子地取消同类型旧默认模板；多设备并发设置默认模板后 MUST 最终收敛为单一默认模板。

#### Scenario: 设置新的日报默认模板
- **WHEN** 用户将“精简日报”设置为默认模板
- **THEN** “精简日报”成为唯一日报默认模板，原日报默认模板仍保留但不再标记为默认

#### Scenario: 删除默认模板
- **WHEN** 用户尝试删除当前默认模板且同类型仍有其他有效模板
- **THEN** 系统要求或原子指定一个替代默认模板后才完成删除，并保证该类型始终存在唯一默认模板

#### Scenario: 删除最后一份同类型模板
- **WHEN** 用户尝试删除某种报告类型的最后一份有效模板
- **THEN** 系统拒绝删除并提示每种报告类型至少需要保留一份模板

### Requirement: 创建报告时选择模板
创建报告界面 SHALL 在用户选择报告类型后列出该类型全部有效模板，并默认选中该类型的默认模板。用户 MUST 能为本次报告改选其他模板，改选操作不得改变系统默认模板。系统 SHALL 将实际选择的模板 ID 保存到报告。

#### Scenario: 使用默认模板创建报告
- **WHEN** 用户选择日报且未手动更换模板
- **THEN** 系统预选默认日报模板，使用其内容生成报告，并在报告中保存该模板 ID

#### Scenario: 临时选择非默认模板
- **WHEN** 用户创建周报时从默认模板改选“客户周报”
- **THEN** 系统使用“客户周报”生成本次报告，但后续新建周报仍默认选择原默认周报模板

#### Scenario: 切换报告类型
- **WHEN** 用户在创建报告界面从日报切换为月报
- **THEN** 系统只显示月报模板并选择默认月报模板，不得保留不兼容的日报模板选择

### Requirement: 报告保持明确的模板绑定
系统 SHALL 在报告创建后保留所选模板绑定。重新生成报告 MUST 使用该报告绑定模板的最新内容，不得因默认模板变化而自动切换。调整报告范围时，用户 SHALL 能保留当前模板或显式更换为同类型的其他模板。

#### Scenario: 默认模板后来改变
- **WHEN** 报告 A 使用“标准日报”创建，之后“精简日报”被设为默认模板，用户重新生成报告 A
- **THEN** 系统仍使用“标准日报”的最新内容重新生成报告 A

#### Scenario: 修改绑定模板后重新生成
- **WHEN** 用户修改报告 A 所绑定模板的内容后重新生成报告 A
- **THEN** 系统使用该模板的最新内容生成报告，模板修改本身不得自动覆盖报告 A 的已有 Markdown

#### Scenario: 更换报告模板
- **WHEN** 用户在调整报告范围时将报告 A 的模板从“标准日报”改为“客户日报”并确认重新生成
- **THEN** 系统保存新的模板 ID，并使用“客户日报”生成报告内容

#### Scenario: 使用已归档模板重新生成历史报告
- **WHEN** 报告绑定的模板后来被软删除，用户重新生成该历史报告
- **THEN** 系统仍可使用保留的模板内容完成重新生成，但该模板不得出现在新建报告的可选列表中

### Requirement: 提供独立模板管理入口
报告页面 SHALL 提供不依赖已有报告的模板管理入口。模板管理界面 MUST 支持按报告类型查看、新建、编辑、复制、排序、删除和设置默认模板，并展示模板名称、说明、默认状态和内置状态。

#### Scenario: 尚无任何报告时管理模板
- **WHEN** 工作空间尚未创建任何报告，用户进入报告页面并打开模板管理
- **THEN** 系统展示日报、周报和月报模板，用户可以直接创建或编辑模板

#### Scenario: 复制模板
- **WHEN** 用户复制“标准周报”并输入“项目周报”作为新名称
- **THEN** 系统创建内容相同但 ID、名称和版本独立的新模板，且不会自动把副本设为默认

### Requirement: 模板支持占位符编辑和预览
模板编辑器 SHALL 提供 Markdown 内容编辑、实时预览以及与当前报告类型匹配的占位符列表。点击占位符 MUST 插入当前光标位置。系统 MUST 拒绝空模板、未闭合占位符和未知占位符，并在保存前给出明确错误。

#### Scenario: 插入日报占位符
- **WHEN** 用户编辑日报模板并在光标位置点击 `{{今日事项}}`
- **THEN** 系统在光标位置插入该占位符并用示例数据刷新预览

#### Scenario: 使用未知占位符
- **WHEN** 用户保存包含 `{{不存在字段}}` 的模板
- **THEN** 系统拒绝保存并指出未知占位符，不得生成不可预测的报告内容

#### Scenario: 按报告类型过滤占位符
- **WHEN** 用户从日报模板切换到周报模板
- **THEN** 系统优先展示适用于周报的占位符及说明，不得引导用户使用仅适用于日报且无法正确渲染的字段

### Requirement: 迁移既有模板和报告引用
升级时系统 SHALL 将既有模板迁移为全局命名模板。内置日报、周报和月报模板 MUST 分别命名为“标准日报”“标准周报”“标准月报”并成为各类型默认模板；既有主体专属模板 MUST 转换为全局模板且通过稳定的重名处理保留全部内容。已有报告的模板引用和 Markdown MUST 保持不变。

#### Scenario: 迁移内置模板
- **WHEN** 旧数据库中每种报告类型只有一份内置全局模板
- **THEN** 升级后产生三份带标准名称的默认模板，原模板内容和 ID 保持可用

#### Scenario: 迁移多个同名主体模板
- **WHEN** 不同主体各有一份日报专属模板且迁移后的候选名称重复
- **THEN** 系统使用包含原主体名称和稳定序号的唯一名称保留全部模板，不得覆盖任何模板内容

#### Scenario: 保留已有报告内容
- **WHEN** 已有报告引用旧模板并包含用户手动编辑的 Markdown
- **THEN** 升级不得改写报告 Markdown、生成次数或模板 ID

### Requirement: 本地与云端模板库保持一致
本地模式 SHALL 完整支持模板库而不依赖云服务。云端模式 SHALL 同步模板 CRUD、默认状态、排序、软删除和报告模板绑定；离线写入、重复消息和乱序增量 MUST 通过版本和确定性约束最终收敛，且模板同步不得阻塞前台编辑。

#### Scenario: 离线创建模板后恢复联网
- **WHEN** 用户离线创建一份命名模板并将其设为默认，随后恢复联网
- **THEN** 系统在后台上传相关变化，其他设备最终获得同一模板和唯一默认状态

#### Scenario: 两台设备并发设置默认模板
- **WHEN** 两台设备同时将同一报告类型的不同模板设置为默认
- **THEN** 云端只形成一个权威默认结果，两台设备最终显示相同默认模板且不产生两个默认项
