# Proposal

## Why

当前每个主体的已完成事项折叠在进行中待办下方，并随工作台一次性全部加载。随着历史事项持续累积，已完成区域会越来越靠下，页面长度、加载量和前端计算成本也会持续增长，不利于用户聚焦当前工作。

## What Changes

- 在每个主体的待办工作台中增加“进行中”和“已完成”两个标签，默认显示“进行中”。
- “进行中”仅展示未完成事项，继续保留树形层级、新增、编辑、拖动排序、缩进和开始计时等现有操作。
- 移除进行中列表底部现有的“已完成”折叠区域，不再随主体工作台一次性加载全部完成历史。
- “已完成”使用独立的历史列表，按实际完成时间倒序展示，最新完成的事项排在最前面。
- 已完成事项按主体进行后端分页，默认每页 20 条，并展示事项原层级路径、完成时间和累计用时。
- 已完成历史仅包含真正进入 `done` 状态的普通事项；重复事项的每日完成轮次不进入该列表、计数或分页。
- 已完成事项支持恢复为未完成、编辑和删除；恢复后从历史页移除并重新进入进行中列表，当前页变空时自动回到上一页。

## Capabilities

### New Capabilities

- `task-status-tabs`: 定义主体待办的进行中/已完成标签、完成历史排序与分页、普通事项与重复事项轮次的边界，以及恢复后的列表联动。

### Modified Capabilities

无。当前项目尚未建立主规格目录，本变更新增主体事项状态标签能力。

## Impact

- 前端待办：调整 `MainWorkbench.vue`、`PlanListEditor.vue` 和工作台状态，拆分进行中树与已完成历史列表。
- 前端服务：增加按主体分页查询已完成事项的接口类型、加载状态、总数和页码管理。
- Tauri/Rust：扩展事项查询，返回 `completedAt`，并提供按主体、完成时间倒序的普通已完成事项分页结果。
- 数据：复用现有 `tasks.completed_at` 和主体完成时间索引，不新增数据库表或迁移；重复事项轮次继续保存在 `task_occurrences` 中。
- 同步：不改变现有 SQLite/Supabase 状态模型，完成、恢复、编辑和删除继续沿用现有同步操作。
- 测试：增加分页顺序、主体隔离、重复轮次排除、恢复后页码回退和进行中列表不加载完成历史的验证。
