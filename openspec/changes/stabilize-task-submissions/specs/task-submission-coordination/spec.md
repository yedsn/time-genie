# Spec Delta

## Purpose

该能力用于协调待办事项的连续编辑与版本敏感操作，确保同一事项的请求不会并发、最后一次有效修改不会被丢弃，并在自动保存体验不变的前提下减少不必要的重复写入。

## ADDED Requirements

### Requirement: 同一事项的提交必须串行执行
系统 SHALL 以逻辑事项为粒度协调提交，并 SHALL 保证任一时刻同一逻辑事项最多只有一个持久化请求正在执行；不同事项的提交不得因该约束而被全局串行化。

#### Scenario: 同一事项连续触发保存
- **WHEN** 同一事项在前一次保存完成前再次触发保存
- **THEN** 系统不并发发送第二个持久化请求，并在前一次请求结束后继续处理待提交状态

#### Scenario: 不同事项同时保存
- **WHEN** 两个不同事项分别触发保存
- **THEN** 系统允许它们独立推进，且一个事项的等待状态不阻塞另一个事项

### Requirement: 等待中的编辑必须合并为最新状态
系统 SHALL 将同一事项等待提交的多次字段编辑合并为该事项的最新完整可保存状态，并 SHALL 保证在编辑停止后最终状态被持久化。短合并窗口 MUST 仅作为减少重复写入的优化，不能作为防止丢失更新的唯一机制。

#### Scenario: 合并窗口内修改多个字段
- **WHEN** 用户在短时间内依次修改同一事项的标题、预计日期和预计时长
- **THEN** 系统提交包含这些字段最新值的事项状态，且不得遗漏任一最终修改

#### Scenario: 保存执行期间再次修改
- **WHEN** 一个事项的保存请求正在执行且用户再次修改该事项
- **THEN** 系统在当前请求成功后使用其返回的最新版本继续提交修改后的最新状态

#### Scenario: 持续编辑超过合并窗口
- **WHEN** 用户对同一事项的编辑持续时间超过短合并窗口
- **THEN** 系统仍保持请求串行，并最终持久化最后一次有效修改

### Requirement: 版本敏感操作必须先冲刷待提交编辑
系统 SHALL 在执行依赖事项当前版本、当前身份或当前字段值的即时操作前，完成该事项尚未落盘的编辑提交。即时操作本身 SHALL 不受普通字段编辑的合并窗口延迟。

#### Scenario: 编辑后立即完成事项
- **WHEN** 用户修改事项后立即将其标记为完成
- **THEN** 系统先持久化最新编辑，再使用更新后的事项版本执行完成操作

#### Scenario: 编辑后立即删除事项
- **WHEN** 用户修改事项后立即删除该事项
- **THEN** 系统先处理该事项待提交编辑，再使用当前持久化身份和版本执行删除，且不得在删除后补发编辑请求

#### Scenario: 编辑后立即调整结构
- **WHEN** 用户修改事项后立即进行排序、拖动、缩进或父级变更
- **THEN** 系统先持久化最新编辑，再基于更新后的版本执行结构操作

#### Scenario: 编辑后立即开始计时
- **WHEN** 用户修改事项后立即以该事项开始或切换计时
- **THEN** 系统在计时引用该事项前确保其最新编辑和持久化身份可用

### Requirement: 新建事项的逻辑身份必须跨 ID 替换保持稳定
系统 SHALL 在新建草稿从临时 ID 替换为持久化 ID 时保留其提交队列归属，并 SHALL 将创建期间发生的后续编辑提交到创建成功后的事项。

#### Scenario: 创建请求期间继续编辑
- **WHEN** 新建事项的创建请求正在执行且用户继续修改该事项
- **THEN** 系统在创建成功后将待提交最新状态应用到返回的持久化 ID，而不是丢弃修改或再次创建事项

#### Scenario: 创建后立即执行版本敏感操作
- **WHEN** 新建草稿已触发创建且用户立即完成、移动或开始计时
- **THEN** 系统等待创建取得持久化 ID 和版本后再执行对应操作

### Requirement: 提交失败不得被静默吞掉
系统 SHALL 将保存失败反馈给调用方，停止依赖该失败提交的即时操作，并 SHALL 保留界面中的最新可编辑值，以便用户重试或系统重新加载权威状态。

#### Scenario: 字段保存失败
- **WHEN** 一个事项的持久化请求失败
- **THEN** 系统向现有错误处理链路返回失败，不将该事项错误标记为已保存，也不静默丢弃最新编辑值

#### Scenario: 冲刷失败后执行即时操作
- **WHEN** 即时操作前的待提交编辑冲刷失败
- **THEN** 系统不执行该即时操作，并向用户显示相应失败信息
