# Spec Delta

## Purpose

定义 TimeGenie 在直连云端、窗口冷启动和大事项集场景下的响应性边界，使网络延迟、非当前页面依赖和数据规模增长不会把整个桌面应用表现为卡死或持续无响应。

## ADDED Requirements

### Requirement: 云端业务操作不得阻塞应用控制面

系统 MUST 在云端查询或 mutation 等待网络响应期间，保持窗口显示、隐藏、移动、关闭以及其他不依赖该业务结果的轻量命令可继续处理。系统 MUST 对云端并发工作使用受控执行资源，避免一组慢请求无限占用处理能力。

#### Scenario: 慢查询期间窗口仍可响应
- **WHEN** 一个云端业务查询处于网络等待或超时重试阶段
- **THEN** 用户执行窗口显示、隐藏、移动或关闭操作时，系统仍可处理该操作，而无需等待业务查询完成

#### Scenario: 多个慢请求受控并发
- **WHEN** 主窗口和悬浮窗同时触发多个慢云端请求
- **THEN** 系统限制阻塞工作的并发占用，并且不因请求数量增长而使所有轻量命令失去执行机会

### Requirement: 云端连接资源必须复用并正确失效

系统 SHALL 对相同有效 Supabase 配置复用 HTTP 连接资源。配置、账户会话或隔离边界发生变化时，系统 MUST 使不再适用的客户端状态失效，并且不得把一个配置或测试上下文的连接状态错误复用于另一个上下文。

#### Scenario: 连续请求复用连接资源
- **WHEN** 同一 Supabase 配置和会话连续执行多个查询或 mutation
- **THEN** 系统复用已建立的 HTTP 客户端及其连接池，而不是为每次业务请求重新初始化客户端

#### Scenario: 配置变化后不复用旧客户端
- **WHEN** 用户修改 Supabase 地址或 anon key，或者切换账户及测试隔离上下文
- **THEN** 后续请求使用与新上下文匹配的客户端，旧客户端不再承载这些请求

### Requirement: 窗口初始化必须遵守请求预算

系统 MUST 合并同一轮窗口初始化中的等价工作区上下文读取。主窗口首次初始化 SHALL 至多执行一次工作台 bootstrap；悬浮窗首次展示 SHALL 只请求其计时与未归属展示所需的数据，并且不得为未展示的报告、设置或完整待办页面发起加载。

#### Scenario: 主窗口冷启动不重复 bootstrap
- **WHEN** 用户启动应用并首次显示主窗口
- **THEN** 日历、主体及工作区上下文从同一个初始化结果复用，该轮初始化至多发起一次工作台 bootstrap

#### Scenario: 悬浮窗首次展示使用最小数据集
- **WHEN** 悬浮窗在主窗口未完成加载或未显示时首次打开
- **THEN** 系统只加载当前计时、必要事项标签和未归属状态，不加载报告、备份、云端历史或设置页面数据

### Requirement: 窗口和重量页面必须按需加载

系统 SHALL 将主窗口与悬浮窗的前端依赖边界分离，并按当前窗口及可见页面加载重量功能。悬浮窗初始执行路径 MUST NOT 包含仅由主窗口页面使用的报告编辑器、备份、云端历史和设置页面实现。

#### Scenario: 悬浮窗入口不加载主窗口重量功能
- **WHEN** 应用仅创建或显示悬浮窗视图
- **THEN** 悬浮窗初始代码路径不执行主工作台及其重量页面模块

#### Scenario: 用户进入重量页面时再加载功能
- **WHEN** 用户首次进入报告、设置或备份相关页面
- **THEN** 系统按需加载对应实现并提供可识别的加载状态，已加载的计时和工作台交互保持可用

### Requirement: 大事项集必须具备可重复的性能门槛

系统 MUST 提供可重复的 1,000 条和 5,000 条事项基准，至少覆盖待办页初始呈现、事项搜索或筛选、计时事项面板打开和列表更新。基准 MUST 记录数据生成方式、运行环境和可比较指标；若 5,000 条基准超过项目设定的交互阈值，系统 MUST 使用虚拟列表、分段渲染或等价机制限制单次 DOM 与响应式工作量。

#### Scenario: 基准验证事项规模增长
- **WHEN** 在固定环境中分别运行 1,000 条和 5,000 条事项基准
- **THEN** 输出各关键交互的耗时和渲染规模，并能与后续版本重复比较

#### Scenario: 超过阈值时启用有界渲染
- **WHEN** 5,000 条事项场景的关键交互超过已记录的验收阈值
- **THEN** 实现采用有界渲染策略，并验证视口外事项不会全部同时创建为活动 DOM 行

### Requirement: 性能优化不得改变数据语义

系统 MUST 保持 Supabase 作为云端模式唯一业务权威，并保持 expected version、workspace epoch、Realtime 失效、断网只读和本地 SQLite 模式的既有行为。后台执行、请求合并和延迟加载不得把 mutation 失败显示为成功，也不得遗漏更高版本的远端变化。

#### Scenario: 后台执行仍返回真实业务结果
- **WHEN** 云端 mutation 在后台执行资源中成功、冲突或失败
- **THEN** 前端收到与优化前等价的权威成功结果或结构化错误，并按既有规则更新或恢复界面状态

#### Scenario: 延迟加载不改变远端收敛
- **WHEN** 一个尚未加载的页面对应领域收到更高 change sequence 的远端变化
- **THEN** 系统记录该领域失效，并在页面进入时执行一次权威加载以收敛到最新状态
