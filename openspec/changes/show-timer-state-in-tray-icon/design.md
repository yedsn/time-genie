# Design

## Context

见 `proposal.md` 与 `specs/tray-timer-status-icon/spec.md`。TimeGenie 当前在启动时用 `default_window_icon` 创建 Tauri 托盘，此后只通过每两秒读取 `get_timer_state` 更新右键菜单的可用状态，不更新图标或 Tooltip。前端计时命令、托盘菜单命令和云端计时命令存在多个状态变化入口，因此只在某一个 UI 入口刷新会产生展示滞后。

Windows 上另有一条八秒后检测并注册的原生备用托盘路径。它目前从 `icon.ico` 创建一次 `HICON`，注册后不再修改。动态托盘能力必须同时覆盖这两条路径，并避免动态原生图标句柄泄漏。

TokenBall 已验证可用 `tauri::image::Image` 在内存中绘制 32x32 RGBA 图像，再通过 `set_icon` 与 `set_tooltip` 更新托盘。TimeGenie 可以复用这种技术思路，但状态语义改为计时器的 `running`、`paused` 与无活动记录。

## Goals / Non-Goals

**Goals:**

- 建立一个集中式托盘展示快照，使图标、Tooltip 和菜单状态来自同一次权威计时读取。
- 用纯内存绘制生成小尺寸状态图标，不引入新的图像处理依赖或额外资源文件。
- 让计时动作成功后即时刷新，并保留低频周期校准覆盖恢复、同步和遗漏事件。
- 让 Tauri 托盘与 Windows 原生备用托盘共享状态映射、样式规范和 Tooltip 文案。
- 将图标样式作为设备级设置保存，不同步到其他设备。

**Non-Goals:**

- 不在托盘图标中表达事项的待办、进行中或已完成状态。
- 不显示百分比、数字计时、进度环或每秒动画。
- 不允许上传自定义托盘图片，也不改变应用窗口图标和安装包图标。
- 不改变悬浮面板、右键菜单动作、计时状态机或数据库表结构。

## Decisions

### 1. 使用统一的托盘展示快照

增加一个内部展示模型，将权威计时记录和设备设置归一化为：图标样式、三态状态、显示标签、累计时长、Tooltip 文本和菜单动作可用性。一次刷新只读取一次计时状态，然后同时更新菜单、图标与 Tooltip，避免不同组件分别查询后短暂出现状态不一致。

如果状态读取失败，刷新返回错误并保留最近一次有效展示，不把读取失败解释为空闲。现有周期刷新仍继续执行，使临时错误恢复后可以自动修正。

备选方案是保留菜单刷新函数，再为图标增加独立轮询。它改动较小，但会重复访问数据库并允许两个托盘表面显示不同状态，因此不采用。

### 2. 动态样式在 Rust 中绘制 32x32 RGBA 图像

“状态圆标”和“极简色块”由无平台依赖的纯函数输出 RGBA 缓冲区，再转换为 Tauri `Image`。状态圆标以圆形底和播放、暂停、空闲轮廓同时编码状态；极简色块保持较少装饰，但仍保留三种不同内部轮廓，颜色不作为唯一信号。

建议颜色固定为执行绿、暂停橙黄、空闲中性灰。图标保留透明外缘、浅色高光和足够对比度，以兼容 Windows 深浅任务栏及 16px 缩放。“应用图标”样式直接复用现有默认窗口图标，不参与动态绘制。

备选方案是准备三组或六组静态 PNG/ICO。静态资源更容易直观看到原稿，但需要维护多套平台资源，难以复用到原生备用托盘的运行时尺寸转换，也不利于集中测试像素边界，因此采用程序绘制。

### 3. 即时刷新与周期校准并存

建立 `refresh_tray_presentation` 一类统一入口，在以下时机调用：应用创建托盘后、托盘菜单计时动作成功后、设置保存后，以及能够获得 `AppHandle` 的计时状态变化入口。现有两秒菜单刷新循环改为统一展示校准循环，作为跨窗口、云端同步、系统恢复和事件遗漏的兜底。

Tooltip 中的累计时长不需要每秒刷新。执行中状态在周期校准时更新显示时长，暂停状态保持已累计有效时长；这避免为仅在悬停时可见的文本引入高频任务栏更新。

前端保存 `tray_icon_style` 后，通过一个后端刷新命令或设置更新后的事件立即应用样式。周期校准仍会验证最终结果。

备选方案是只依赖事件。当前计时变更分布在本地命令、云端命令、托盘命令及恢复协调路径，首版要求所有路径严格发出事件会增加遗漏风险，因此保留周期校准。

### 4. 图标样式使用设备级通用设置存储

使用现有 `device_settings` 键值表保存 `tray_icon_style`，支持 `status-orb`、`minimal` 和 `app-icon` 三个值，默认 `status-orb`。前端加载设置时对值做白名单归一化，后端绘制前再次归一化，未知值安全回退到默认样式。

无需新增 SQLite migration，因为设置表已经支持任意键；数据库初始化默认值中加入该键可使新设备显式拥有默认设置。该设置只作用于当前设备，不进入 Supabase 共享配置。

备选方案是将设置放入共享设置，使多设备风格一致。托盘可用性、操作系统主题和用户偏好通常具有设备属性，现有托盘设置也属于设备级，因此不采用共享范围。

### 5. Windows 原生备用托盘通过消息通道运行时更新

原生托盘线程继续拥有窗口、当前 `HICON` 和 `NOTIFYICONDATAW`。主应用需要刷新时，将与 Tauri 托盘相同的状态快照或已生成 RGBA 数据发送给该线程；线程在自身消息循环中创建新 `HICON`，调用 `Shell_NotifyIconW(NIM_MODIFY, ...)` 更新 `NIF_ICON | NIF_TIP`，成功后释放旧的动态句柄。

不能从任意异步线程直接替换原生线程维护的句柄状态。使用 Windows 消息或受控通道将更新串行化，可以避免竞态和在 Shell 尚未注册时更新。原生备用托盘未启动时，发送更新是无操作；启动后先读取最近一次快照完成初始展示。

备选方案是为每个状态准备静态 `.ico` 并按路径重新加载。它仍需要正确释放句柄，而且会让两套绘制逻辑和资源同步维护，因此不采用。

### 6. Tooltip 由状态快照统一生成

Tooltip 文案使用当前 `TimeEntryDto` 的 `state`、`label` 和 `duration_seconds`。执行中和暂停状态格式为状态、标签、格式化时长三段；空闲状态使用固定文案。若计时没有关联具体事项，`label` 仍是现有记录的权威回退名称，不额外查询事项表。

Windows 原生托盘的 `szTip` 有固定长度，编码前按 UTF-16 可用容量安全截断并保留结尾空字符；Tauri 托盘可以使用完整文案。为了两者语义一致，主要信息顺序保持相同。

## Risks / Trade-offs

- [32px 图标在 Windows 实际显示为 16px 时内部图形模糊] → 使用粗线条、整数附近坐标和少量形状，并在 100%、125%、150% 缩放及深浅任务栏实际检查。
- [两秒周期刷新频繁重建相同图标和原生句柄] → 缓存最近一次展示键，仅当样式、状态、标签或 Tooltip 显示时长发生有效变化时调用系统更新；菜单可用状态仍可独立校准。
- [设置保存成功但即时刷新失败] → 设置继续持久化，保留最近一次图标并由下一次周期校准重试，不阻止用户保存其他设置。
- [Windows 原生备用托盘句柄泄漏或过早释放] → 由原生线程单点拥有和释放动态 `HICON`，只在新图标成功创建并提交后销毁旧句柄，退出时释放当前句柄。
- [Tauri 托盘和原生备用托盘短暂同时存在] → 继续沿用现有“仅在 Tauri 托盘不可见时启动备用托盘”的判断；若异常并存，两者仍使用同一快照，至少保证展示一致。
- [状态读取调用会触发跨日协调写入] → 复用现有托盘菜单已经使用的权威读取与周期，不额外提高查询频率。

## Migration Plan

1. 先增加纯状态映射、Tooltip 和 RGBA 绘制模块及测试，不改变现有托盘显示。
2. 将 Tauri 托盘的菜单刷新收敛为统一展示刷新，并接入三种样式和设备设置。
3. 在设置页增加样式选择和即时应用入口，默认迁移为“状态圆标”。
4. 扩展 Windows 原生备用托盘的动态更新与句柄生命周期管理。
5. 接入计时动作后的即时刷新，保留周期校准，并完成自动化与实际 Windows 验收。

回滚时可将默认及现有设置解释为 `app-icon` 并恢复静态托盘创建逻辑；新增设置键可以保留且不会影响旧版本，未涉及业务数据迁移。
