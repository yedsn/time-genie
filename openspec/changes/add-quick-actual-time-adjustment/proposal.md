# Proposal

## Why

计划页已经可以快速分配“今日预计”，但用户发现实际计时有偏差时，仍必须切换到计时页面手动补录或重新修正记录。对于正在计时、已暂停或当天已经完成的事项，这种操作打断当前工作，也不能直接表达“今天最终实际应该是多少分钟”。需要在计划页提供按当前主体集中调整今日实际的入口，并把调整作为可追溯记录保存。

## What Changes

- 在计划页“分配今日预计”左侧增加“调整今日实际”入口，打开类似的批量编辑面板。
- 面板以打开时的今日实际分钟为基线，允许用户为叶子事项输入“今日最终实际应该是多少分钟”。
- 父事项只展示子事项实际合计，不提供输入框；进行中、暂停中和今天已完成的叶子事项都允许调整。
- 保存前展示当前值、目标值和固定差额；统一使用一个可选备注。
- 正差额创建正向补录，负差额创建负向实际调整记录，零差额不创建记录；不修改原始计时记录。
- 实际调整记录出现在时间记录页面，明确标记来源、正负分钟和备注；允许删除撤销，不允许直接编辑旧调整。
- 今日概览、计划页事项实际、日报、趋势和工时导出统一使用原始工时叠加调整后的最终实际。
- 调整记录支持本地优先保存、事务回滚、版本/冲突保护和现有云同步。

## Capabilities

### New Capabilities

- `quick-actual-time-adjustment`: 定义计划页快速调整今日最终实际、正负差额记录、父子汇总、时间记录展示与撤销语义。

### Modified Capabilities

无。项目当前没有已归档的主规格目录；本能力独立定义新的计划页和时间记录行为。

## Impact

- 前端计划页：`src-ui/src/components/PlanListEditor.vue` 增加入口、叶子事项实际快照、目标分钟编辑、变化摘要和保存状态。
- 前端状态与 Tauri 封装：`src-ui/src/store.ts`、`src-ui/src/services/tauri.ts` 增加今日实际快照、批量调整和删除撤销协调。
- 时间记录页面：`src-ui/src/components/TimeTrackingWorkspace.vue` 增加调整记录展示和删除确认，并区分普通计时/补录。
- Rust 时间领域：`src-tauri/src/time_tracking.rs` 或独立模块增加调整记录模型、批量事务命令、删除命令和汇总读取。
- 数据模型与同步：本地 SQLite、Supabase schema、云同步 outbox 和导出查询增加带正负分钟的实际调整实体；原始 `time_entries`、`time_allocations` 保持不可变。
- 验证：覆盖叶子/父项、空计划、正在计时、已完成事项、增减调整、零差额、下限为零、删除撤销、并发冲突、事务回滚、今日概览/日报/导出和双设备同步。
