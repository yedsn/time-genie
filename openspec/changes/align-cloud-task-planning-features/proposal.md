# Proposal

## Why

TimeGenie 的本地模式已经支持按日预估和重复事项，但云端模式仍明确拒绝这两类写入，导致用户切换到 Supabase 后丢失核心的事项规划能力。当前云端表和全量快照已包含相关数据，需要补齐日常增量写入、跨设备同步和冲突处理，使存储模式只影响数据落点，不改变工作空间业务功能。

## What Changes

- 云端模式支持为事项设置、修改和清空指定日期的按日预估，并同步到同一账号的其他设备。
- 云端模式支持创建、修改和关闭重复规则，覆盖每天、工作日和每周指定星期，行为与本地模式一致。
- 重复规则、按日预估和重复事项每日轮次统一接入本地 SQLite 事务、同步 outbox、Supabase 原子写入、增量拉取和版本冲突处理。
- 重复事项的完成、恢复、计时、工时分配、日报与明日计划在本地和云端模式保持相同语义。
- 移除前后端中“云端模式暂不支持按日预估或重复事项”的限制和提示。
- 明确功能对齐只适用于工作空间业务数据；托盘行为、本机文件路径、凭据和其他设备级配置继续只保存在本机。

## Capabilities

### New Capabilities

- `cloud-task-planning-parity`: 定义按日预估、重复规则和每日轮次在本地与云端模式下的一致行为、离线写入、跨设备同步及冲突处理。

### Modified Capabilities

无。当前主规格目录尚无已归档能力，本变更以新的云端事项规划对齐能力补充行为约束。

## Impact

- Rust：`tasks.rs`、`recurring.rs`、`cloud_sync.rs` 及相关命令需要为按日预估和重复规则增加云端事务入队、载荷读取、推送及冲突处理。
- Supabase：`cloud_apply_patch`、实体版本检查、复合实体身份和 schema 集成测试需要支持 `task_daily_estimate` 与 `task_recurrence_rule`。
- Vue：移除云端模式限制，保持现有按日预估编辑和重复设置交互在两种模式下可用，并展示统一的同步失败或冲突反馈。
- 同步协调：实现需建立在 `reduce-timer-sync-conflicts` 变更形成的 outbox 顺序、依赖和重试约束之上，避免引入独立同步路径。
- OpenSpec：旧的 `add-recurring-tasks` 变更中“第一版不接入 Supabase”的限制由本变更后续能力覆盖，但不改变其既有本地重复事项语义。
