# Proposal

## Why

计时页面已经能够按日期浏览完整时间记录，但用户无法把一段日期范围内的工时归属整理为可交付、可汇总的 Excel。需要提供以工时归属行为核心的导出能力，让用户选择期间和保存位置，并明确控制是否把未归属、休息等特殊时间纳入文件与统计。

## What Changes

- 在计时模块增加“导出”入口和紧凑的导出弹框，可选择开始日期与结束日期，默认使用工作空间当前月份。
- 导出前根据所选日期范围和“包含特殊时间”选项预览最终行数与合计分钟；开始日期不得晚于结束日期。
- 通过系统原生“另存为”窗口选择保存位置，生成 `.xlsx` 文件；用户取消选择时不创建文件，也不视为错误。
- Excel 仅包含一个“工时归属”工作表，每条正分钟事项归属占一行，字段包含工作日期、主体、事项、用时、时间段和备注。
- 默认不包含特殊时间，只导出已经归属到具体事项的工时；一段时间分配给多个事项时按归属拆成多行。
- 勾选“包含特殊时间”后，将工作记录尚未归属的剩余分钟导出为“未归属”行，并将休息记录导出为“休息”行；统计严格只计算最终写入 Excel 的行。
- 已删除或标记为无效的时间永不导出；没有符合条件的行时不生成空文件，并向用户提示。
- 本地模式和云端模式均从本地 SQLite 权威缓存生成导出，不请求 Supabase、不产生同步队列操作，也不增加待保存数量。

## Capabilities

### New Capabilities

- `time-allocation-export`: 定义计时模块按日期范围预览并导出单工作表 Excel、事项归属行与可选特殊时间行、统计和文件保存行为。

### Modified Capabilities

无。项目当前没有已归档的主规格，本变更以新能力规格描述导出行为。

## Impact

- 计时页面：`src-ui/src/components/TimeTrackingWorkspace.vue` 和 `src-ui/src/styles.css`，增加导出入口、日期范围与特殊时间选项、预览统计和导出状态。
- 前端调用：`src-ui/src/services/tauri.ts`，增加导出预览和执行命令类型。
- Rust/Tauri：新增时间归属导出模块或扩展 `src-tauri/src/time_tracking.rs`，从 SQLite 按日期范围构建扁平导出行并生成 Excel。
- 桌面能力：`src-tauri/capabilities/default.json` 增加系统保存对话框权限；复用已安装的 `tauri-plugin-dialog`。
- 依赖：Rust 增加 Excel 写入库，例如 `rust_xlsxwriter`；不增加前端 Excel 库。
- 数据与云端：不修改 SQLite 或 Supabase 表结构，不上传导出文件，不记录同步 outbox，也不导出密码、Token 等敏感配置。
- 测试：覆盖月份默认值、日期校验、分配拆行、主体与事项映射、特殊行开关、进行中快照、合计、空结果、文件生成及本地/云端只读一致性。
