# Design

## Context

见 `proposal.md` 与 `specs/inline-timer-task-creation/spec.md`。当前 `TaskSelectControl.vue` 同时负责搜索已有事项和快速创建：未匹配文本会在 Enter 或失焦时调用 `store.addQuickTask`，该方法只能创建顶层临时事项。`GlobalTimerBar.vue` 在空闲状态展示选择器，存在活动计时时只展示名称、时长和暂停/结束按钮，因此无法在原地选择或创建下一个事项。

前端 `store.startTimer` 会先持久化尚未保存的事项，再调用计时开始命令；计划页的事项切换则先调用 `stopTimer`、再调用 `startTimer`。两者都是多个独立事务：前者可能留下已创建但未开始的事项，后者可能在停止成功、开始失败时失去原活动计时，而且普通停止会触发阻断式归属确认。Rust 已有事项父级校验、工作日期、计时幂等、单活动计时、跨日切片、outbox 和云端协调能力，但缺少表达“创建并开始”及“切换”的组合业务命令。

## Goals / Non-Goals

**Goals:**

- 用一个选择器状态机承载搜索已有事项、选择创建类型和选择父级，避免隐式失焦创建。
- 让空闲开始和活动切换通过后端组合命令获得一致时间边界、事务回滚和请求幂等。
- 复用现有事项创建与计时领域校验，不在前端复制父级资格或单活动计时规则。
- 让本地数据库事务、云端操作依赖和前端刷新都以同一个业务结果为准。

**Non-Goals:**

- 不在快速选择器中编辑预计、备注、重复规则、排序或其他完整事项属性。
- 不支持在一次快速操作中创建父事项和子事项组成的新树，也不支持三级事项。
- 不改变已结束计时的最终归属规则；切换只延后其确认入口，不自动把默认事项视为最终分配。
- 不把创建入口重新加入托盘悬浮面板；本变更只覆盖主窗口顶部快速计时入口及复用它的主窗口流程。

## Decisions

### 1. 将选择器改为显式的三阶段状态机

`TaskSelectControl` 区分搜索/创建方式层和父级选择层。用户输入未匹配的新名称后，首层只提供“新建为一级事项”和“新建为二级事项”两个创建动作；已有事项候选仅承担选择事项的职责，不再附带“在此事项下新建”。选择二级创建后进入独立父级列表，并保留名称和已选主体。Esc 从父级列表返回搜索与创建方式层，关闭整个选择器不产生持久化操作。

组件不再自行调用 store 创建事项，而是向使用方发出结构化意图：选择已有事项，或提交 `{ title, subjectId, parentId? }`。这样同一组件可根据外部计时状态决定执行“开始”还是“切换”，也避免输入框 blur 在用户点击父级动作前抢先创建。

备选方案是在输入中约定 `父事项 / 子事项` 语法。它难以处理同名父项、主体和转义，也不容易被用户发现，因此只保留为未来可选增强，不作为本变更入口。

### 2. 父级候选以前端快照展示、后端事务重验

前端根据已加载事项即时过滤当前主体的顶层、进行中、非重复候选，并标注不可用原因；最终资格由后端在组合事务内重新校验。请求携带 `parent_id` 与可选 `expected_parent_version`，避免父项在列表打开后被其他窗口或设备修改却静默创建。

新事项使用 quick 来源、当前工作日期和父项末尾排序。创建规则抽取为可在传入事务上运行的内部函数，供普通快速创建和计时组合命令复用，而不是复制标题、主体、深度、直接实际时间和排序校验。

### 3. 用统一计时转换命令处理已有和新事项

新增面向用户意图的命令，例如 `timer_transition`，请求包含：

- 稳定的 `client_request_id`；
- 当前活动计时 ID 与期望版本，可为空表示期望空闲；
- 目标为已有 `task_id`，或新事项草稿 `{ subject_id, parent_id, expected_parent_version, title }`；
- 可选备注及来源标识。

命令在一个本地事务内获取统一 `transition_at`，完成以下步骤：

1. 协调跨日和远端活动计时状态，并校验客户端看到的当前状态。
2. 若目标是新事项，在事务内创建并获得正式 ID。
3. 若存在不同的当前活动计时，在 `transition_at` 结束其开放 segment 和 entry，但不创建默认分配。
4. 以同一个 `transition_at` 创建目标事项的新运行 entry 和首个 segment。
5. 更新未归属锚点、修订号、幂等结果和 outbox 依赖后提交。

若目标就是当前事项，命令返回 no-op 结果。空闲开始、已有事项切换和新事项创建并切换共用同一命令，避免主窗口、计划页以后继续出现不同的切换语义。

备选方案是前端继续依次调用创建、停止和开始。它无法在响应丢失、版本冲突或第二步失败时恢复原状态，也无法保证毫秒级统一边界，因此不采用。

### 4. 组合结果显式返回前后状态

命令结果返回 `created_task`（若有）、`previous_stop_result`（若发生切换）、`active_entry`、`transition_at` 和是否 no-op。前端以返回值更新当前活动项，并统一刷新事项、今日概览、计时历史和未归属状态。

切换产生的旧计时仍保持待归属语义，但 `store` 不设置会立即打开全局阻断对话框的 `timerStopConfirmationEntryId`。旧记录继续出现在计时页的待处理/历史入口，可由用户稍后确认；界面用轻量提示说明“已切换，上一段计时待确认”。用户主动点击停止按钮仍沿用现有停止确认对话框。

### 5. outbox 使用单条原子转换操作承载内部依赖

本地事务为组合操作生成同一个业务请求 ID，并写入一条 `timer_transition_apply` outbox 操作。payload 按固定结构携带可选的原计时结束镜像、可选的新事项镜像和新计时开始镜像；云端 RPC 在一个数据库事务中严格按“结束原计时 -> 创建新事项 -> 开始新计时”执行。已有目标事项时省略事项镜像，空闲开始时省略原计时镜像。相比三条独立 outbox 记录，这一实现把依赖顺序和回滚边界同时收口到服务端事务，避免前序节点已成功、后序节点冲突所产生的部分远端状态。

云端 RPC 校验活动计时版本、父项版本及资格，并将完整转换结果写入幂等记录。在线和离线 flush 都将整条转换视为一个可重试业务结果；服务端冲突时整笔事务回滚，不会只接受事项或只结束原计时。

### 6. 保持现有快速创建接口兼容

`task_create_quick` 继续供未涉及计时的调用方使用，`TaskSelectControl` 的计时场景改用组合命令。现有直接选择事项、无事项计时、主动停止、暂停和继续接口保持兼容。计划页现有“点击另一事项先停再开”可迁移到同一转换命令，以消除已知中间状态，但不强制改变计划列表的视觉布局。

## Risks / Trade-offs

- [组合命令跨越事项与计时领域，职责较宽] -> 把事项插入、计时结束和计时开始拆为接收同一事务的内部领域函数，外层只负责编排用户意图。
- [切换不立即弹出归属确认，用户可能遗忘上一段记录] -> 在顶部显示非阻断提示，并在计时页保留清晰的待处理入口和数量；不自动创建最终分配。
- [云端 RPC 与本地事务行为漂移] -> 使用共享请求/结果契约和相同场景测试，覆盖父项失效、活动版本冲突、响应丢失和依赖顺序。
- [候选父级列表可能因后台刷新变化] -> 前端只作引导，后端用父级版本和完整资格重验；失败后保留名称并重新加载候选。
- [顶部栏空间有限，活动状态加入选择器可能拥挤] -> 默认仍显示紧凑计时摘要，点击事项名称进入覆盖式/弹出式切换层，不长期展开完整输入框。
- [切换与跨日边界同时发生] -> 先执行现有计时协调并取得最终活动 slice，再以同一转换时间结束当前 slice 和创建新 entry，测试跨日临界点。

## Migration Plan

1. 抽取可共享事务的事项创建、计时结束和计时开始内部函数，并增加组合请求/结果类型及本地测试。
2. 接入 outbox 依赖、云端等价事务和幂等结果，验证在线、离线及双设备冲突。
3. 将选择器改为显式状态机，接入空闲创建并开始、活动创建并切换和已有事项切换。
4. 增加非阻断待归属提示、键盘操作和前端业务逻辑测试，再运行完整类型检查、Rust 测试及手工交互验证。

回滚前端后，新增组合命令可以保留而不影响旧客户端；已创建事项和计时记录均使用现有数据模型，无需数据库回填。若回滚后端，旧客户端路径仍可使用原快速创建和独立计时命令，但不再具备组合原子性。
