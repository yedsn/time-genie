# Verification

## 自动化验收

- Rust 计时转换测试：覆盖空闲创建一级并开始、创建二级并切换、运行中/暂停中切换、选择当前事项 no-op、父级完成或版本冲突整体回滚、跨自然日工作日期、跨日计时链、重复事项 occurrence、单条原子 outbox 和响应丢失重试幂等。
- 隔离双设备测试：设备 A 离线创建并开始后恢复上传，设备 B 增量拉取后同时获得新事项和唯一活动计时；远端活动版本被另一设备改变时，后续切换进入冲突且不留下新活动计时或部分远端状态。
- PostgreSQL 集成测试：实际执行 `timer_transition_apply` 的空闲创建并开始、统一边界切换、重试幂等和冲突回滚，并验证升级补丁可重复执行。
- 前端逻辑测试：覆盖父级资格、空白输入不创建、计时模式失焦不创建、显式一级/二级创建动作及原始草稿保留。
- 全量构建与测试：`npm run typecheck`、`npm run build`、`npm run test:supabase:schema` 和单线程全量 `cargo test` 均通过；真实 Supabase 专用账号测试按项目既有保护规则忽略。

## 界面与键盘验收

- 顶部空闲计时栏保持紧凑布局，输入名称后明确展示“新建为一级事项”和“新建到一级事项下”。
- 进入父级选择时输入框保持原始名称；无一级事项时显示明确空状态；Esc 返回创建方式列表并保留草稿。
- 有效一级事项在搜索候选中提供“在此事项下新建”，无效父级显示不可用原因。
- 点击候选和创建动作期间使用 busy 状态防止重复提交；失败后输入框保留原始名称。
- 活动计时紧凑态保留暂停、继续、主动停止，并可从事项名称或切换按钮打开选择层；切换成功只显示非阻断提示，主动停止仍沿用原确认对话框。

## 验收结论

本次验收使用浏览器界面巡检和临时 SQLite/PostgreSQL 测试数据完成，没有向用户的真实本地数据或真实 Supabase 工作空间写入测试事项。变更满足空闲开始、活动切换、取消不创建、父级并发失效、离线重试、单活动计时和延后归属确认要求。
