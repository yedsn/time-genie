# Proposal

## Why

用户准备开始计时或计时过程中临时想到新事项时，当前快速计时选择器只能把陌生文本创建为顶层事项，无法直接指定一个一级事项作为父级；若要建立正确层级，只能先离开当前流程到计划页创建，再回来开始或切换计时。这个中断会增加漏记、错放层级和继续在旧事项上计时的概率。

## What Changes

- 在主窗口快速计时选择器中，将陌生文本的静默顶层创建改为明确的两步创建流程：首层只提供“新建为一级事项”和“新建为二级事项”。
- 用户选择“新建为二级事项”后，再单独列出当前主体下可作为父级的一级事项，避免在已有事项搜索结果中混入二级创建入口。
- 新事项归属选定主体，默认计划到当前工作日期；快速流程只采集名称和父级，其他属性继续在计划页维护。
- 空闲状态下，创建成功后立即以新事项开始计时；创建或开始失败时不得留下与用户意图不一致的半完成状态。
- 计时进行中允许打开同一选择器执行“创建并切换”，系统在统一时间边界结束当前计时并开始新事项计时。
- 限制父级候选为当前主体内可接收子项的有效一级事项，继续遵守最多两级、重复事项和直接实际时间等现有规则。
- 保留直接选择已有叶子事项开始或切换计时的能力，并补充键盘操作、加载状态和失败反馈。

## Capabilities

### New Capabilities

- `inline-timer-task-creation`: 定义在快速计时选择器中原地创建一级或二级事项，并立即开始或无缝切换计时的交互和一致性要求。

### Modified Capabilities

无。项目当前没有已归档主规格；本变更复用既有事项与计时领域能力，并新增面向快速计时入口的行为规格。

## Impact

- 前端组件：`src-ui/src/components/TaskSelectControl.vue` 增加显式创建动作、父级选择状态和创建模式；`src-ui/src/components/GlobalTimerBar.vue` 在计时状态下提供事项切换入口。
- 前端状态：`src-ui/src/store.ts` 增加带层级的快速创建，以及创建后开始/切换计时的统一操作。
- Tauri 封装与 Rust 领域：复用或扩展事项创建、计时开始/停止能力，并为“创建并开始/切换”提供原子或可幂等的一致性边界。
- 云同步：新事项必须先于引用它的计时记录同步；跨设备仍遵守单活动计时与计时版本校验。
- 验证：覆盖一级/二级快速创建、无效父项、空闲开始、运行中切换、失败回滚、重复提交、键盘操作及本地/云端一致性。
