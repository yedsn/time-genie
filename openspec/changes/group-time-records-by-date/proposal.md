# Proposal

## Why

计时页面目前只查询和展示工作空间当天的时间记录，用户无法在同一页面回看更早日期的计时、补录、休息和未归属处理结果。底层已经按 `work_date` 保存历史记录，因此需要把页面扩展为按日期分组、按有记录日期分页的完整时间记录视图。

## What Changes

- 将计时页面的“今日时间记录”改为包含全部历史正式时间记录的“时间记录”。
- 按工作空间日期倒序分组；每个日期分组完整展示当天所有记录，同一天不得跨页。
- 每页固定显示 7 个有记录的日期，空白日期不占分页名额，并提供总日期数、当前页、上一页和下一页。
- 每个日期分组展示日期标签、记录数、工作分钟、休息分钟和待确认分钟；组内记录按开始时间倒序排列。
- 历史记录继续支持展开、修正时间、调整归属、标记休息或无效；手动补录仍默认写入今天。
- 将历史分页数据与当前计时、今日汇总和今日完成统计隔离，历史记录不得被计入今日指标。
- 本地模式和云端模式都从本地持久化缓存读取同一分页结果；后台同步到达后刷新当前页，不为纯分页查询产生待保存操作。

## Capabilities

### New Capabilities

- `time-entry-history`: 定义时间记录按日期完整分组、按 7 个有记录日期分页、历史记录编辑以及与今日状态隔离的行为。

### Modified Capabilities

无。当前项目尚未建立持久化主规格，本变更以新能力规格承接时间记录历史展示行为。

## Impact

- Rust/Tauri 时间记录查询：`src-tauri/src/time_tracking.rs`，需要增加以日期为分页单位的历史查询和分页汇总 DTO。
- 云端兼容入口：`src-tauri/src/cloud_sync.rs`，保持旧按单日查询兼容，并让新历史查询复用本地缓存。
- 前端调用与状态：`src-ui/src/services/tauri.ts`、`src-ui/src/store.ts`，需要独立维护历史页码、日期分组和汇总，避免污染今日指标。
- 计时页面：`src-ui/src/components/TimeTrackingWorkspace.vue`，需要增加日期组标题、组内记录列表和分页控制。
- 测试：覆盖空白日期跳过、同日不拆页、日期与组内排序、历史编辑刷新、今日统计隔离以及本地/云端一致性。
- 不需要修改 SQLite 或 Supabase 表结构，也不需要新增按秒同步或历史数据迁移。
