# Proposal

## Why

当前托盘悬浮面板承担了主体筛选、事项搜索、候选列表扩展和窗口边界切换等复杂交互，导致实现与使用成本都远高于托盘入口应有的价值。事项选择更适合在主窗口完成，悬浮面板应回归快速查看当前状态和执行少量单步操作。

## What Changes

- **BREAKING** 从托盘悬浮面板移除主体选择、事项输入、候选搜索、临时事项创建和“开始所选事项计时”。
- 将悬浮面板改为固定紧凑尺寸的状态面板，不再为事项候选扩展窗口表面或切换扩展交互区域。
- 正在计时时展示计时状态、累计时长和当前事项，并保留暂停、继续以及“结束并处理”等单步动作。
- 没有活动事项计时时展示未归属时间、今日已记录和待归属摘要；需要选择事项时通过“选择事项并开始”打开主窗口并定位到计时区域。
- 保留“处理未归属时间”和“打开主窗口”入口，复杂编辑、分配和确认流程统一在主窗口完成。
- 继续支持悬停显示、移出三秒关闭、点击外部立即关闭、显示时刷新和手动刷新。

## Capabilities

### New Capabilities

- `tray-status-panel`: 定义简化托盘状态面板的展示内容、允许的单步动作、主窗口导航和关闭交互。

### Modified Capabilities

无。当前项目尚未建立主规格目录，本变更以新的状态面板能力替代先前变更中的复杂事项选择方案。

## Impact

- 前端：简化 `HoverPanel.vue`，移除其对 `TaskSelectControl` 和事项选择模式的依赖，调整固定面板布局与样式。
- Tauri/Rust：移除托盘事项选择的扩展窗口模式、预置大表面、原生裁剪切换及相关边界状态；保留固定窗口定位与指针关闭监控。
- 跨窗口导航：增加或复用打开主窗口并定位到计时选择区域的事件；未归属处理继续复用现有主窗口流程。
- 服务与测试：清理不再使用的窗口模式命令和前端服务接口，更新托盘验证脚本及 Windows 实际交互验收。
- 不改变计时、未归属时间、分配记录、SQLite 或 Supabase 数据结构。
