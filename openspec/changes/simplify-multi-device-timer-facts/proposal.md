# Proposal

## Why

多设备计时当前共用一把工作空间级的「计时写入权」租约：任何在线设备每 30 秒都会续租，于是另一台设备在结束计时或确认未归属时间时会长时间停在「等待计时写入权」。即使通过抢占绕过等待，两台设备各自基于同一段计时产生不同结果时，又会落成需要人工选择的数据冲突（例如同一段计时分别记录为 15 秒／1 分钟与 281 秒／5 分钟）。用户需要的是「开始计时只记录一个时间、其他设备用本地时钟展示、任何设备都能随时同步」，而不是先争夺写入资格再互相覆盖。

## What Changes

- **BREAKING**：取消普通事项计时写入对「计时写入权」租约的依赖。已授权设备随时可以提交开始、暂停、继续、结束等计时事实；云端只用唯一约束、事务锁和当前状态校验保证并发安全，不再要求或抢占租约。
- **BREAKING**：普通事项计时改为「先到云端的事实生效」。云端已存在同一段计时的竞争事实时，后到设备不再新建冲突，而是废弃自己的待同步操作及其依赖链，采用云端权威结果继续工作。
- 移除客户端的「等待计时写入权」状态，以及为此存在的续租失败重试与队列恢复原因。
- 新增一条非阻塞轻提示：跟随另一台设备的结果时告知用户「已在另一台设备保存，已跟随该结果」，可跳转到对应时间记录，并按现有「修正实际用时」流程调整。
- **BREAKING**：撤回当天为绕过等待而部署的 `tracking_lease_takeover_for_timer_write` 抢占入口；计时写入不再需要先取得写入资格。
- 租约保留为内部机制，仅用于未归属时间的跨日边界协调，不再影响任何用户可见的计时写入。
- 未归属时间的显示时长改为只用本地时间增量推进（以拉取到的权威时长为基准逐秒计算），使各设备系统时钟存在偏差时仍显示一致数值。
- 保留真正的业务冲突处理入口，继续用于非计时对象（事项、报告等）的竞争修改。

## Capabilities

### New Capabilities

- `timer-fact-convergence`: 定义普通事项计时事实（开始、暂停、继续、结束）的免租约写入、「先到云端生效」的收敛规则、后到设备的本地回退与轻提示要求。
- `shared-unassigned-time-display`: 定义多设备未归属时间显示时长的派生规则，要求显示值不受各设备系统时钟偏差影响。

### Modified Capabilities

无。项目尚未建立持久化主规格（`openspec/specs/` 为空），`timer-sync-authority` 与 `shared-unassigned-time` 目前只存在于未归档变更中；本变更以新的能力规格承接并取代其中的写入权与显示要求。

## Impact

- Supabase 权威 schema 与版本化补丁：普通计时写入不再校验租约，撤回抢占 RPC，租约仅保留给未归属跨日协调；`supabase/schema_integration_test.sql` 与 `scripts/verify-supabase-schema.mjs` 同步更新。
- Rust 客户端同步：`src-tauri/src/cloud_sync.rs`（租约获取与续租、`reconcile_timer_sync_context`、`lease_wait` 恢复类型、抢占入口）与 `src-tauri/src/time_tracking.rs` 的计时写入与推送路径。
- 前端：`src-ui/src/services/timerSyncRecoveryPresentation.ts` 去掉「等待计时写入权」文案，`src-ui/src/views/MainWorkbench.vue` 增加跟随提示，`src-ui/src/store.ts` 的未归属时长派生改为本地增量推进。
- 既有本地队列：本机已存在的 `timer_stop` 冲突及其后续依赖操作在升级并按新规则同步后自动收敛，不再需要用户手动选择。
- 测试：`src-tauri/src/cloud_e2e.rs` 双设备用例改为验证「先到生效、后到跟随」，并补充设备时钟偏差下的显示一致性验证。
- 文档：`docs/` 中与计时同步权威、未归属时间相关的说明需要同步更新。
