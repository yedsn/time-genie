# Spec Delta

## Purpose

定义 TimeGenie 主工作台在鼠标悬停或点击导航时的即时反馈、页面状态保留和缓存刷新边界，使已访问页面能够直接恢复，同时继续保证首次启动按需加载和远端数据最终收敛。

## ADDED Requirements

### Requirement: 导航反馈必须即时且避免无意的中间页面工作
系统 MUST 在用户悬停或点击主导航、主体导航和页面标签时立即更新目标选中反馈。系统 MUST 合并同一渲染帧内连续产生的悬停目标，不得仅因指针快速经过而依次挂载全部中间页面或发起其业务查询。

#### Scenario: 悬停目标在下一帧获得反馈
- **WHEN** 用户启用悬停切换并把鼠标移到另一个可用菜单
- **THEN** 目标菜单的选中反馈在下一渲染帧内出现，且不等待目标页面代码或数据加载完成

#### Scenario: 快速扫过多个菜单只提交最终目标
- **WHEN** 指针在同一渲染帧内连续经过多个非活动菜单
- **THEN** 系统只提交该帧最后一个有效目标，中间目标不挂载页面且不触发业务数据查询

### Requirement: 已访问页面必须恢复原有实例状态
系统 SHALL 在主工作台会话内保留已首次访问页面的页面实例。再次进入页面时 MUST 恢复其滚动位置、筛选条件、展开状态、当前选择和未保存草稿，而不是重新执行完整挂载流程。

#### Scenario: 再次进入时间记录页面
- **WHEN** 用户离开已加载的时间记录页面后再次切回
- **THEN** 系统直接恢复先前的分页、展开记录和滚动位置，不显示首次加载占位且不因重新挂载重复初始化

#### Scenario: 报告草稿跨页面切换保留
- **WHEN** 用户在报告页面编辑未保存内容并切换到其他主页面后返回
- **THEN** 未保存内容、编辑模式、筛选条件和所选报告保持不变

### Requirement: 页面数据必须缓存优先并按失效刷新
系统 MUST 在页面已有可用缓存时先呈现缓存内容。单纯离开并返回页面 MUST NOT 强制重新查询；只有缓存缺失、用户显式刷新或对应领域因 mutation、Realtime、跨日、账户或 workspace epoch 变化而失效时才重新查询。有缓存的失效页面 SHALL 在显示现有内容的同时后台刷新。

#### Scenario: 未失效页面再次进入不刷新
- **WHEN** 用户返回已访问且数据未被标记失效的页面
- **THEN** 系统立即显示缓存数据，不发起新的权威查询且不显示全页 Loading

#### Scenario: Realtime 失效后后台收敛
- **WHEN** 已缓存页面对应领域收到更高 change sequence 的 Realtime 变化
- **THEN** 系统保留当前可用内容，并在页面可见时执行后台权威查询，完成后收敛到最新数据

#### Scenario: 跨日或工作空间世代变化不复用过期语义
- **WHEN** 当前工作日或 workspace epoch 发生变化
- **THEN** 依赖该边界的缓存被标记失效，页面再次进入时重新取得匹配新边界的权威数据

### Requirement: 重量页面必须保持按需加载并支持安全预加载
系统 SHALL 继续将报告和重量设置功能保留在主入口之外的动态依赖边界。系统可以在主工作台关键初始化完成后或用户接近对应入口时预加载代码，但 MUST NOT 因预加载而创建页面实例、读取业务数据或把主工作台重量模块加入悬浮窗初始依赖链。

#### Scenario: 空闲预加载只准备代码
- **WHEN** 主工作台已稳定且系统开始预加载高概率访问的重量页面
- **THEN** 对应代码进入模块缓存，但页面组件未挂载且其业务查询未执行

#### Scenario: 悬浮窗依赖边界保持不变
- **WHEN** 应用仅创建或显示悬浮窗
- **THEN** 悬浮窗初始代码路径仍不包含报告、设置或主工作台页面实现

### Requirement: 加载反馈必须保持布局稳定且不阻断切换
系统 MUST 在首次进入尚未准备好的页面时立即呈现稳定内容容器和可识别的轻量加载状态。已有缓存的页面再次进入 MUST NOT 显示全页 Loading。页面加载和切换反馈不得阻止用户继续选择其他目标，并 MUST 为减少动态效果偏好提供直接切换或短淡入替代。

#### Scenario: 首次进入重量页面
- **WHEN** 用户首次进入代码或数据尚未准备好的报告或设置功能
- **THEN** 内容区域尺寸保持稳定并显示页面结构化占位，用户仍可立即切换到其他页面

#### Scenario: 减少动态效果
- **WHEN** 系统启用了减少动态效果偏好
- **THEN** 页面切换不使用大范围位移动画或弹跳，仅使用直接切换或短透明度反馈

### Requirement: 页面缓存必须具备可验证的性能与资源边界
系统 MUST 提供可重复验证，覆盖首次与再次切换延迟、组件挂载次数、页面查询次数、状态恢复、失效刷新和页面保活后的内存占用。已缓存页面切换的项目验收目标 SHALL 为 P95 不超过 50ms，并且不得因快速悬停持续增加页面实例或事件监听。

#### Scenario: 已缓存页面切换基准
- **WHEN** 在固定环境中重复切换已访问的主工作台页面
- **THEN** 输出切换耗时分布、挂载次数和查询次数，且切换耗时 P95 不超过 50ms

#### Scenario: 页面保活资源稳定
- **WHEN** 用户多轮切换今日、待办、时间记录、报告和设置页面
- **THEN** 每个页面至多保留一个活动实例，事件监听不会随轮次增长，常驻内存保持在记录的验收基线内
