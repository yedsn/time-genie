# Design

## Context

见 proposal.md 与 specs/fluid-workbench-navigation/spec.md。当前 `v-hover-switch` 在 `mouseenter` 时直接调用绑定函数或 `element.click()`；主工作台通过一条 `v-if / v-else-if` 链展示页面，因此离开页面会卸载组件。时间记录在 `onMounted` 中加载历史，报告页面在挂载后建立筛选 watch、设置读取和编辑器状态，待办今日标签还会以 `force=true` 请求当日计划。

上一变更已经把报告和重量设置组件改为动态 import，并建立查询协调、领域失效和 Realtime 收敛能力。本设计必须保留首次启动与悬浮窗分包收益，不能通过静态导入全部功能或启动时一次性挂载所有页面来换取切换速度。

## Goals / Non-Goals

**Goals:**

- 使导航反馈与异步代码、数据加载解耦，hover 和点击都能立即反映用户意图。
- 页面首次访问后保留组件实例和局部交互状态，再次切换只激活已有实例。
- 复用现有 query coordinator 与领域失效语义，形成 stale-while-revalidate 式的页面进入行为。
- 在不回退动态分包的前提下，降低报告和重量设置页面的首次进入等待。
- 用挂载次数、查询次数、切换 P95 和资源稳定性测试锁定效果。

**Non-Goals:**

- 不持久化跨应用重启的页面 DOM、滚动位置或未保存草稿。
- 不为所有业务查询引入新的通用缓存库或 service worker。
- 不改变 Realtime、workspace epoch、版本冲突和 Supabase 单一权威语义。
- 不把所有设置区同时常驻挂载，也不承诺任意数量页面无限缓存。
- 不引入弹跳、位移或装饰性动画来掩盖真实加载延迟。

## Decisions

### 1. 用访问集合加 KeepAlive 实现“首次按需、之后保活”

主工作台维护已访问页面集合。目标页面第一次被选中时才创建异步页面实例，之后由 `KeepAlive` 保留并切换活动组件。页面组件使用稳定名称和 key，每个主页面在一个工作台会话内最多一个实例。

`v-show` 全量挂载会让所有页面在启动时同时创建，直接回退上一变更的启动优化；继续使用互斥 `v-if` 又会反复销毁实例。因此选择“访问后保活”。今日、待办、时间记录、报告适合页面级保活；设置页作为一个页面保活，内部重量区继续按需创建。

页面级全局状态继续放在 Pinia store，页面私有 UI 状态保留在组件实例中。需要在失活时暂停的计时器、DOM 测量和非全局监听使用 activated/deactivated 生命周期处理，不能依赖 unmount。

### 2. hover 切换通过一帧提交器合并，不增加可见延迟

`hoverSwitchDirective` 不再同步 `click()`，而是把本帧最后一个目标提交到 `requestAnimationFrame`。同一帧内新的目标覆盖旧目标；点击仍立即执行且取消待提交 hover。元素失活、卸载或被禁用时取消对应提交。

不采用 100～300ms 定时防抖，因为它会直接增加跟手延迟；一帧合并最多等待一个显示帧，能过滤指针快速扫过产生的中间页面工作，同时符合即时反馈目标。现有 hover 开关、禁用判断、active/aria 判断和点击兼容行为保持不变。

### 3. 页面进入不再把“切换”解释为“强制刷新”

现有 query coordinator 已支持 maxAge、single-flight、mark stale、change sequence 和 workspace epoch。页面进入统一按以下顺序处理：

1. 页面有缓存时立即展示。
2. key 未失效且仍在新鲜期时不请求。
3. key 已失效时保留旧内容并后台刷新。
4. 页面没有可显示内容时才进入结构化初始 Loading。
5. 用户显式刷新、恢复备份等明确动作仍可强制读取权威数据。

待办 `selectPage('plan')`、`selectSubject` 和 `selectPlanTaskTab('today')` 不再仅因导航使用 `force=true`；mutation 和 Realtime 已负责标记领域失效。时间历史组件激活时调用非强制 load，报告 watch 仅在过滤 key 变化或缓存缺失/失效时重置列表。

不额外复制一份页面数据缓存，否则会与 Pinia、query coordinator 和 persistent cloud read cache 形成多重真相。

### 4. 代码预加载与页面/数据加载严格分离

为每个重量页面保留稳定 loader 函数，同一个 loader 同时供异步组件和预加载调用。预加载只执行动态 import：

- 主工作台关键初始化和首帧稳定后，使用 `requestIdleCallback`，无该能力时用受控的延后任务，预加载报告入口。
- 用户 pointerenter 主导航时可以立即预加载目标代码，同时页面提交仍由一帧合并器决定。
- 设置目录接近备份、历史、快照、自动化区时只预加载对应代码；组件第一次进入可见范围或成为目标区时再创建。

预加载逻辑只能存在于 MainWorkbench 加载后的依赖链，不能上移到共享 App 或 hover 入口。构建验证继续断言 hover 初始 manifest 链不包含这些模块。

### 5. 使用稳定外壳和短淡入，不让动画承担性能职责

主内容区保留最小高度和上一布局尺寸，首次加载页面展示对应结构的轻量 skeleton，而不是空白或单行文字。导航 active 状态先于内容准备更新。内容就绪后只使用 transform 之外的短 opacity 淡入，目标约 100～140ms；切换过程不锁定输入，新的导航目标可以立即中断旧目标。

已缓存页面激活不展示 skeleton，也不播放显著入场动画。`prefers-reduced-motion: reduce` 下直接切换或使用极短透明度变化。

### 6. 缓存容量按固定主页面集合控制，设置区按可见性延迟实例化

主页面数量固定为五个，全部访问后的单实例保活是可控上限。设置页内部不能因为主页面保活就立即创建所有重量组件；使用已访问设置区集合和可见性观察，仅在目标区即将进入视口时实例化，实例创建后保留。

报告 Markdown 编辑器是主要内存风险。验收记录首次访问前后及多轮切换后的 `performance.memory`（环境支持时）、DOM 节点数、组件挂载计数与监听计数；不支持内存 API 时至少验证实例和 DOM 数不会随轮次线性增长。若固定五页仍超出基线，再以最近访问策略只淘汰无草稿的重量页面，而不是一开始引入 LRU 复杂度。

### 7. 增加可观测测试钩子而不暴露业务正文

开发/验证环境记录页面 mount、activate、deactivate、导航提交、代码 preload 和领域 query 计数，仅使用页面 id、领域名、次数和耗时，不记录报告正文、事项标题或凭据。

浏览器测试覆盖：快速扫过多个菜单、首次进入报告、报告草稿返回、时间记录状态恢复、未失效无查询、Realtime 失效后台刷新、减少动态效果及 100 次往返切换。已缓存页面切换采集至少 25 次并断言 P95 ≤ 50ms。

## Risks / Trade-offs

- [页面保活增加常驻内存] → 固定最多五个主页面实例，设置重量区延迟创建，并记录多轮切换后的 DOM/内存基线。
- [deactivated 页面仍运行监听或定时器] → 审计各页面 onMounted/onUnmounted 副作用，迁移页面可见性相关工作到 activated/deactivated，并增加监听不增长测试。
- [缓存内容短暂陈旧] → 只在有可用缓存时先显示；沿用 mutation、Realtime、跨日和 epoch 失效，并在可见页面后台权威刷新。
- [一帧合并误吞用户点击] → 点击路径不延迟并取消待处理 hover；仅悬停目标参与合并。
- [预加载重新拖慢启动] → 只在关键初始化和首帧后空闲执行，保持 hover manifest 边界测试，并记录主线程长任务。
- [保活页面中的未保存草稿与远端更新冲突] → 草稿继续遵循现有保存/版本冲突行为，后台刷新不得直接覆盖明确的本地编辑态。

## Migration Plan

1. 先增加 hover 提交、页面 mount/query 次数和重复切换基准，复现当前卸载与查询行为。
2. 将主内容区收敛为访问后保活的动态页面容器，并修正页面激活/失活生命周期。
3. 移除导航引发的强制刷新，复用 query coordinator 的缓存与失效机制。
4. 增加报告和重量设置模块的空闲/意图预加载，验证悬浮窗依赖链不回退。
5. 加入稳定 skeleton、短淡入和 reduced-motion 行为，完成状态恢复、Realtime、跨日和内存回归。

可分层回滚：代码预加载可独立关闭；hover 一帧合并可恢复同步提交；页面保活容器可恢复互斥渲染。回滚不得改回静态导入全部重量组件，也不得绕过数据失效规则。
