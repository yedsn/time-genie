# Proposal

## Why

主工作台开启鼠标悬停切换后，会在指针快速经过菜单或标签时立即销毁当前页面并挂载目标页面。报告、时间记录和设置等页面包含异步模块、复杂 DOM 及挂载期查询，导致菜单状态虽然已经变化，内容区仍出现短暂停顿、Loading 或重复刷新，削弱了悬停导航应有的直接感。

## What Changes

- 已首次访问的主工作台页面 SHALL 保留页面实例、滚动位置、筛选条件、展开状态和未保存草稿，再次切回时直接恢复，不重新执行完整挂载流程。
- 页面数据 SHALL 优先显示现有缓存；只有缓存缺失或被 mutation、Realtime、跨日、workspace epoch 等事件标记失效时才重新查询，并在有缓存时采用后台刷新而不是阻塞页面切换。
- hover 导航 MUST 在下一渲染帧内更新选中反馈，并合并同一帧内连续经过的中间目标，避免快速扫过菜单时依次挂载所有页面或触发无用请求。
- 报告及重量设置模块继续按需分包，但可在主工作台稳定后或用户接近入口时预加载代码；预加载不得提前创建页面、请求业务数据或污染 hover 窗口依赖边界。
- 首次进入确实尚未准备好的页面时，内容区保持稳定布局并显示与页面结构匹配的轻量加载反馈；已有缓存的再次进入不得显示全页 Loading。
- 为页面切换延迟、重复挂载、请求次数、状态恢复和失效收敛增加可重复验证，并检查页面保活后的常驻内存边界。

## Capabilities

### New Capabilities

- `fluid-workbench-navigation`: 定义主工作台悬停导航的即时反馈、页面实例保活、缓存优先显示、失效后台刷新、重量模块预加载和状态恢复要求。

### Modified Capabilities

无。项目当前尚无已归档主规格，本变更新增独立的工作台流畅导航能力。

## Impact

- 前端导航与页面容器：`src-ui/src/services/hoverNavigation.ts`、`src-ui/src/views/MainWorkbench.vue`。
- 页面生命周期与本地状态：今日、待办、时间记录、报告和设置相关组件。
- 前端数据协调：`src-ui/src/store.ts` 中今日计划、时间历史、报告和今日概览的缓存、强制刷新及失效逻辑。
- 构建与预加载：动态 import 的加载时机和 hover/main 依赖边界；不重新静态引入重量页面。
- 验证：hover 快速扫过、首次/再次切换、页面状态恢复、Realtime/跨日失效和常驻内存回归。
- 不改变 Rust/Tauri API、Supabase 权威数据语义、SQLite 本地模式或用户可见的保存规则。
