# Design

## Context

见 `proposal.md` 的问题说明和 `specs/calendar-day-time-accounting/spec.md` 的行为要求。当前 `time_entries` 和 `unassigned_sessions` 在创建时写入 `work_date`，运行、暂停、恢复和处理期间不会因为工作空间日期变化而切分。今日概览、报告和重复事项实际用时随后都按这个固定字段聚合，所以错误日期一旦写入，所有上层视图都会继承同一偏差。

工作空间已经保存 IANA 时区字符串，默认 `Asia/Shanghai`，但多数 Rust 业务逻辑直接使用设备 `chrono::Local`；Supabase RPC 又使用数据库 `now()` 和会话默认时区。现有云端同步具备本地优先 outbox、实体版本、幂等 operation ID、单活动计时约束、共享未归属会话和采集租约，可用于协调跨日切分，但目前没有“按日切片”业务动作。

## Goals / Non-Goals

**Goals:**

- 让日期归属成为底层时间记录的事实，而不是今日页面临时裁剪出来的显示值。
- 本地和服务端都能从工作空间时区计算任意时间戳对应的日期和日边界。
- 跨日切分可重复执行、可断点恢复、可同步，并维持同一工作空间只有一个活动计时和一个活动未归属会话。
- 停止计时后的人工结算仍然清晰，不因底层产生多个日期切片而要求用户重复处理同一天。
- 不修改无法可靠还原的既有已结束历史数据。

**Non-Goals:**

- 不提供历史跨日记录的自动批量修复工具。
- 不把时间精度从当前秒/分钟结算改成更细粒度，也不改变分钟向上取整规则。
- 不在本变更中增加复杂班次日、凌晨归前一工作日或用户自定义日界线；日界线固定为工作空间时区的自然日零点。
- 不把系统休眠时间推断为工作或空闲；无法由有效心跳、租约或连续运行证明的区间一律不累计。

## Decisions

### Decision 1: 建立统一的工作空间日历服务

新增共享日期辅助模块，输入工作空间时区、时间戳和可选日期，输出：

- 时间戳所属 `work_date`；
- 指定日期的起止时间戳；
- 一个时间区间经过的日界线；
- 把 segment 按日边界裁剪成若干日期切片。

Rust 侧读取 `workspaces.timezone`，使用 IANA 时区库计算边界；Supabase 函数通过 `timezone(workspace.timezone, timestamp)` 或等价表达计算同一边界，并显式处理夏令时导致的一天不是固定 24 小时。所有现有 `local_date()` 调用逐步替换为该服务。

备选方案是继续使用设备本地时区，只在今日查询里裁剪。该方案会让多设备对日期产生不同判断，也无法修正报告、重复轮次和同步实体，因此不采用。

### Decision 2: 跨日活动事项计时拆成同一计时链的按日记录

保留 `time_entries` 一条记录只对应一个 `work_date` 的约束。新增可空的计时链标识和相邻切片关系，例如：

```text
timer_chain_id
previous_entry_id
split_boundary_at
```

开始计时时创建链首记录。发现工作日期已变化时，在一个事务或服务端原子动作中：

1. 将旧记录的开放 segment 截止于第一个日界线，更新时长并结束旧记录；
2. 为之后每个自然日建立对应记录；中间完整日期只保存确实由连续运行证明的部分；
3. 最后一个日期切片保持 `running` 或 `paused`，并继承 task、label、note 和计时链；
4. 为重复事项确保每个实际产生有效时间的日期轮次存在。

同一计时链在任意时刻仍只有一个活动切片。跨日动作以 `timer_chain_id + work_date` 唯一约束和确定性 operation ID 幂等，避免两台设备或重试生成重复切片。

停止后的结算界面以计时链为一次用户操作：后端返回本次停止涉及的切片列表，默认将同一事项分配分别写入各切片；“同时完成”只作用于停止当天的轮次。历史日期切片若尚未结算，继续显示为对应日期的待结算记录，而不是把分钟移动到今天。

备选方案是在同一 `time_entry` 内保存跨日 segments，并在每个查询中按时间戳动态拆分。该方案会让现有分配只能绑定整条记录，无法表达重复事项每天的分钟和完成状态，因此不采用。

### Decision 3: 未归属会话按日期链式轮转，不把历史时间灌入处理日

复用现有 `predecessor_session_id` 表达未归属会话链。一个 session 的所有 segments 必须落在该 session 的工作日期范围内。发现跨日时：

1. 旧 session 在日界线关闭开放 segment，刷新 `duration_seconds`，若超过阈值则保留 `awaiting_resolution`；
2. 旧 session 不因日期切换自动生成工时，也不自动丢弃，用户仍可按原日期处理；
3. 如果边界后仍有有效采集资格且没有活动事项计时，创建下一日期 session，开始边界固定为日界线或恢复时间；
4. 当前状态接口返回今天活动 session，并单独返回历史待处理数量/最早日期，处理弹窗可在会话间切换。

未归属处理使用 session 自身 `work_date` 创建最终 `time_entry`、确保重复轮次并完成对应日期，而不再调用处理时的当前日期。若未来需要把一个历史会话分配到多个日期，应通过多个会话分别处理，不允许单 session 跨日。

备选方案是零点自动把未归属时间记为休息或无效时间。该方案替用户做了不可逆业务判断，因此不采用。

### Decision 4: 有效累计使用可证明的连续性边界

本地模式记录最近一次采集心跳时间，云端模式使用现有 45 秒租约及服务端时间。每次心跳、用户计时动作、窗口恢复和应用启动都会先执行“日界线/中断协调”：

- 心跳间隔在允许容差内：按连续运行处理，并可跨零点切分；
- 应用关闭、休眠、进程停顿或租约过期形成超出容差的间隙：开放 segment 截止于最后可确认时间；
- 恢复后从当前服务端或本地时间建立新 segment，不补算间隙；
- 暂停中的事项计时本来不累计，恢复时若日期已变化则直接创建当天活动切片。

容差应略大于心跳/租约周期并集中配置。云端权威边界优先采用服务端租约过期或 RPC 时间，避免设备时钟漂移；本地模式采用单调心跳观测与墙上时间共同判断。

备选方案是只在应用启动时用当前时间封口。该方案会把关闭或休眠区间错误算入旧 segment，不能满足“不累计未使用时间”的要求。

### Decision 5: 今日概览和报告读取按日事实，并修正重复虚拟轮次

今日概览继续按 `work_date` 聚合，但活动数据加载前先执行轻量的日界线协调，保证运行中的跨日记录已物化为今天切片。事项列表的日期判断不再只依赖今天已有 `task_occurrences`；它同时读取指定日期有效的重复规则，合并：

- 当天到期的虚拟 open 轮次；
- 当天已有 occurrence、按日预估或实际工时的物化/手工轮次；
- 普通事项原有今日规则。

未归属摘要只汇总今天 session；历史 `awaiting_resolution` 通过额外 DTO 显示数量和入口。报告继续基于 `time_entries.work_date` 和 occurrence 日期汇总，因底层已正确切片，无需在每种报告中重复裁剪逻辑。

备选方案是仅在今日页面根据 started/ended 时间裁剪分钟。它不能修复分配、报告和完成轮次，所以只可作为旧历史记录的展示保护，不作为新数据主路径。

### Decision 6: 云端使用原子 RPC 确认权威跨日结果

扩展 Supabase schema 和 RPC，使服务端按 workspace timezone、服务端当前时间和 expected version 执行：

- 活动 timer chain 的跨日切分；
- 活动未归属 session 的日期轮转；
- 过期租约/中断分段封口；
- 返回当前日期权威活动记录。

客户端仍然先在本地事务中产生候选切分和 outbox，前台立即刷新。云端操作依赖旧切片更新后再创建新切片，并使用链 ID、日期和 operation ID 保证幂等。若服务端已经由另一设备切分，本地候选被封存或映射到服务端权威实体，相关分配和 occurrence 依赖随之重定向，不生成双份工时。

服务端函数和 RLS 继续验证工作空间归属、设备授权和计时租约。Realtime 只通知离散切分结果，不按秒同步。

### Decision 7: 历史兼容采用不重写策略

迁移只增加链关系、切分边界、最近有效心跳等必要字段和索引。已有 ended 记录保持原 `work_date`、duration 和 allocation；报告结果不被升级静默改变。

升级时对活动记录执行一次恢复审计：

- paused timer：按原日期封存旧活动切片，今天恢复时再建新切片；
- running timer 或 collecting session：截止到可证明的最后活动/租约边界，间隙不累计；
- awaiting_resolution session：保留原日期和时长，今天另建活动 session；
- 云端设备先拉取权威状态再创建本地候选。

旧客户端兼容期内，服务端保留现有 RPC 签名，但拒绝旧客户端把跨日期聚合覆盖到已经按日切分的权威链；新字段对旧快照读取提供默认值。

## Risks / Trade-offs

- [Risk] 自动日切会把一次计时变为多条记录，结算交互和 outbox 依赖更复杂 → 通过稳定计时链聚合用户操作，底层按日期保存，界面只在需要时展开。
- [Risk] 分钟分别向上取整可能让跨日总分钟比原单条记录多一分钟 → 按计时链先计算总有效秒，再以日切片秒数分配结算分钟，保证各切片分钟之和等于链总分钟。
- [Risk] 工作空间时区修改会改变未来边界解释 → 修改时区只影响修改后的新边界和记录，不重写历史 `work_date`；设置页提示此行为。
- [Risk] 夏令时日期可能为 23 或 25 小时 → 使用时区库计算相邻本地零点，不用固定加减 86,400 秒。
- [Risk] 本地心跳容差过短会误删有效时间，过长会纳入休眠时间 → 统一配置并测试容差，界面允许用户通过现有时间修正功能调整异常记录。
- [Risk] 多设备并发切分产生本地候选和服务端权威 ID 不同 → 服务端按链和日期唯一约束返回既有实体，客户端执行依赖重定向和候选封存。
- [Risk] 历史待处理未归属会话增加后，强制弹窗可能阻塞今天工作 → 弹窗优先处理当前必须处理会话，同时提供历史待处理列表；不得把历史分钟并入今天。

## Migration Plan

1. 增加时区日期模块、IANA 时区依赖和纯函数测试，先保持现有写入路径不变。
2. 部署 Supabase 兼容补丁：链/切分字段、唯一索引、跨日 timer/unassigned RPC、租约封口、权限和 schema 集成测试。
3. 增加 SQLite 迁移和本地恢复审计，发布能读取新旧 payload 的客户端。
4. 接入普通计时按日切分、停止结算链聚合及重复轮次日期归属。
5. 接入未归属按日轮转、历史待处理状态和云端权威收敛。
6. 更新今日概览、报告和前端显示，完成跨零点、休眠恢复、离线和双设备验收后启用。
7. 回滚客户端时保留新增字段和按日记录；禁止把已切分链自动合并。服务端兼容旧读取，但旧写入不得覆盖较新权威版本。
