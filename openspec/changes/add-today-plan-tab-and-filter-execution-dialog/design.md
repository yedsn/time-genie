# Design

## Context

见 `proposal.md` 与 `specs/today-task-planning/spec.md`。当前 `task_daily_estimates` 只能保存大于零的分钟数，清空预计等价于删除记录，无法表达“属于今日但尚未估时”；重复事项又会按规则虚拟生成当日轮次，因此还需要表达“今天明确不要执行”的覆盖。

待办页当前由 `planTaskTab` 在“进行中 / 已完成”之间切换，进行中使用完整 `PlanListEditor`，已完成单独分页。`TimerTaskDialog` 的执行、停止分配、历史分配和未归属分配模式共用 `actual_adjustment_snapshot` 数据；执行模式现在直接展示当前主体的全部开放事项。`todayTasks` 与今日概览还会把今日时间记录、到期日期和重复轮次合并为活动视图，不能直接作为“今日计划”的权威来源。

本地与 Supabase 已同步 `task_daily_estimates`、重复规则和重复轮次，并将它们纳入增量同步、冲突、快照、备份恢复和双设备测试。新的今日成员数据必须沿用同一离线优先和版本收敛机制。

## Goals / Non-Goals

**Goals:**

- 为每个事项和工作日提供明确、可同步、可冲突检测的今日成员资格。
- 保持每日预计是可选属性，使“是否今天做”和“预计做多久”可以独立修改。
- 为普通事项、重复事项、已完成当日事项和跨日活动计时提供一致的有效成员计算。
- 让待办页今日标签与执行模式弹框共享同一权威成员口径。
- 保持时间活动型今日概览、报告和非执行分配模式的既有范围。

**Non-Goals:**

- 不把今日标签改成日历或支持任意未来日期的计划编辑器。
- 不让预计开始日期、逾期状态或今日活动自动成为计划成员。
- 不改变重复事项的长期开放模型、当日完成模型或整体/每次预计语义。
- 不改变计时状态机、唯一活动计时、停止确认、未归属处理和实际分钟聚合。

## Decisions

### 1. 新增按日成员表，保留每日预计表

新增 `task_day_plans`，建议字段为：

- `workspace_id`、`task_id`、`work_date`；
- `state`：`included` 或 `excluded`；
- `created_at`、`updated_at`、`version`；
- 主键 `(task_id, work_date)`，并按工作空间、日期建立索引。

`task_daily_estimates` 继续只保存大于零的预计分钟。成员资格与分钟分离后：

- `included` + 无预计记录：今天做，但尚未估时；
- `included` + 预计记录：今天做，并有预计分钟；
- `excluded`：明确覆盖当日自动成员资格，主要用于重复事项；
- 无成员记录：按重复规则决定是否自动进入，普通事项默认不进入。

迁移时为每条现有 `task_daily_estimates` 记录补一条 `included` 日计划记录。读取时仍将“存在预计记录”作为兼容性成员信号，避免迁移、恢复或旧数据缺少成员行时丢失计划。

备选方案是让 `task_daily_estimates.estimate_minutes` 可空并增加状态列。它会改变既有表约束、序列化和旧数据假设，而且“预计”和“成员覆盖”仍耦合在一个实体中。独立成员表更清晰，也让现有预计同步逻辑保持单一职责。

### 2. 用统一函数计算有效今日成员

后端抽取按 `task_id + work_date` 计算有效成员的共享逻辑，优先级为：

1. 显式 `excluded`：不是今日成员；
2. 显式 `included`：是今日成员；
3. 存在该日预计记录：是今日成员，作为兼容性兜底；
4. 有效重复规则命中该日：是今日成员；
5. 其他情况：不是今日成员。

完成状态不改变成员资格。普通事项完成后由日计划记录保证它继续出现在当天；重复事项完成后由当日轮次提供状态，成员仍由上述规则计算。查询结果同时补齐可见成员的祖先节点，但祖先只标记为上下文，不获得执行资格。

今日概览继续按活动、预计和重复规则生成，不改成纯计划口径。待办今日标签和执行弹框使用新的日计划查询，避免一个 `todayTasks` 同时承担“计划”和“活动历史”两种含义。

### 3. 日计划写操作使用独立版本化命令

新增单项和批量日计划写能力，输入至少包含事项、工作日、目标状态及期望版本。写操作验证事项属于当前工作空间/主体，更新全局 revision，并在云端模式写入同步 outbox。

字段操作语义为：

- 手动加入：upsert `included`；
- 设置大于零的今日预计：在同一事务中 upsert `included`，再写预计；
- 清除今日预计：只删除预计记录，确保成员仍为 `included`；
- 移出今日：删除该日预计并写 `excluded`，使普通和重复事项均得到一致的显式结果；
- 再次加入：把 `excluded` 更新为 `included`。

每日预计批量分配也必须同时确保对应事项为 `included`。重复事项原有“修改每次预计”逻辑继续保留，但当日计划成员写入与重复轮次创建必须处于同一事务或具有明确同步依赖。

备选方案是普通事项移出时删除成员行，仅对重复事项写 `excluded`。虽然数据更少，但 UI 和同步需要根据是否重复选择两套写语义，且规则变更时旧的删除意图不可追踪，因此统一写 `excluded`。

### 4. 今日标签使用专用快照，不复用活动型 todayTasks

新增按主体和工作日加载的今日计划快照，返回：

- 有效成员及其父级上下文；
- 当日成员状态与版本；
- 可选今日预计与预计版本；
- 普通完成状态或重复轮次状态；
- 当前已确认实际、当前计时状态及既有事项字段。

store 独立维护当前主体的今日计划数据、加载状态和计数。跨过工作空间自然日、主体切换、日计划写入、预计写入、完成/恢复、新建、删除和同步刷新后都重新加载。它不覆盖 `todayOverview` 或时间活动集合。

待办页标签扩展为 `today | active | completed`。从其他页面进入待办页和在待办页切换主体时默认回到 `today`。今日视图与进行中视图直接复用同一个列表编辑器：拖动、缩进、底部“+”新增、行内编辑和子事项操作保持一致；今日模式仅以过滤快照决定可见范围，并追加配置/移出今日能力。批量编辑入口按标签区分：今日显示“编辑今日计划”，编辑区只载入未完成今日成员及必要父级上下文；进行中显示“编辑全部计划”，继续载入完整开放树。今日批量保存仍以完整开放计划作为版本基线，将今日范围的改名、层级和排序结果合并回完整计划，未显示事项保持不变；从今日草稿移除成员转换为当日 `excluded`，新增事项创建后转换为当日 `included`，纯上下文父项不得从今日草稿单独删除。拖动和层级写入仍作用于完整计划，刷新后继续按今日成员范围显示，避免形成第二套排序模型。

### 5. 今日标签提供加入、移出和新增入口

今日工具栏提供“配置今日事项”和“编辑今日计划”；进行中工具栏提供“编辑全部计划”；不再提供独立的“从进行中加入”“分配今日预计”“新增今日事项”或“管理完整计划”按钮。配置弹框展示当前主体完整开放树，父事项作为上下文，叶子事项提供成员勾选与今日预计编辑器。预计编辑器复用既有时间分配交互：中间输入框可直接填写分钟数并点击展开 30、60、90、120、150 分钟五个常用选项，左右按钮以 15 分钟为步长增减；空值点击减号保持为空，增减结果不小于零。尚未加入的事项可无预计加入今日，填写、选择或增加正数预计会自动选中事项；已在今日事项默认保持勾选并允许修改预计。保存时先批量加入新增成员，再批量保存有变化的预计；任一步失败均保留弹框和用户草稿，并以权威重载结果为准。进行中标签为尚未加入今日的可执行叶子事项提供行内“加入今日”快捷按钮，并复用同一批量日计划动作完成写入；成功后保持当前标签，失败沿用统一错误反馈。新增一级事项与子事项使用和进行中一致的列表“+”入口，新事项保存后自动加入今日。

共享列表将“是否可完成”与“是否展示行首勾选框”分离：叶子事项显示可操作勾选框，包含二级事项的一级父事项显示禁用勾选框，今日上下文父项同样保持禁用。二级事项采用整行左侧操作区缩进：拖动柄、勾选框和名称共同向右移动 17px，右侧时间与操作列继续对齐；待办拖动柄始终可见，减少排序入口的发现成本。进行中标签隐藏“今日用时”元信息及其调整入口；今日标签继续展示该信息，用于当天计划执行反馈。

今日成员行提供“移出今日”。已完成普通事项和已完成重复轮次仍可移出；该动作不改变完成状态。上下文父项不显示移出动作，除非父项自身也是显式成员。

今日标签新增事项先走现有创建规则，再在同一用户动作中写入当日成员。后端优先提供原子组合命令；如果复用现有创建命令，则前端必须在加入失败时保留新事项并明确提示“事项已创建，但加入今日失败”，不得静默丢失。执行弹框的“新建并开始”需要更强原子性，见下一决策。

今日列表头部增加紧凑的“今日预计 / 今日实际”汇总，统计范围仅包含有效今日成员中的叶子事项，使用叶子事项 `todayEstimate` 与 `directMinutes` 求和，父级上下文和父级汇总行不重复计入。配置今日事项弹框顶部复用未归属时间弹框的上下文加大数字指标布局：今日实际保持权威快照口径，今日预计使用当前选择与输入草稿实时求和，使用户保存前即可看到计划容量变化。正在进行但尚未确认的当前计时段沿用事项行现有语义，不提前计入今日实际。

今日计划加载反馈分为首次加载与后台刷新。首次加载不在标题与列表之间插入额外提示块，而在固定最小高度的列表区域内渲染四行低对比骨架，其行高、列结构和二级缩进接近真实事项；后台刷新继续展示上一次成功快照，仅将列表轻微降低饱和度和透明度，并在标题副文案旁显示“正在更新”、标题栏底部显示 2px 流动进度线。加载状态不改变编辑器外框尺寸，动画遵守 `prefers-reduced-motion`。

配置今日事项复用待办列表的 `taskTreeSortable` 树形拖动协调器。候选树使用完整进行中计划作为拖动基线，保存调用完整计划移动命令；搜索时禁用拖动，防止隐藏行导致错误落点。拖动成功后重新加载完整事项和今日计划，使弹框、今日标签与进行中标签共享权威顺序。候选树同样让二级事项的拖动柄、选择框和名称整体缩进 17px，实际与预计编辑列保持对齐。

配置弹框直接提供事项配置能力：表格左上角保留新增一级事项入口，逐行不再显示新增子项按钮；用户在拖动柄上右键打开紧凑行菜单，最上方独立显示“复制事项”，分隔线下方依次提供“在上方插入行”和“在下方插入行”。子事项插入与复制均保留原父级；一级事项复制仅复制一级行本身，不复制其子树。复制保留标题、整体预计、预计日期、备注和项目等基础内容，但不复制完成状态、重复规则、今日成员/预计、实际时间与时间记录。菜单使用 viewport 边界约束定位，点击外部、滚动或按 Escape 时关闭。新增或复制出的叶子事项立即加入选择草稿。名称输入框继续支持行内保存；实际用时列复用已有的目标分钟调整交互，打开时加载实际快照，保存前再次使用权威基线；成功后由 store 重载工作区、时间、今日概览和历史记录，使顶部实际合计与事项行同步更新。

### 6. 仅执行模式过滤，分配模式保持完整范围

`actual_adjustment_snapshot` 增加日计划状态，或新增等价执行快照，使 `TimerTaskDialog` 可区分有效今日成员、父级上下文和其他事项。

组件按模式处理：

- `execute`：只展示未完成的有效今日叶子及其祖先；
- `entry-allocation`、`unassigned-allocation` 等分配模式：继续展示既有合法事项范围；
- 当前运行或暂停事项不属于新一天计划时：从候选列表排除，但在弹框顶部的当前计时区域继续显示。

三个模式均复用同一树形拖动协调器。执行模式过去仅允许浏览，现改为允许拖动今日可见树；写入仍作用于完整事项计划，保存后重新加载今日计划快照。未归属与历史分配模式继续在完整合法事项范围内拖动，并刷新执行快照。所有模式在搜索过滤状态下禁用拖动。

执行模式和未归属时间分配模式进一步复用同一套事项配置控件：表格左上角新增一级事项，拖动柄右键菜单上方依次显示“复制事项”和“新增事项”，分隔线下方提供同层上方/下方插入。“新增事项”复用表格左上角入口，始终创建一级事项；逐行不再显示新增子项按钮。一级行操作一级事项，子项操作同一父级下的子项；复制只复制当前行并放在其下方，不复制子树、完成状态、重复规则或历史时间。执行模式中新建或复制出的叶子自动加入今日，未归属模式只刷新完整事项范围。叶子事项的已确认实际显示为可点击入口。实际调整保存时始终重新获取 `actual_adjustment_snapshot`，以最新 `version`、`directMinutes` 与 `adjustmentFingerprint` 计算变化，避免长时间打开弹框后覆盖新数据。未归属模式的实际调整只修改今日实际记录，不修改“本次分配分钟”草稿；历史记录归属模式继续只读实际时间，避免把历史归属修正与今日实际校正混为一体。

主窗口的未归属时间指示器只在对应分配弹框已经打开时隐藏，不再因存在运行中或暂停事项而隐藏；强制打开仍要求当前确有未归属时长，保持原有分配校验与计时状态机不变。

执行模式提供“从进行中加入今日”和“新增今日事项”。新建并立即开始时，扩展现有 `transitionTimer` 新事项请求，携带当前工作日和加入今日意图，由后端在创建事项、写日计划、处理旧计时并启动新计时的同一事务中完成，避免出现“已经开始但不属于今日”或“属于今日但计时转换失败”的中间状态。

### 7. 日计划作为独立云同步实体

新增同步实体 `task_day_plan` 和表映射 `task_day_plans`，采用复合实体 ID `task_id|work_date`。它进入：

- 增量推拉与 revision 域；
- outbox 操作和依赖关系；
- 版本冲突、冲突列表文案与保留/覆盖处理；
- 完整云快照、本地备份恢复和数据保护清单；
- 隔离双设备测试。

设置今日预计时，成员操作应先于预计操作或作为其依赖，保证接收端不会短暂把预计当成无成员孤立数据；读取端的“预计记录兜底即成员”进一步保证乱序容错。

Supabase 只新增表、索引、RLS 和变更触发器，不破坏现有 `task_daily_estimates` schema。旧版本客户端仍可同步每日预计，但无法理解无预计成员或显式排除；同一云工作空间的完整今日计划语义要求设备升级到包含此能力的版本。

### 8. 工作空间自然日切换触发权威重载

沿用现有 `workspaceToday` 和 `workspaceDayEndAt`。跨日刷新除现有工作区、时间和今日概览外，还重新加载日计划快照和执行弹框数据。若弹框跨日保持打开，则显示新日期的候选；昨天仍活动的事项只保留在当前计时状态区域。

成员数据按明确 `work_date` 持久化，不由客户端本地时区直接计算，避免工作空间时区与操作系统时区不一致。

## Risks / Trade-offs

- [“今日”与现有“今日概览”的事项集合不同，用户可能困惑] → 今日标签明确使用“今日计划”文案；今日概览继续强调已发生时间与完成统计，空状态说明活动不会自动加入计划。
- [新增成员表与预计表形成双实体写入，可能乱序] → 使用同一事务、本地 revision、云操作依赖和读取兜底；增加双设备乱序与离线重试测试。
- [过滤树后拖动可能错误重排隐藏事项] → 今日标签复用完整计划的移动命令和树约束，拖动结果写回完整结构后再按今日成员刷新；执行弹框仍不承担结构排序。
- [重复事项自动成员与显式移出发生冲突] → `excluded` 优先于重复规则，并严格限定到单个工作日。
- [跨版本设备无法理解无预计成员] → 云 schema 采用加法变更，预计记录保持兼容；发布说明要求同一云工作空间设备升级后使用完整今日计划能力。
- [今日已完成事项增加列表长度] → 保留是计划复盘所需行为，可在视图中置于未完成事项之后并弱化显示，不移入全量已完成分页。
- [执行弹框没有候选导致流程中断] → 空状态和工具区始终提供新增今日事项、从进行中加入和前往待办今日标签的路径。

## Migration Plan

1. 新增本地 `task_day_plans` 迁移，并从现有 `task_daily_estimates` 幂等回填 `included` 记录；保留原表和数据。
2. 在 Supabase schema 中新增对应表、索引、RLS、变更触发器和快照字段，再部署支持新实体的同步代码。
3. 实现共享有效成员查询和版本化写命令，先以测试固定普通事项、重复规则、显式排除、完成状态和预计兜底。
4. 接入 store 与待办页今日标签，再将执行模式切换为同一成员口径；非执行分配模式保持原查询。
5. 完成备份恢复、冲突处理、跨日刷新、本地与双设备验证后发布。

回滚应用代码时保留 `task_day_plans` 表和云端数据，不做破坏性降级；旧版本继续使用现有每日预计和全量进行中列表。再次升级后可恢复今日成员和排除覆盖。
