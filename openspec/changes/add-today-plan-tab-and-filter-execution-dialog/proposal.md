# Proposal

## Why

当前待办页只能按“进行中 / 已完成”浏览，虽然事项支持今日预计，但不存在一个可明确维护的今日计划集合；统一执行事项弹框又展示当前主体的全部进行中事项，导致真正准备今天执行的内容容易被长期待办淹没。需要让用户先形成今日计划，再让所有开始或切换执行入口聚焦这份计划。

## What Changes

- 在待办页增加“今日”标签，并调整为“今日 / 进行中 / 已完成”；进入待办页时默认打开“今日”。
- 将“今日事项”定义为独立的按日计划集合：设置大于零的今日预计会自动加入，也允许不填写预计时间而手动加入；移出今日不会删除事项。
- 当天应执行的重复事项自动进入今日；直接新增今日事项或在执行弹框中新增事项时，也自动加入当天计划。
- 今日标签保留当天已完成事项及必要的父事项层级上下文，但执行候选只包含未完成、可执行的今日叶子事项。
- 今日标签与“进行中”标签复用同一套待办列表编辑器和交互，包括拖动排序、层级调整、底部“+”新增、行内编辑、子事项和快速编辑计划；差异仅限今日数据范围与加入/移出今日、分配今日预计等今日专属能力。
- “进行中”标签允许在单个事项行上快捷加入今日，并隐藏仅属于今日执行反馈的“今日用时”；今日与进行中列表中的非叶子父事项均保留禁用态勾选框，以维持行首结构和完成操作位置一致。
- 统一执行事项弹框仅展示当前主体的今日计划，不再展示全部进行中事项；空状态提供新增今日事项和从进行中加入今日的路径。
- 今天仅产生过时间记录、预计开始日期已到或事项逾期，不会因此自动加入今日计划；相关记录仍继续进入今日概览和报告。
- 将现有按日预计持久化模型扩展为可表达“已加入今日但尚未估时”的日计划记录，并同步调整本地数据库、Supabase schema、同步、快照和冲突处理。
- 本变更更新 `merge-tasks-and-timer-into-execution-list` 中“执行弹框展示全部进行中事项”和“不新增按天执行清单”的既有边界；其他计时转换、父事项不可执行和完整待办管理职责保持不变。

## Capabilities

### New Capabilities

- `today-task-planning`: 定义今日计划的成员资格、待办页今日标签、加入与移出操作、重复事项和完成事项行为，以及执行事项弹框只消费今日计划的规则。

### Modified Capabilities

无。当前项目尚未归档形成主规格；与在途 `timer-task-dialog` 变更的差异在本变更设计中明确，并由新能力规格覆盖。

## Impact

- 前端状态与界面：`src-ui/src/store.ts`、`MainWorkbench.vue`、`PlanListEditor.vue`、`TimerTaskDialog.vue` 及其派生逻辑和样式。
- 本地后端：事项列表与日计划命令、执行快照、今日概览，以及 `task_daily_estimates` 相关 SQLite 迁移。
- 云端与同步：`supabase/schema.sql`、云同步实体序列化/合并、快照备份恢复、冲突展示及双设备测试。
- 兼容性：现有非空按日预计记录继续表示“属于该日计划并有预计时间”；新增独立成员记录表达“属于今日但尚未估时”，每日预计仍只保存正数分钟。
- 不新增第三方依赖，不改变唯一活动计时、停止确认、未归属时间或报告时间口径。
