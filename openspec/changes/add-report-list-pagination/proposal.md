# Proposal

## Why

报告页面当前一次性从本地数据库加载全部报告，再由前端筛选并完整渲染。随着日报、周报和月报长期积累，首次进入报告页、同步后刷新以及列表渲染都会持续变慢，因此需要把报告列表改为有界加载。

## What Changes

- 报告列表查询增加后端分页能力，默认每批返回 20 条，并返回符合条件的总数量和是否还有下一批。
- 主体、报告类型和搜索关键词由后端参与筛选，排序继续以最近更新时间倒序为准。
- 报告页左侧列表首次只加载第一批，滚动到底时自动加载下一批，不新增占用窄侧栏空间的页码栏。
- 切换主体、报告类型或搜索关键词时取消或忽略旧请求，清空旧结果并从第一批重新加载。
- 新建、删除、同步刷新或报告内容变化后，重新校准当前筛选范围，避免重复、遗漏和选择态指向不可见报告。
- 优化报告摘要加载，分页查询直接返回列表所需的关联事项数量等字段，避免对每条报告逐一执行完整详情查询。

## Capabilities

### New Capabilities

- `report-list-pagination`: 定义报告列表的后端筛选、分页结果、滚动续载、筛选重置和刷新一致性。

### Modified Capabilities

无。当前项目尚未归档形成报告列表主规格。

## Impact

- 后端报告查询：`src-tauri/src/reports.rs` 的列表请求、返回结构和 SQL 查询。
- 前端服务与状态：`src-ui/src/services/tauri.ts`、`src-ui/src/store.ts` 的分页参数、列表状态和刷新流程。
- 报告页面：`src-ui/src/components/ReportWorkspace.vue` 的筛选、滚动加载、加载态、空状态和选择态。
- 测试：Rust 报告查询测试、前端分页状态与滚动加载验证。
- 不改变报告正文、模板、生成、编辑、同步实体结构和现有报告数据。
