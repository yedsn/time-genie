# Proposal

## Why

当前日报模板中的 `{{工作时段}}` 只读取工作空间级的单段文本，无法体现不同主体在不同星期的实际工作安排，也无法表达一天内多个时段。需要为主体提供可视化的每周工作时段设置，让日报能按主体和日期自动取得合适的默认值，同时保留生成后手工编辑报告的能力。

## What Changes

- 在主体编辑入口增加“工作时段”设置，按周一至周日展示和编辑。
- 每天支持零个或多个工作时段；零个时段表示休息日。
- 提供周一至周五的默认时段 `10:00-12:00`、`13:30-17:30`，周六、周日默认休息。
- 支持添加、删除时段，将某天安排复制到其他星期，以及恢复默认安排。
- 校验时段起止顺序及同一天的时间重叠。
- 日报生成时按照报告主体、报告日期对应的星期解析 `{{工作时段}}`；生成后的 Markdown 仍可直接修改，重新生成时重新使用主体配置。
- 本地模式和云端模式使用一致的主体工作时段数据；UI-only 阶段仅实现界面与内存 mock 交互，持久化与同步留给完整实现阶段。

## Capabilities

### New Capabilities

- `subject-work-schedules`: 主体每周多时段配置、校验、默认安排和日报工作时段解析。

### Modified Capabilities

无。

## Impact

- 前端：主体编辑弹框、工作时段编辑控件、报告工作时段展示与预览。
- 后端：后续需要增加主体工作时段读取、保存和日报占位符解析命令。
- 本地数据：后续需要增加 SQLite 主体工作时段结构与迁移。
- 云端数据：后续需要在 Supabase 增加对应结构并纳入事件驱动同步。
- 兼容性：现有报告 Markdown 编辑能力保持不变；旧的工作空间级默认文本可作为迁移期兜底。
