# Design

## Context

当前主体只有名称和排序等基础字段；报告生成从工作空间设置 `default_work_period_text` 读取统一文本，并直接替换日报模板中的 `{{工作时段}}`。现有 `work_days` 是工作空间与日期维度的数据，不包含主体维度，无法表达多个主体在同一天的不同安排。参见 `proposal.md` 与 `specs/subject-work-schedules/spec.md`。

## Goals / Non-Goals

**Goals:**

- 用清晰、紧凑的主体设置界面维护每周七天及多段时间。
- 数据结构可以独立同步、进行版本控制，并避免时间流逝触发写入。
- 日报生成可以稳定地由主体与日期解析工作时段。
- UI-only 阶段使用与正式结构相近的内存数据，便于先确认交互。

**Non-Goals:**

- 不在本次变更中增加按具体日期的临时工作时段覆盖。
- 不改变周报、月报的工作时段语义。
- 不保证重新生成报告后保留对最终 Markdown 的手工修改。
- UI-only 阶段不写入 SQLite、Supabase，也不增加真实命令。

## Decisions

### 使用主体星期规则与时段子记录

正式实现使用主体、星期维度的规则记录，以及按顺序保存的时段记录，而不是把整周安排作为 JSON 塞入 `subjects`。独立结构便于校验、软删除、版本同步及局部冲突处理。备选方案是 `subjects.schedule_json`，代码较少但不利于查询、演进和多设备合并，因此不采用。

建议结构：

- `subject_work_schedules`: `id`、`workspace_id`、`subject_id`、`weekday`、`is_workday`、版本及软删除字段。
- `subject_work_schedule_segments`: `id`、`workspace_id`、`schedule_id`、`sequence_no`、`start_minute`、`end_minute`、版本及软删除字段。

### 显式区分休息日与未配置

`is_workday = false` 表示用户确认该天休息；没有主体规则表示尚未配置，需要采用默认安排或迁移兜底。这样不会把“休息”误判为缺失数据。

### 新主体复制默认安排

创建主体时复制周一至周五两段、周末休息的默认规则，已有主体在首次保存前显示同一默认草稿。备选方案是动态继承工作空间默认，但后续修改默认会静默改变历史主体行为，因此不采用。

### 报告生成时即时解析

日报生成根据工作空间时区解释 `reference_date`，优先读取主体对应星期规则，排序并格式化时段后替换占位符。当规则缺失或明确为休息日时，查询当天已结束、未删除、`kind = 'work'` 且通过正分钟 `time_allocations` 分配到该主体事项的时间记录，以记录级去重后取最早 `started_at` 和最晚 `ended_at`，格式化为一个连续加班时段。未归属、休息、无效、其他主体和运行中的记录不参与计算。报告仍保存最终 Markdown，不增加报告级覆盖字段。

### UI-only 使用模块级内存 mock

界面阶段用模块级响应式 Map 保存每个主体的草稿结果，使主体设置和报告创建界面能共享预览；刷新或退出应用后数据消失，并明确提示尚未连接持久化。完整实现阶段用后端结果替换该 mock，保持界面数据形状不变。

## Risks / Trade-offs

- [已有主体没有规则] -> 读取时使用默认安排，首次保存后建立正式规则。
- [跨设备同时编辑同一主体的星期规则] -> 以星期规则为最小版本冲突单元，沿用现有同步冲突处理。
- [时段跨越午夜] -> 当前明确要求开始时间早于结束时间；跨夜班次后续作为独立能力处理。
- [旧工作空间默认文本与新规则不一致] -> 迁移时仅把旧文本作为无法解析或尚未配置时的兼容兜底，不反向覆盖已保存主体规则。
- [一条时间记录分配给多个事项] -> 查询以时间记录为单位去重，避免同一记录重复影响边界；只要有正分钟分配到目标主体事项，该记录即可参与边界计算。
- [加班记录中间存在空档] -> 按产品要求只输出最早开始到最晚结束的一段范围，不尝试推断或拆分休息间隔，生成后由用户手工调整。
- [UI mock 被误认为已保存] -> UI-only 保存后显示“仅本次运行有效”的提示，完整实现时移除。

## Migration Plan

1. 先评审 UI-only 界面与交互，不修改数据结构。
2. 增加 SQLite 迁移和 Supabase 同构表、约束、索引与 RLS。
3. 增加主体工作时段命令及事件驱动同步实体。
4. 将前端内存 mock 替换为真实读取和保存命令。
5. 更新日报占位符解析，并为旧主体保留默认兜底。
6. 验证本地模式、云端模式和双设备同步后发布。

回滚时保留新增表但停止读取，报告恢复使用 `default_work_period_text`；新增数据不影响旧版主体和报告结构。
