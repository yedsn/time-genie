# Spec Delta

## Purpose

日报以同一主体的待办列表为可核对的数据来源：今日事项反映报告日期的今日实例，明日计划反映生成时的进行中来源事项，并在预览、保存和主动重新生成时保持相同口径。

## ADDED Requirements

### Requirement: 今日事项对应今日列表
系统 SHALL 纳入报告日期和主体下的全部今日成员及其父级上下文，保留实例标题、层级、顺序和状态，MUST NOT 因没有用时或尚未完成而排除成员，也不得额外纳入仅有执行记录但不在今日列表的事项。

#### Scenario: 未执行的今日成员
- **WHEN** 今日列表包含未计时未完成成员及已完成成员
- **THEN** 今日事项包含这些成员，按实例完成状态展示，父项仅作上下文

#### Scenario: 今日实例独立编辑
- **WHEN** 今日实例改名、移动或新增子项，与来源事项不同
- **THEN** 今日事项使用实例的标题、层级和顺序，不重复输出来源事项

### Requirement: 明日计划对应进行中列表
系统 SHALL 将同一主体生成时的全部进行中来源事项按待办树输出至明日计划，MUST NOT 根据次日重复规则或计划日期删减，也不输出今日实例。两个区块独立取数。

#### Scenario: 重复事项次日不执行
- **WHEN** 进行中存在次日不匹配重复规则的事项
- **THEN** 明日计划仍包含该事项，已完成来源事项不进入计划

### Requirement: 工时补充与生成一致性
系统 SHALL 合并同一展示事项的时间分配和调整，工时不得改变列表成员范围。预览、创建和主动重新生成 MUST 使用同一规则；重新生成日报刷新今日成员范围，周月报保持已保存日报合集规则。已保存内容不得被后台自动覆盖。

#### Scenario: 创建和刷新范围
- **WHEN** 相同输入且数据不变时预览并创建，之后加入新的今日事项并主动重新生成
- **THEN** 预览与创建 Markdown 相等，重新生成包含新成员并更新保存的关联范围

#### Scenario: 本地和云端
- **WHEN** 本地和云端基于等价今日实例、进行中事项和工时生成日报
- **THEN** 两者事项范围、层级、状态和用时符合相同规则
