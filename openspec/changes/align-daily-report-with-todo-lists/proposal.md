# Proposal

## Why

日报当前按执行记录选择事项，遗漏今日列表中未执行的事项，并使用来源事项而非今日实例的内容。用户已确认改为两个待办列表直接映射报告区块，替代此前未归档变更中的执行记录筛选要求。

## What Changes

- 日报今日事项取对应日期和主体的今日实例列表，包含未执行和已完成成员，保留父级上下文、标题、层级和顺序。
- 明日计划取对应主体的进行中来源事项树，不按次日重复规则过滤。
- 工时仅作为补充信息，不作为纳入条件；今日实例与来源事项不重复输出。
- 预览、创建和重新生成使用一致规则；重新生成日报刷新范围，不自动改写已保存报告。
- 同步本地与云端实现及专项回归测试。

## Capabilities

### New Capabilities

- `report-generation`: 以待办今日和进行中列表作为日报两个区块的数据来源，保留工时汇总和预览一致性。项目尚无持久化主规格，本次替代旧变更中的冲突规则。

### Modified Capabilities

无。

## Impact

- Rust 报告取数、渲染、范围和重新生成。
- Supabase 报告函数、新增增量 SQL、schema 入口和集成测试。
- 必要的报告界面提示与测试；不改变待办编辑交互，不新增业务表，不部署线上数据库。
