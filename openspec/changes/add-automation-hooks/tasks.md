## 2. 事件协议、模板与动作执行器

- [x] 2.1 定义版本化 `HookEvent` 信封和事项、主体、计时快照结构，提供 `timer.started`、`timer.stopped`、`task.completed` 构造器；通过序列化测试覆盖有效事项、已删除事项、待归属计时和重复事项轮次日期。
- [x] 2.2 实现固定白名单模板解析和变量预览，未知变量拒绝保存、缺失变量渲染为空并提示；通过测试覆盖中文、空格、保留字符、缺失字段和未知变量。
- [x] 2.3 实现 URI 动作执行器，验证 scheme、拒绝 `file`/`javascript`/控制字符，编码动态值并调用操作系统协议处理器；通过单元测试覆盖最终 URI，手工验证已注册测试协议可打开且未注册 `raycast://confetti` 返回明确错误。
- [x] 2.4 实现结构化本地程序执行器，按程序与参数边界启动、写入 UTF-8 JSON stdin、捕获并截断 stdout/stderr、处理非零退出码和 1 至 60 秒超时；通过辅助测试程序验证含空格参数、标准输入、输出截断和超时终止。

## 3. 持久化调度与幂等

- [x] 3.1 实现提交后 Hook 调度服务：按事件和排序匹配启用规则、幂等写入 `queued` 记录并在 Tauri 异步运行时执行，业务调用无需等待动作结束；通过测试验证无规则快速返回、同事件多规则按序调度和单条失败不阻止后续规则。
- [x] 3.2 使用稳定 `event_id + hook_id` 唯一约束防止重复执行，测试运行使用独立随机事件 ID且不占用实际事件唯一键；通过重复发布同一事件测试验证每条规则只启动一次。
- [x] 3.3 实现 `queued -> running -> succeeded/failed/timed_out` 状态更新、耗时和退出信息记录，应用启动时将遗留 queued/running 标记为中断且不自动重放；通过模拟重启测试验证外部动作不会重复。
- [x] 3.4 新增“测试 Hook 草稿”命令，使用 `test=true` 的固定示例事件复用真实执行器但不保存规则或修改业务数据；通过 URI 与本地程序测试验证返回状态、耗时、退出码和输出。

## 4. 计时事件接入

- [x] 4.1 在本地计时成功开始和结束的命令边界发布 `timer.started` 与 `timer.stopped`，结束事件包含时长、已分配/待归属分钟和名称快照；通过测试覆盖有关联事项、无关联事项、原事项已删除和结束失败不触发。
- [x] 4.2 将系统托盘与原生托盘的开始/结束操作接入同一事件发布出口，暂停和继续不触发第一版 Hook；通过托盘生命周期测试验证主窗口和托盘产生一致事件且不重复。
- [x] 4.3 在 Supabase 云端计时开始/结束成功后使用 operation ID 发布本机事件，RPC 重试和后续快照拉取不得重复或补执行；通过云端适配测试模拟同操作重试和其他设备历史快照。
